# 2024年11月

## 推理、代码与 Agent 接口同时向前：R1-Lite、Qwen2.5-Coder 与 MCP

> 2024 年 11 月表面上仍然是模型月：DeepSeek 展示 R1-Lite，Qwen 推进代码模型与百万上下文。但在 **11 月 25 日**，Anthropic 发布 Model Context Protocol（MCP）。当时它远没有“推理模型”那么吸睛，后来却成为 Agent 史上的基础设施节点：**模型拥有工具以后，行业开始认真解决工具怎样被发现、连接、描述和授权。**

### DeepSeek-R1-Lite：R1 的先遣队

**2024-11-20** — DeepSeek 上线 **DeepSeek-R1-Lite-Preview**，公开展示面向数学、代码和逻辑问题的长推理行为。[^1]

它的历史位置应当谨慎描述：R1-Lite 不是 2025 年正式 R1 的同一个发布物，也不能简单把后来 R1 的全部训练路线倒推到预览版上。但它确认了一件事：OpenAI o1 在 9 月公开“推理时计算”路线后，中国模型团队已经迅速进入同一赛道。

两个月后，DeepSeek-R1 正式发布，推理模型从闭源前沿产品变成开放权重生态中的核心品类。

### Qwen2.5-Coder：代码模型继续专业化

**2024-11-12** — Qwen 团队发布 **Qwen2.5-Coder** 系列更新，继续强化代码生成、理解、修复和代码推理。[^2]

代码模型的意义正在变化。2021 年 Codex 的典型任务是“根据注释生成一个函数”；到 2024 年，行业真正需要的是能理解更大代码上下文、配合工具、最终进入 repository-level Agent 的模型。

Qwen2.5-Coder 因而不仅属于“代码生成模型”史，也属于第二年 coding agent 爆发的模型基础设施前史。

### Qwen2.5-Turbo：百万上下文成为云模型规格

**2024-11-25** — Qwen 宣布 **Qwen2.5-Turbo** 上下文扩展到 1M token。[^3]

百万上下文不是 Agent 的充分条件，但长程任务会持续消耗上下文：系统指令、工具目录、对话历史、文档、代码、tool result、执行日志都争夺同一个窗口。

后来 Agent 工程会用 retrieval、compaction、external memory 和 checkpoint 避免“把全部历史永远塞进 context”，但 1M context 的普及仍显著扩大了单次工作流可直接携带的信息量。

### Model Context Protocol：Agent 工具连接开始协议化

同样在 **2024-11-25**，Anthropic 发布并开放 **Model Context Protocol（MCP）**。[^4]

MCP 的目标不是让 Claude 多会一种推理，而是提供一种开放标准，把 AI application 与：

- 数据源；
- 文件系统；
- 开发工具；
- 企业系统；
- 可调用工具

连接起来。

在 MCP 之前，工具生态大多是“一家应用写一套 integration”。即使 Function Calling 已经让模型能结构化表达函数调用，**工具怎样被发现、怎样描述能力、怎样建立连接、怎样授权**仍高度私有。

MCP 开始把这些问题从应用私有逻辑抽成协议层。

从后来 2026 年回看，它与 Function Calling 的关系可以概括为：

| 层 | 问题 |
|---|---|
| Function / Tool Calling | 模型怎样结构化表达“我要调用这个工具”？ |
| MCP | 工具与资源怎样被发现、连接、描述和授权？ |

二者不是替代关系。

### MCP 为什么在 2024 年看起来不惊艳

一个协议发布时通常没有 benchmark 可以展示。

它不会让 MMLU 多 5 分，也不会让模型突然能写更漂亮的代码。它的价值只有在生态规模扩大后才显现：当几十、几百、几千种工具都希望被多个 Agent 客户端调用时，共同协议可以减少重复适配。

这与互联网历史中的许多基础设施类似：**协议真正重要的时候，往往已经没人把它当成新闻。**

到 2025—2026 年，MCP 被多个模型、IDE、Agent 产品与开发平台采用，并进入 Linux Foundation 下的 Agentic AI Foundation；其规范开始讨论 stateless core、routing、Tasks、extensions 和 authorization。[^5]

### 同月其他模型与产品

**2024-11-04 前后** — Claude 3.5 Haiku 开始进入实际可用阶段。Anthropic 的 Computer Use 则是在 **10 月 22 日**随新 Claude 3.5 Sonnet / Haiku 一起宣布的 public beta；此前旧稿把 Computer Use 写成 11 月事件，现按正式公告日期校正。[^6]

**2024-11-05** — 腾讯发布 Hunyuan-Large 开放权重模型。[^7]

**2024-11-18 前后** — Mistral 更新其旗舰模型与 le Chat 能力，继续增强函数调用、多语言和长上下文路线。[^8]

### 月度数据小结

| 日期 | 事件 | 主要历史线 |
|---|---|---|
| 11-05 | Hunyuan-Large | 开放权重 / MoE |
| 11-12 | Qwen2.5-Coder | 代码模型 → coding-agent 前史 |
| 11-20 | DeepSeek-R1-Lite-Preview | 推理模型扩散 |
| 11-25 | Qwen2.5-Turbo 1M | 长上下文基础设施 |

### 评曰

2024 年 11 月最容易被记住的是 R1-Lite，因为它预告了两个月后的 DeepSeek-R1。

但从 Agent 历史看，MCP 可能具有更长的制度寿命。

模型版本会迅速过时，而“怎样让不同 Agent 安全、稳定地接入不同工具”是长期系统问题。Function Calling 让行动请求有了结构；Computer Use 让模型获得通用 GUI 手段；MCP 则开始给整个外部工具世界建立共同插座。

因此这个月同时出现了两条后来会在 2025—2026 年汇合的线：

> **模型更会想；系统更会让模型做。**
