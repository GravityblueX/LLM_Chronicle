# 2026年1月

## Agent 获得桌面、任务中心、集群与“自己的机器”：Cowork、MCP Apps、Kimi Swarm 与 OpenClaw

> 2026 年 1 月的 Agent 史出现了几条彼此咬合的路线：Anthropic 把 Claude Code 式执行能力带到知识工作桌面；MCP 工具开始返回交互式 UI；GitHub 把 Agent session 变成 repository 一等对象；Kimi 把多 Agent 编排变成 test-time scaling；月底，Clawd / Moltbot 正式定名 **OpenClaw**，把“自己的机器、自己的 workspace、自己的消息入口与长期 Agent runtime”推成极具传播力的个人产品范式。**Agent 不再只是一个会调用工具的模型，而开始变成有工作空间、生命周期、组织结构和所有权边界的软件执行者。**

### Cowork：从 Claude Code 到普通知识工作

**2026-01-12** — Anthropic 发布 **Cowork** research preview。Anthropic 在次日宣布 Labs 时明确写道：Cowork “launched as a research preview yesterday”，目标是把 Claude 的 agentic capabilities 带到 desktop。[^1]

Claude Code 面向程序员，天然拥有 terminal、repository、build / test、Git 与明确 artifact；Cowork 则试图把同一种“接受任务并执行”的结构带给研究综合、文档创建、数据抽取、文件整理和多步骤办公流程。

Anthropic 在 1 月 30 日 webinar 直接用 **Chat → Code → Cowork** 描述产品演进，并称 Cowork 的目标是让 Claude “actually does the work alongside you”。[^2]

这里只能确认产品定位与可用状态；它并不自动证明所有开放式知识工作都能长期无人值守完成。后续评估仍需看任务成功率、人工接管和重复可靠性。

### MCP Apps：工具不再只返回 JSON，也能返回界面

**2026-01-26** — MCP 发布 **MCP Apps**，成为第一个正式 extension：tool 可以向支持的客户端返回可交互 UI。[^3]

真实工作常需要人选择项目、填表、看图表、确认配置或中途调整参数。MCP Apps 让工具可以在任务过程中露出交互面，为 human-on-the-loop 提供一种比“每一步点确认”更自然的介入方式。

### GitHub Agents Tab：Agent session 成为项目管理对象

同日，**2026-01-26**，GitHub 发布 repository **Agents tab**。[^4]

它把 Copilot coding agent session 与代码、Issue、PR 放在同一项目界面中，可查看日志、切换任务、跳转关联 PR，并 resume session。

传统仓库对象：

> code / issue / branch / PR / action

开始增加：

> **agent session**

Agent 因而越来越像可以排队、观察、恢复和验收的工作单元，而不只是 IDE 功能。

### Kimi K2.5 Agent Swarm：Scaling Out, Not Just Up

**2026-01-27** — Moonshot AI 发布 **Kimi K2.5**，其中最具 Agent 史意义的是 **Agent Swarm** research preview。[^5]

Moonshot 官方称 K2.5 可 self-direct 最多约 **100 个 sub-agents**、执行最多约 **1,500 个 coordinated steps / tool calls**，并报告在适合并行的任务中相对 single-agent setup 最多约 **4.5× wall-clock reduction**。

这些数字必须按本书 v2.2 凡例理解：它们是**厂商在特定评测和任务设置下的结果**，不等于“100 个 Agent 在任意真实工作中都能带来 4.5 倍效率”。Multi-Agent 同时增加总 compute、协调、冲突与结果合并成本。

但它仍然标志着一条新的 scaling 轴：

> 参数更多 → reasoning 更多 → **并发工作更多**。

### 1 月 29 日：OpenClaw 定名——个人 Agent 开始强调“你的助手、你的机器、你的规则”

**2026-01-29** — Peter Steinberger 正式宣布 **OpenClaw** 名称。项目此前由 2025 年 11 月 25 日诞生的 Clawd 演变为 Moltbot，再最终定名 OpenClaw。官方公告称，这个最初的周末项目在两个月左右已超过 100,000 GitHub stars。[^6][^7]

OpenClaw 不是 Agent 技术史的起点。真正值得记录的是它把已有部件重新包装成一种非常容易传播的个人 Agent 所有权结构：

> **你的助手 + 你的机器 + 你的 workspace + 你的模型 / API Key + 你的消息渠道 + 你的 Skills。**

OpenClaw 官方 lore 的口号甚至直接写成：

> **Your assistant. Your machine. Your rules.**[^7]

这和 Cowork / Codex 的托管 Agent 有一处重要差别：OpenClaw 把“Agent 跑在哪里、数据放在哪里、从哪个消息入口下令”明确交还给用户自己配置。

这种自由同时意味着更高责任。shell、文件、credentials、消息渠道和长期 daemon 一旦组合在一起，prompt injection、恶意 Skill、错误权限和误操作都可能产生真实后果。

OpenClaw 在全球并不是第一款 Agent；但一个月后，它会在中国进入完全不同的传播环境，并最终引爆“养龙虾”大众热潮。

### 1 月的五块拼图

| 日期 | 事件 | Agent 系统层 |
|---|---|---|
| 01-12 | Claude Cowork | desktop / knowledge-work environment |
| 01-26 | MCP Apps | interactive tool UI |
| 01-26 | GitHub Agents Tab | session operations / mission control |
| 01-27 | Kimi K2.5 Agent Swarm | dynamic parallel orchestration |
| 01-29 | OpenClaw | local-first personal runtime / ownership |

它们分别回答：

> Agent 在哪里工作？  
> 人怎样在工具中介入？  
> 多个任务怎样被管理？  
> 一项工作怎样横向扩展？  
> **Agent 到底属于谁、跑在谁的机器上？**

### 评曰

2026 年 1 月以后，“Agent 产品”已经不能用一个聊天框概括。

Cowork 是托管工作空间；GitHub Agents Tab 是任务中心；Kimi Swarm 是并行组织；OpenClaw 则把个人机器和长期 runtime 本身变成产品想象的一部分。

这里也第一次非常鲜明地出现两种哲学：

> **把任务交给厂商云里的 Agent。**

以及：

> **把 Agent 装到自己的机器上，再从任何地方给它下令。**

后者会在中国 2026 年春天获得远超技术社区本身的社会传播力。
