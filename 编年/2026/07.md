# 2026年7月

## 前沿能力开始分层：GPT-5.6、Kimi K3、Gemini 3.6、Claude Opus 5 与 DeepSeek V4-Flash

> 2026 年 7 月没有出现一个可以单独概括全月的“唯一赢家”。相反，几条路线同时成熟：OpenAI 把旗舰模型与通用工作 Agent 绑在一起；Moonshot 用 Kimi K3 把 3T 级开放权重模型推入原生多模态与长程 Agent；Google 继续押注高吞吐 Flash；Anthropic 用 Opus 5 把接近受控前沿的能力下放到日常产品层；DeepSeek 再次把竞争拖回单位任务成本。与此同时，腾讯 ADP、x402 与 MCP 的新进展说明 Agent 已经不只是在“会不会调用工具”，而开始拥有**独立 runtime、支付层与可横向扩展的生产协议**。

### 7月1日：腾讯 ADP 工作台 / Claw 正式商用——Agent Runtime 开始按时长收费

**2026-07-01** — 腾讯云宣布 **智能体开发平台（ADP）智能工作台及 Claw 模式应用**结束免费公测，进入正式商业化，并按**任务运行时长**消耗 PU 余额 / 资源包。[^18]

这个节点在中国 Agent 商业史里比“又多一个 Agent Builder”更重要。

企业 Agent 早期的价格通常隐藏在模型 token 或 SaaS seat 里；ADP 的商用规则把另一项成本直接暴露出来：

> **Agent 占用执行环境多久，本身就是需要计量的资源。**

ADP 的整体定位也很典型：它不是一个明星 C 端 Agent App，而是围绕 **AgentOps** 提供 Agentic Loop、RAG、Workflow、Multi-Agent、API / SDK、企业安全、可观测性与生命周期管理，并允许客户通过云部署 License 在自有腾讯云资源中部署。

这说明中国企业 Agent 市场正在从“大模型应用开发平台”进入更像传统 IT 运维的一层：

- Agent 怎么发布；
- 谁能访问；
- 运行多久；
- 用了多少 PU / 模型资源；
- 日志怎么看；
- 故障怎么定位；
- 私有数据与网络边界在哪里。

到这一阶段，Agent 商业化的对象已经不是“一个提示词应用”，而是**一套持续运行的企业软件服务**。

### Fable 5 / Mythos 5 恢复：6 月治理危机的直接后续

同日 **2026-07-01**，Anthropic 恢复 **Claude Fable 5** 与 **Claude Mythos 5** 的访问。Fable 5 重新面向全球用户开放；Mythos 5 仍主要面向获批的美国组织。此前 6 月 12 日，美国政府的出口管制要求迫使 Anthropic 暂停两款模型；6 月 30 日限制被解除。Anthropic 公告与 AWS 更新均确认了恢复时间及范围。[^1][^2]

这使 6 月发生的“模型发布后三天即被迫撤回”没有停留在一次孤立事故上。治理开始直接进入模型产品生命周期：模型不再只是“训练—评测—发布”，还可能经历受控预览、政府审查、撤回、重新部署和分级访问。

### GPT-5.6：旗舰模型与通用工作 Agent 合流

**2026-07-09** — OpenAI 正式发布 **GPT-5.6** 系列：旗舰 **Sol**、均衡档 **Terra** 与低成本档 **Luna**。其中 Sol 面向编码、科研、网络安全、计算机操作和复杂知识工作；OpenAI 同时将更高计算预算的 `ultra` 模式描述为可协调多个 Agent 并行执行复杂任务的高能力设置。[^3][^4]

同日，OpenAI 推出 **ChatGPT Work**，把研究、文件与连接器操作、文档 / 表格 / 演示文稿等制品创建以及较长时间运行的任务放进同一个 Agent 工作空间。[^5]

GPT-5.6 也体现出模型产品线进一步分层。Sol、Terra、Luna 不再只是简单“大中小”，而是在能力、延迟、价格和可投入推理计算之间提供连续选择。

### x402 Foundation 正式运营：Agent 开始获得原生支付层

**2026-07-14** — Linux Foundation 宣布 **x402 Foundation** 正式进入 operational launch，并完成 Coinbase 对 x402 协议的贡献。基金会首批约 40 个成员来自支付、金融基础设施、云与技术公司，目标是维护开放、厂商中立的 **HTTP 原生支付标准**。[^16]

此前 Agent 可以调用工具、搜索网页、操作软件，却缺少一种像 HTTP request 一样自然的机器支付接口。x402 试图让 Agent、API 和应用在网络交互中直接发送和接收付款。

从 Agent 技术栈看，它补的是：

> **Agent ↔ Payment / Economic Resource**

Agent 如果要自主购买数据、调用收费 API、租用算力或完成商业交易，预算、身份、授权与支付协议最终必须进入 runtime。

### Kimi K3：3T 级开放权重模型进入原生多模态 Agent 阶段

**2026-07-16** — Moonshot AI（月之暗面）发布 **Kimi K3**。官方资料给出的规模为 **2.8T 总参数、104B 激活参数**，具有原生视觉能力和 **1M token** 上下文，并引入 KDA、Gated MLA 与 AttnRes 等结构。Moonshot 将其定位为面向长程编码、知识工作和推理的开放权重 Agent 模型。[^6][^7]

**2026-07-27** — Kimi K3 完整权重与技术报告公开。[^6][^8]

K3 的历史意义不只是“参数更多”。开放权重路线开始正面承接原生多模态、超长上下文、长时间工具调用、复杂代码库操作和 Agent 编排等工程目标。

### Gemini 3.6 Flash：Google 把“工作马”推到台前

**2026-07-21** — Google 发布 **Gemini 3.6 Flash**、**Gemini 3.5 Flash-Lite** 与 **Gemini 3.5 Flash Cyber**。Google 将这些模型明确定位于生产级 Agent 所需要的效率、延迟和可靠性。[^9]

Reuters 报道称，旗舰 Gemini 3.5 Pro 此时仍处于合作伙伴测试，而 Google 把更多生产负载押在更便宜、更快的 Flash 系列。[^10]

Agent 可能反复调用模型几十甚至上百次，因此每一次调用的价格、延迟和稳定性会在整项任务中被放大。

### Claude Opus 5：把接近 Fable 的能力下放到日常层

**2026-07-24** — Anthropic 发布 **Claude Opus 5**。API 基础价格保持与 Opus 4.8 相同，为每百万输入 token 5 美元、输出 token 25 美元，并继续强化长程 Agent、编码与知识工作。[^11][^12][^13]

Anthropic 至此形成 Sonnet / Opus / Fable / Mythos 的能力、价格与风险分层。

### MCP 2026-07-28：从“能连工具”到“能在普通 Web 基础设施上规模化”

**2026-07-28** — Model Context Protocol 发布 **2026-07-28 specification**。核心改为默认**无状态**，加入 Multi Round-Trip Requests、header-based routing、可缓存 list results、更严格授权机制与正式 extensions framework。[^17]

MCP 官方称，当时 Tier 1 SDK 月下载量已接近 5 亿次。这个数字不是 Agent 数量，但说明 MCP 已从单一厂商工具协议扩散为大规模开发基础设施。

“无状态”尤其重要：企业生产系统需要负载均衡、网关、缓存、水平扩容和容器随时重启。MCP 的演进记录了 Agent 工具连接从本地 demo 进入分布式系统的过程。

### DeepSeek-V4-Flash：价格战重新进入前沿模型比较

**2026-07-31** — DeepSeek 将 **DeepSeek-V4-Flash** API 推入公开测试，重点增强 Agent、代码与工具使用能力。[^14]

Reuters 随后报道其运行成本处于知名模型中的极低水平。[^15] DeepSeek 再次提醒行业：能力榜只回答“能不能做”，价格与 token 效率决定“能不能大规模一直做”。

### 评曰

2026 年 7 月最值得记住的，不是某个 benchmark 第一名，而是**前沿智能从单一商品变成了分层供给，Agent 也开始拥有完整的运行、经济与协议基础设施。**

同一个月里：

- 腾讯 ADP 把 Agent runtime duration 直接写进企业云账单；
- OpenAI / Anthropic / Google / DeepSeek 继续做能力与成本分层；
- Kimi 把开放权重推进长程 Agent；
- x402 给 Agent 补支付层；
- MCP 把工具层推进到可横向扩展的 Web 基础设施。

所以 Agent 商业化的成本单位已经不只是 token：

> **token + runtime + tools + payment + storage + human intervention。**

这也是中国云厂商和美国云厂商逐渐汇合的地方。各家产品名字不同，但最终都不得不回答同一组问题：一个 Agent 要运行多久、调用什么、花多少钱、谁有权限、失败后谁负责。
