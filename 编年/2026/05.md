# 2026年5月

## Claude Mythos：一个不能公开发布的模型，和它引发的全球恐慌

> 2026 年 5 月的前沿 AI 一边继续讨论高能力网络安全模型怎样被受控开放，另一边 Agent 产品也悄悄换了形态：月底字节发布扣子 3.0，把原来的 Bot / workflow builder 重新定义成“一人 + 多 Agent / 多人 + 多 Agent”的 AI 团队协作空间。能力治理和 Agent 组织化在同一个月并行推进。

## 5月29日：扣子 3.0——从搭 Bot 到“一人 + 多 Agent / 多人 + 多 Agent”

**2026-05-29** — 字节跳动旗下 **扣子（Coze）3.0** 发布。官方把新版本定位为面向 Agent 时代的 AI 团队协作平台，而不再只是早期“搭 Bot / 搭 Workflow”的低代码工具。[^7]

核心变化包括：

- **一人 + 多 Agent**：个人可以在一个项目空间内调用不同专长 Agent；
- **多人 + 多 Agent**：人类成员与 Agent 共同进入同一协作空间；
- 项目级文件、资产与上下文；
- 长期记忆；
- Skills；
- 云端 Agent；
- 本地 Agent 接入；
- 对 Claude Code、Codex CLI、OpenClaw 等第三方 Agent 的接入；
- 手机 / 电脑跨端继续任务。

这个版本的意义不是“扣子支持更多模型”，而是产品的基本对象变了。

早期低代码 AI 平台的对象是：

> Bot / workflow / plugin

扣子 3.0 开始把对象改成：

> **project / member / agent / skill / long-running task / cloud device**

这说明中国 Agent 产品也在从“构建一个应用”进入“组织一群执行主体”的阶段。

### 云设备成为执行资源

扣子同时推进云电脑、云手机和 OpenClaw 云电脑等执行环境。随后 6—7 月，这些云设备开始按规格和**在线时长**计费。

这非常值得记录，因为它与 Kimi Claw、阿里 Managed Agents、腾讯 ADP 的方向逐渐汇合：

> **Agent 真正商业化以后，成本不只是 token；保持一个随时能替你工作的机器环境，本身也要付钱。**

因此扣子的商业模式开始同时包含：

- 个人 / 团队 / 企业订阅；
- 积分；
- Agent 使用；
- 云设备 runtime；
- 企业按量资源。

这比传统“多少钱一个 AI 席位”更接近 Agent 时代的真实成本结构。

### 评曰

五月常被高风险模型新闻吸走注意力，但扣子 3.0 提供了另一条值得长期保存的线索：

> **Agent 产品的“界面”正在从聊天框变成团队空间。**

一个人和一个 AI 对话，只需要 conversation history；一个人指挥十个 Agent、多人共同与多个 Agent 工作，则需要完全不同的系统：

- project state；
- member identity；
- task ownership；
- memory；
- skill registry；
- permission；
- concurrent runtime；
- artifact management；
- cloud device。

所以 multi-agent 商业化并不是给聊天窗口增加几个头像。

它逼着产品重新发明项目管理、组织权限和计算资源管理。

中国互联网公司在这方面有一个天然入口：它们已经拥有协作软件、超级应用、云服务和移动终端。Agent 因而更容易直接嵌入现成工作入口，而不是完全从零建立新的 SaaS。
