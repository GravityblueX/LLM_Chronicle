# 2026年3月

## “养龙虾”：OpenClaw 引爆中国大众 Agent 产品潮

> 2026 年 3 月如果只写“318”“国产模型替代”，会错过这个月最直接影响普通用户的一件事：**OpenClaw 从开源技术项目变成了中国社会现象。** 学生、退休者、职场人开始“养龙虾”，地方政府办活动、发补贴，云厂商推出一键部署，大厂在几周内密集推出 QClaw、WorkBuddy、DuClaw、ArkClaw、悟空、百度“龙虾家族”、ClawBot 等产品。与此同时，真实用户也开始抱怨 token 成本、执行缓慢和收益不及预期，监管与金融机构则担心数据与权限风险。中国 Agent 的大众产品史由此真正进入爆发阶段——但它从第一天起就同时存在**宣传、可用性与可靠性之间的落差**。

### 先澄清：Agent 并不是从 OpenClaw 才开始

全球 LLM Agent 技术史至少可以追溯到 SayCan、MRKL、ReAct，再经过 AutoGPT、Devin、Computer Use、MCP 等节点。

OpenClaw 的不同之处，是把这些部件组合成了一种极容易被普通人理解的个人执行者：

> **一台自己的机器 + 一个长期运行的 Agent + 消息入口 + workspace + shell / browser + Skills + 模型 / API Key。**

因此，本书采用两个同时成立的判断：

> **全球 Agent 工程史不从 OpenClaw 开始；**  
> **中国 2026 年大众“会干活 Agent / 养龙虾”产品潮，可以把 OpenClaw 视为引爆点。**

OpenClaw 前身 Clawd 于 2025-11-25 出生，2026-01-29 正式定名；2 月已有安全个案与监管警告。详见《编年·2025年11月》《编年·2026年1月》《编年·2026年2月》。

## 3 月 9 日：地方推广与安全限制同时出现

**2026-03-09** — Reuters 报道深圳龙岗、无锡、合肥、苏州等中国科技 / 制造业城市正在推动 OpenClaw 应用，包括活动、算力、办公空间与最高可达千万人民币级的相关 AI 产业支持。[^9]

“养龙虾”因此不再只是开发者社区梗。它开始和：

- 一人公司；
- 副业自动化；
- 制造业流程；
- 政务试验；
- 个人办公；
- 云计算促销

绑在一起。

但两天后，同一条技术线又出现完全相反的制度反应。

**2026-03-11** — Reuters 报道部分政府机构、国企与金融相关单位开始限制或警告员工在办公设备上安装 OpenClaw，主要担忧包括敏感数据、深度系统权限、删除 / 修改文件以及未经授权的访问风险。[^10]

这不是政策自相矛盾，而是两个不同风险偏好的场景：

> **地方产业政策看见生产力和创业机会；敏感机构看见高权限常驻 Agent 的数据与控制风险。**

## 腾讯：QClaw、WorkBuddy 与微信 ClawBot 不是同一层产品

### WorkBuddy：不能简单写成“腾讯套壳 OpenClaw”

腾讯 WorkBuddy 的发布时间需要区分两个口径：

- **2026-03-04**：腾讯官方更新日志出现 WorkBuddy 4.5.0 首个公开版本记录；[^11]
- **2026-03-09**：腾讯云产品资料与当时报道把这一天作为对外正式 / 公测发布节点。[^12]

WorkBuddy 经常在媒体标题中被简称为“腾讯版 OpenClaw”，但从架构关系看并不准确。腾讯资料和开发者社区实测把 **QClaw** 与 WorkBuddy 区分：QClaw 更接近把 OpenClaw 原生体验产品化；WorkBuddy 则来自 CodeBuddy 系列自研 Agent 架构，同时兼容 OpenClaw Skills / MCP / Claw 使用习惯。[^13]

因此史书应写成：

> **WorkBuddy 属于 OpenClaw 浪潮中的自研办公 Agent，而不是简单 OpenClaw fork。**

官方列出的能力包括本地文件、Office、代码、terminal、Skills、自动任务、多模型 / 多专家、腾讯文档等。这些可以证明产品入口存在；**不能单凭产品页推出复杂任务已经稳定无人值守完成**。

### QClaw：把极客安装变成个人消费软件

3 月中旬，腾讯已经把 **QClaw** 放进个人 OpenClaw 产品线。其历史位置更接近：

> **简化 OpenClaw 安装、配置和消息入口，把“自己养一只龙虾”变成普通用户更容易完成的事。**

它和 WorkBuddy 的差异很重要：

- QClaw 更接近 OpenClaw / local-first 生态；
- WorkBuddy 更偏标准化桌面办公执行；
- 腾讯云 ADP 则属于企业 AgentOps。

同一家公司已经同时做**个人 runtime、办公产品和企业平台**。

### 3 月 22 日：ClawBot——微信本身变成 Agent 遥控器

**2026-03-22** — Reuters 报道腾讯把 OpenClaw 接入微信，推出 **ClawBot**。它可以像联系人一样出现在微信中，用户直接通过聊天远程下达任务。[^14]

OpenClaw 原本就是 messaging-first 设计；在中国，这个设计碰上十亿级超级应用后，意义被放大：

> 用户甚至不需要养成“打开 Agent App”的习惯，**微信一下就能让自己的 Agent 工作。**

## 百度：DuClaw 之后，一口气做出桌面、手机、云和硬件“龙虾家族”

### 3 月 11 日：DuClaw——租一只已经装好的 OpenClaw

**2026-03-11** — 百度智能云发布 **DuClaw**，官方称其为 zero-deployment OpenClaw 托管服务，预装百度搜索、百度百科、百度学术等 Skills，并支持多个主流基础模型。[^15]

这把商业模式从：

> 自己装 OpenClaw

变成：

> **向云厂商租一只已经装好、接好模型和工具的龙虾。**

### 3 月 17 日：DuMate / RedClaw / DuClaw / 小度设备

**2026-03-17** — Reuters 报道百度进一步推出基于 OpenClaw 的产品族：[^16]

- **DuMate（搭子）**：桌面；
- **RedClaw**：移动端；
- **DuClaw**：云端；
- **小度设备 Agent**：家庭硬件入口。

报道中，百度高管同时明确提醒：这些 Agent **仍处于发展中，并且容易犯错**。[^16]

这句限制必须和“能剪视频、做 PPT、研究、跨设备执行”等发布能力放在一起记录。

因为它提醒读者：

> **厂商自己也没有把“功能列表”理解成“稳定成功率”。**

---

## 3 月 16 日：ArkClaw——OpenClaw 变成云产品生命周期

**2026-03-16** — 火山引擎正式发布 **ArkClaw**。官方 release notes 显示，产品随后持续同步 OpenClaw 社区版本，并在月底上线 OpenClaw → ArkClaw 迁移，把原有记忆、Skills 和数据迁入托管服务。[^17][^18]

ArkClaw 后续逐渐加入：

- 云浏览器；
- 云电脑；
- 自动备份 / 恢复；
- 多任务 / 团队模式；
- OpenClaw 原生控制台；
- Agent Plan；
- 观测与日志。

它很像一次标准的开源基础设施云化：

> **开源 harness → managed runtime → cloud browser / computer → backup / observability → commercial plan。**

但官方文档也留下了一组比宣传页更有历史价值的限制：[^19]

- 部分轻量实例后来不再支持云电脑；
- 操作流畅度受实例资源规格影响；
- 多 Agent / 多会话同时触发同一云电脑任务可能产生资源竞争，因此建议同一实例同时只运行一个云电脑任务；
- 复杂验证码、扫码登录、高危权限确认可能需要用户手动接管。

这就是为什么本书 v2.2 凡例要求把**宣称能力与真实边界同时保存**。

## 智谱：AutoGLM 之外，再出现 OpenClaw 路线的 AutoClaw

智谱 2024 年已有 AutoGLM Phone Use，因此不能写成“智谱 Agent 从 OpenClaw 开始”。

但在 2026 年龙虾潮中，智谱又推出 **AutoClaw**，官方产品说明明确称其基于 OpenClaw 开源框架，强调本地安装、IM、文件 / 浏览器 / 代码、Skills、记忆与后续集群模式。[^20]

所以智谱实际上同时拥有两条不同脉络：

> **AutoGLM：视觉 / Phone Use；**  
> **AutoClaw：OpenClaw 式长期个人 Agent runtime。**

这正是“中国 Agent 很多，不能只按公司列产品名”的原因。

## 阿里：OpenClaw 浪潮产生了两种答案

### 3 月 17 日：悟空——不是 fork，而是企业组织型答案

**2026-03-17** — 阿里巴巴发布 **悟空（Wukong）**。Reuters 与阿里官方都把它放在当时中国 agent craze 的背景中，但悟空并不是 OpenClaw gateway 的简单重包装。[^8][^21]

它选择利用钉钉已有的：

- 组织身份；
- 通讯录；
- 日程；
- 文档；
- 审批；
- 企业应用；
- 权限体系

来承载多 Agent 工作。

可以把它理解为：

> **OpenClaw 证明市场想要“会干活的 Agent”；悟空回答企业内部怎样组织、授权和审计这些 Agent。**

### 月底：CoPaw / QwenPaw 与 HiClaw——独立重实现而不是照抄 OpenClaw

阿里 AgentScope 团队同期推进 **CoPaw（后更名 QwenPaw）**，它基于 AgentScope / AgentScope Runtime / ReMe，面向自托管、多渠道、长期记忆和主动任务，并提供阿里云预装镜像。[^22]

**HiClaw** 则进一步尝试 Manager + Worker 的轻量多 Agent 结构，重点之一是降低 worker 容器资源开销。[^23]

它们与 OpenClaw 属于同一产品问题空间，却不是简单 fork。

因此“阿里版 OpenClaw”这种说法在新闻标题里方便，在史书里必须拆开：

> **兼容 / 重实现 / 同类竞争 ≠ fork。**

## 3 月 19 日：真实用户开始问——“养这只龙虾到底值不值？”

**2026-03-19** — Reuters 采访中国 OpenClaw 用户，记录了从学生到退休者的“养龙虾”热潮，也同时记录另一面：部分用户抱怨**token 消耗高、执行结果不理想、投入与收益不成比例**。[^24]

这条资料特别重要，因为它让商业史第一次不只剩发布会上的成功路径。

Agent 的真实成本不是一个 token 单价，而更像：

> **模型 token + runtime + 工具 + retry + 等待时间 + 人工接管 + 做错后的返工。**

一个任务最终“做出来了”，也不代表它比人类操作更便宜、更快。

### “一次成功”也不能证明可靠

2026 年 Computer-Use Agent 可靠性研究进一步说明：即使任务和模型完全不变，一个 Agent 成功一次后，重复执行仍可能失败；随机性、任务歧义和行为变化都会影响结果。[^25]

所以真实成熟度应该问：

- 同一任务重复做十次怎样？
- 失败是否集中在同一步？
- 是否允许 retry？
- 需要人救几次？
- 最终环境状态真的正确吗？

而不是只看一条漂亮轨迹。

## Benchmark 自己也不是绝对真相

后续对 Computer-Use Agent benchmark 的审计发现，公开判定为 FAIL 的部分轨迹实际上属于 evaluator false negative 或 broken task。[^26]

因此本书既不能把厂商 demo 当生产能力，也不能把某一个 leaderboard 当绝对现实。

Agent 评价至少要同时说明：

> **model / harness / environment / permissions / retry / evaluator / cost。**

## 同月背景：访问制度与模型供应链争议仍在继续

2 月 Anthropic 公开蒸馏攻击指控后，3 月中文开发者社区又集中报告 Claude、OpenAI、Google 等海外服务的访问、代理与中转可用性变化，并出现“316/317/318”社区称呼。[^1][^2]

其中各厂商具体政策范围、是否属于同步行动、正常用户受影响比例缺乏同口径官方材料，所以本书只记录：

> **中文社区在同一时期明显感知到海外模型访问 / 风控环境收紧。**

不再把“御三家统一封禁中国”写成官方共同事件。

这类供应链不确定性与 OpenClaw 热潮实际上互相强化：一个能接 DeepSeek、Qwen、Kimi、GLM、MiniMax 等本地低价模型，并能自托管 / 国内云托管的 Agent，天然更有吸引力。

## GPT-5.4 与 LeWorldModel

**2026-03-05** — OpenAI 发布 **GPT-5.4**，继续 GPT-5.x 的密集迭代。[^7]

**2026-03** — Yann LeCun 团队发布 **LeWorldModel（LeWM）**，其中 SIGReg 为 joint-embedding prediction 提供新的正则化思路。[^6]

二者分别代表同月另一侧仍在推进的模型与 world-model 研究主线；本篇不因 Agent 热潮而把模型史完全抹掉。

### 评曰

2026 年 3 月最值得记的，不是“所有人突然拥有了可靠的 AI 员工”。恰恰相反。

真正发生的是：

> **普通人第一次大规模相信自己应该拥有一个一直在线、能真正动手的 Agent。**

OpenClaw 给了这种想象一个极具体的形状；中国的低价模型、超级应用、云厂商和激烈产品竞争又把它迅速放大。

但同一个月已经能看见热潮之后所有长期问题的雏形：

- token 成本；
- 任务慢；
- 结果不稳定；
- 多 Agent 资源冲突；
- 验证码与人工接管；
- 权限过宽；
- prompt injection；
- 敏感机构限制安装；
- “厂商说能做”与“普通人重复使用时真的省时间”之间的距离。

所以“养龙虾”真正改变的大模型史问题不是：

> “AI 能不能做事？”

而是：

> **“它到底替我稳定做完了什么，花了多少资源，失败以后谁来收拾？”**

这才是 Agent 从发布会进入真实世界以后必须面对的问题。
