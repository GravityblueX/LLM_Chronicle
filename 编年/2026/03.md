# 2026年3月

## 蒸馏攻击、「318 事变」与国模崛起

> 御三家关上一扇门，国产模型打开一扇窗。这一次，中国用户不是被技术征服，而是被地缘政治的推力推到了国产模型面前——然后发现，它们已经不需要怜悯。

### 前奏：蒸馏攻击（2026 年 2 月）

**2025-09** — Anthropic 更新使用条款，明确将中国列为受限地区，中国控股超 50% 的企业不得使用 Claude。理由是“美国国家安全政策——防止先进 AI 能力被用于军事和情报”。AtomGit, 2026-03-29[^1]（Anthropic 官方博文未提及条款更新具体时间，2025-09 来自 AtomGit 引述。）

**2026-02-23** — Anthropic 在官方博客公开指控三家中国 AI 公司——**DeepSeek**、**月之暗面（Moonshot AI）**、**MiniMax**——通过约 2.4 万个虚假账号，与 Claude 进行了超过 1,600 万次对话交互，实施“工业级别的模型蒸馏攻击”。Anthropic 声称这些行为意在提取 Claude 的核心能力来训练对手模型，并将此事上升到“国家安全”高度。Anthropic Blog, 2026-02-23[^2]; DeepTech 深科技/知乎, 2026-02-25[^3]

此次指控引发大量争议。关于 Anthropic 训练数据、版权诉讼、各公司是否使用其他模型输出训练竞争模型等问题，公开讨论中混杂了已证实事实、诉讼主张与舆论推断；本书在《知识蒸馏与模型压缩》中对这些证据层级另行拆分，本月不把网络讽刺或动机推测当作已证实事实。

### 「318 事变」：中文用户访问与 API 风控争议（2026 年 3 月）

**2026-03-06** — 中文社区出现新一轮 Claude 账号封禁与访问不稳定报告。旧稿引用的 80aj snapshot 已发现错位，当前只能作为待重归档线索，不作关键事实唯一依据。[^4]

**2026-03-16—18** — 中文开发者社区集中报告 Anthropic、OpenAI、Google 等海外模型服务的访问、代理与中转可用性发生变化，社区将这一波事件称作“316/317/318 事变”。其中各厂商限制的具体政策范围、是否属于同步行动、正常用户受影响比例等缺乏同口径官方材料，因此本书把“社区集中感知到访问环境收紧”作为可记录事件，不把“御三家统一封禁中国”写成无争议事实。

**2026-03-29** — AtomGit（CSDN 旗下开源社区）发表长文，尝试把 Anthropic 2025 年地区限制、2026 年 2 月蒸馏攻击指控与 3 月中文用户封号 / 风控感知串成一条因果链。[^1] 这是一种中文开发者社区的解释框架，而不是所有节点均有官方确认的统一事件报告。

### 后续：国产模型与本地服务的迁移价值上升

无论对“318”具体因果怎样解释，2026 年春季中文开发者对**供应链连续性**的重视确实明显上升：模型选择不再只看 benchmark，还开始看 API 能否长期访问、是否可换供应商、是否能自托管、是否有国内云和本地硬件适配。

这一回应随后集中体现在 4 月的 DeepSeek V4、GLM 等模型 / 平台进展上。详见《编年·2026年4月》《志·地缘与封锁》。

### 评曰

3 月最值得记录的不是某个网络梗，而是**访问制度开始像价格、延迟一样进入模型选型**。

技术人员过去习惯问：

> 哪个模型能力最好？

企业后来必须同时问：

> 能不能长期调用？能不能迁移？能不能在自己的云和硬件上跑？数据、身份和权限掌握在谁手里？

这使“国产替代”从情绪词逐渐变成系统工程问题。模型能力只是其中一层；API 兼容、权重获得、Agent runtime、国内云、企业权限和本地硬件同样决定实际可替代性。

## 3月17日：阿里悟空——Agent 直接进入企业组织与钉钉

**2026-03-17** — 阿里巴巴正式发布企业级 AI 原生 Agent 平台 **悟空（Wukong）**。阿里官方将其定位为能够在单一工作空间中协调多个 Agent、处理研究、文档、表格、会议和企业任务的工作平台，并把它直接接入钉钉企业生态。[^8]

这件事在中国 Agent 商业史里很重要，因为它选择的不是“先做一个独立 AI 员工，再去找企业数据”，而是反过来：

> **从现成的组织身份、通讯录、日程、文档、审批、企业应用和权限体系里长出 Agent。**

钉钉随后推进 CLI / 结构化接口改造，让 Agent 能直接调用更多企业功能，而不是只能靠视觉模拟鼠标点击。

这和 AutoGLM / Computer Use 的 GUI 路线形成互补：

- GUI Agent 解决“旧软件没有 API 怎么办”；
- 悟空 / 钉钉路线解决“如果软件本身就是我们的，能不能直接给 Agent 一个结构化控制面”。

对企业来说，后一条路线通常更可靠，因为权限、身份、审计和资源边界更容易被系统化。

悟空后来公开 Free / Starter / Basic / Premium 等档位，并以“算粒”等额度承载模型 / Agent 使用，同时保留企业销售方案。这说明中国企业 Agent 也开始从传统 seat 定价向**订阅 + 智能额度 + 企业合同**混合模式迁移。

## GPT-5.4：OpenAI 推理梯度的第四次迭代

**2026-03-05** — OpenAI 发布 **GPT-5.4**，继续 GPT-5.x 系列的快速迭代。GPT-5.4 提供 Pro 和 Thinking 版本，距 GPT-5.3-Codex（2026-02-05）仅一个月。TechCrunch, 2026-03-05[^7]

GPT-5.4 的发布延续了 GPT-5 系列自 2025 年 8 月以来的密集迭代节奏：GPT-5（2025-08）→ GPT-5.1（2025-11）→ GPT-5.2（2025-12）→ GPT-5.3-Codex（2026-02）→ GPT-5.4（2026-03）。五代模型在七个月内完成，模型版本已经越来越像持续交付的软件。

## LeWorldModel：面向 Embedding 预测的通用正则化方法

> 几十个随机投影方向 + 一个正态性检验，就能替掉 EMA、stop-gradient、预训练编码器全部补丁。一个好用的正则化项，比一堆启发式技巧更值得被记住。

**2026-03** — Yann LeCun 团队（Mila、NYU、Samsung SAIL、Brown University）发布 **LeWorldModel（LeWM）**，一个从原始像素端到端训练的世界模型。其值得被提炼的贡献之一，是为面向 embedding 预测的 loss function 提供简洁的正则化方法 **SIGReg（Sketched Isotropic Gaussian Regularization）**。arXiv:2603.19312[^6]

SIGReg 基于 Cramér-Wold 思想，把高维嵌入沿随机方向投影到一维，再通过分布检验惩罚表示坍塌。相比依赖 EMA、stop-gradient、冻结编码器等工程补丁，它试图把“怎样避免 joint-embedding collapse”变成更统一的正则化问题。

LeWM 的具体架构未必会成为 Agent 主流，但 world model 与长期环境预测仍是 embodied / physical Agent 未来的重要研究支线，因此保留这一节点。
