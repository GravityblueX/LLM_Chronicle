# 2026年8月

## 开放之后是部署：Qwen3.8、Muse Glimmer、DeepSeek V4-Pro 与前沿智能的“最后一公里”

> 7 月的模型竞赛证明前沿智能已经开始分层；8 月则进一步暴露了一个更现实的问题：模型做出来以后，究竟怎样交到人手里。阿里把 Qwen-Max 级旗舰第一次真正开放权重，Meta 反过来把 Agent 压缩到单张消费级 GPU；Google 三周一更 Flash，并把价格砍到上一代的一半；OpenAI 把 Luna 下放给免费用户、再给 Sol 降价；DeepSeek 则从 V4-Flash 的极低价重新向高价旗舰与分时定价移动。与此同时，Shieldstral、Claude 文本水印和 K3 的云托管谈判提醒行业：开放、部署、安全、许可、云分发已经纠缠成同一件事。

### Qwen3.8-Max：Max 级模型第一次进入 Qwen 开放权重主线

**2026-08-03** — 阿里巴巴发布 **Qwen3.8-Max**，官方给出的规模为 **2.4T 总参数**，支持 **1M token** 上下文和原生视觉输入，并把编码、专业工作、研究与长程任务作为主要能力方向。阿里同时宣布，这一代将成为 Qwen 第一次开放 **Max 级旗舰模型**权重的版本。[^1][^2]

Qwen3.8-Max 的意义不只在于“又一个万亿参数模型”。此前 Qwen 的开放生态虽然规模完整，但最顶层 Max 长期仍主要通过云 API 交付。Qwen3.8 改变了这个边界：旗舰层第一次进入公开权重路线。

**2026-08-12** — **Qwen3.8-2.4T-A95B** 权重正式上线 Hugging Face 与 ModelScope。官方资料称其采用稀疏 MoE，2.4T 总参数、每步约 **95B 激活参数**，配合混合注意力与 1M token 上下文。[^3][^4]

这里出现了与 Kimi K3 类似的新矛盾：权重越开放，模型本身却越大。2.4T 或 2.8T 级模型不再是“下载下来就能自己跑”的传统开源体验。开放权重解决的是**可检查、可改造、可再部署**的问题，却没有自动解决**谁有机器把它跑起来**的问题。

因此 2026 年的“开放模型”至少已经分成两层：一层是 Qwen3.8-Max、Kimi K3 这种云集群级开放旗舰；另一层则开始追求真正落到个人设备上的 Agent。

### Muse Glimmer：把 Agent 从数据中心压回一张消费卡

**2026-08-10** — Meta 发布 **Muse Glimmer**，开放模型权重并采用 Apache 2.0 许可。模型规模 **30B**，目标不是与数万亿参数旗舰正面比榜，而是让“always-on local agent”在 Mac、PC 或单张消费级 GPU 上成立。Meta 将其使用场景定位为本地 Agent、函数调用、本地编码和 LLM-as-a-judge，并针对长程执行、工具调用、多模态理解和本地记忆进行训练与量化优化。[^5][^6]

这让 8 月的开放路线形成鲜明对照：

| 路线 | 代表模型 | “开放”解决什么问题 |
|------|----------|--------------------|
| 超大开放旗舰 | Qwen3.8 / Kimi K3 | 让前沿权重可获得、可托管、可二次开发 |
| 本地开放 Agent | Muse Glimmer | 让 Agent 真正离开云端，在个人设备持续运行 |

两者都叫 open-weight，却服务于完全不同的控制权。前者强调模型层的开放；后者强调**运行时控制权**——文件、个人上下文和工具可以留在自己的机器上，不必先送进云端。

到这里，“开放 vs 闭源”已经不是一条线。一个模型可以开放权重但几乎只能在大型云平台运行；另一个模型能力弱一些，却能在断网环境长期驻留。对很多真实场景来说，后者反而拥有更强的实际自主性。

### DeepSeek V4-Pro 正式版：低价路线第一次明显向“旗舰溢价”回摆

**2026-08-13** — DeepSeek 正式发布 **DeepSeek-V4-Pro-0813**。官方称其 Agent 能力显著增强，并加入 Responses API 与 Codex 接入，网页、App 与 API 同时上线。Reuters 报道称，正式版相较此前预览版本有明显能力提升，DeepSeek 同日还宣布调整 V4-Pro 与 V4-Flash 的 API 价格，并引入峰谷定价。[^7][^8]

这一动作值得与 7 月末的 V4-Flash 放在一起看。V4-Flash 刚刚依靠极低运行成本重新掀起价格比较，半个月后 DeepSeek 却又把 Pro 拉回高端价位。Reuters 援引 Artificial Analysis 的数据称，V4-Pro 当时的百万输入 / 输出 token 价格约为 1.32 / 3.96 美元，分别约为 V4-Flash 的 9 倍和 14 倍。[^8]

这不是简单的“涨价”。它说明 DeepSeek 也在形成分层供给：Flash 负责把单位智能价格压低，Pro 则尝试证明**更强的 Agent 完成率值得溢价**。甚至峰谷定价的出现，都说明推理服务越来越像真正的计算基础设施——需求高峰、并发和资源调度开始进入模型价格体系。

曾经最有辨识度的“DeepSeek 就是便宜”，正在变成更复杂的故事：低价仍是武器，但已经不是唯一产品逻辑。

### Gemini 3.7 Flash：旗舰迟到，“工作马”却三周一更

同样在 **2026-08-13**，Google 发布 **Gemini 3.7 Flash**，距离 3.6 Flash 仅三周。Google 直接称其为“most intelligent workhorse model yet”，重点提升软件工程、知识工作、网页开发和 Agent 工作流，并给出**仅为 3.6 Flash 原始价格一半**的首发价。[^9][^10]

真正有意思的是另一面：市场等待已久的 Gemini 3.5 Pro 此时仍没有正式发布日期。Reuters 在报道 3.7 Flash 时仍特别提到这一点。[^10]

于是 Gemini 的产品节奏出现了看似反常的结构：旗舰 Pro 迟迟不来，Flash 却像软件版本一样连续迭代。

这其实很符合 Agent 时代的经济学。一个持续调用搜索、代码执行、文件解析和其他工具的 Agent，可能在一项任务中消耗几十轮模型调用。此时“每次调用便宜一点、快一点、稳定一点”会被累计放大。最高 benchmark 分数属于旗舰，但**每天真正跑最多 token 的模型**可能是 Flash。

“工作马”从过去的次旗舰，开始变成模型厂商真正争夺生产负载的主战场。

### GPT-5.6：从卖更强模型，转向扩大可用智能总量

**2026-08-06** — OpenAI 更新 ChatGPT 中的 **GPT-5.6 Sol**，强调回答聚焦度和事实可靠性，并加入可调节思考投入的滑块；同时宣布 **GPT-5.6 Luna** 将成为 Free 与 Go 用户的默认模型，为日常文本聊天提供不限量访问，并用 Think 按钮提供更深推理。[^11]

**2026-08-21** — OpenAI 又将 GPT-5.6 Sol 的 API 与 credits 价格临时下调 **超过 20%**，持续三个月。此前 7 月 30 日，Luna 和 Terra 的价格已经分别下调约 80% 与 20%。[^12][^13]

这组动作和传统“发布新旗舰”不太一样。它没有创造一个新代际，而是在改变**同一代智能被分配给谁、以多少成本被调用**。

如果把 Luna 的免费下放、Terra/Luna 降价和 Sol 降价放在一起，GPT-5.6 的后续竞争重点显然已经从能力发布转到利用率：更低价、更大免费覆盖，以及让用户自己选择 reasoning effort。

模型厂商开始优化的不是“一个回答有多聪明”，而是整个社会能够消耗多少高质量推理 token。

### 安全与治理也开始被拆成独立基础设施

8 月另外两件较小但很值得留下的事，都说明安全不再只是旗舰模型内部一套不可见的 filter。

**2026-08-04** — Mistral 发布 **Shieldstral**，一个约 3B 级（文档列为 3.8B）的开放权重多模态安全分类模型，Apache 2.0 许可，可在单张 16GB GPU 上运行。它把审核规则写成自然语言 policy question，在推理时切换政策，而不必为每套规则重新训练分类器。[^14][^15]

这等于把 guardrail 从厂商 API 内部拆出来，变成开发者可以部署、查看和自定义的一层模型。

**2026-08-14** — Anthropic 宣布未来 Claude 模型输出将采用统计式**文本水印**，以满足欧盟 AI Act 等透明度要求。Anthropic 强调该方案不加入隐藏字符、不增加 token，也不携带可追踪到具体用户或对话的身份信息。[^16]

两件事一开一闭，却都指向同一趋势：治理要求开始下沉到推理栈本身。安全分类器、来源识别、水印、权限、沙箱和审计日志，正在像 tokenizer、KV cache 一样成为模型系统的常规组成部分。

### Kimi K3 云托管谈判：开放权重仍需要分发渠道

**2026-08-26** — Reuters 报道称，Moonshot AI 正与 Microsoft、Amazon、Google 就 Kimi K3 的云托管与收入分成进行早期谈判，讨论事项包括分成比例、数据访问和 token 使用审计；谈判当时尚未完成。[^17]

这个事件必须以“报道中的谈判”而不是既成协议记录，但它正好给 8 月的主题落下最后一块拼图。

K3 是开放权重模型。理论上，任何合规获得权重的人都可以部署；现实中，2.8T 参数使大规模企业推理高度依赖成熟云基础设施。于是一个开放模型最后仍可能通过 Azure、AWS、Google Cloud 之类的封闭商业渠道被绝大多数企业真正使用。

开放权重和商业云并不矛盾。相反，模型越大，二者可能越绑定：**开放决定谁有权运行，云决定谁实际上跑得起。**

### 评曰

2026 年 8 月把“开放”这个曾经很简单的词拆碎了。

以前讨论开放模型，最常问的是：**权重放不放？许可证是什么？** 到 Kimi K3 和 Qwen3.8 以后，这已经远远不够。2T、3T 级权重可以公开，但多数开发者仍然需要云；Muse Glimmer 只有 30B，却因为能在一张消费级 GPU 上持续运行而获得另一种更直接的控制权。开放开始分成“看得见”“改得了”“跑得起”“托管得出去”几个不同层次。

同样，闭源也不是单一形态。Google 用 Flash 把云模型做得越来越像廉价高吞吐基础设施；OpenAI 用 Luna 免费层和 Sol 降价扩大调用量；DeepSeek 从极低价 Flash 到高价 Pro 做能力分层。云模型虽然不给权重，却可能因为价格和接口而比某些巨大开放权重模型更容易真正被使用。

因此 8 月真正换掉的问题是：

> **不是“模型开放了吗”，而是“智能最终由谁控制、在哪里运行、通过什么价格和渠道被交付”。**

权重、GPU、API、云托管、Agent runtime、guardrail、许可证、价格和监管一起构成了模型的“最后一公里”。2023 年人们争论开源和闭源；2026 年开始不得不承认，真正的生态位存在于两者之间的一整条部署链上。
