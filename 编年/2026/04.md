# 2026年4月

## 从“模型替代”到“工作系统”：DeepSeek V4、Agent 协议栈、Claude Design 与 GPT-5.5

> 2026 年 4 月很容易被写成一场简单的模型对打：DeepSeek V4、GPT-5.5、Claude Opus 4.7 接连出现。但同月还有另一条更基础设施化的 Agent 主线：**x402 把支付纳入 Agent 网络，A2A 宣布 150+ 组织支持并进入生产，OpenAI Agents SDK 加入 native sandbox，Kimi K2.6 把 Agent Swarm 扩到最多约 300 个子 Agent。** 前沿竞争开始从“谁回答得最好”转向“谁能在完整执行系统里工作、协作、付费和恢复”。

### x402 Foundation：Agent 开始拥有支付层

**2026-04-02** — Linux Foundation 宣布成立 **x402 Foundation**，接收 Coinbase 贡献的 x402 protocol，并以中立治理推动 HTTP 原生支付标准。[^7]

x402 的目标很直接：让 AI agents、APIs 和 apps 在 Web 交互中能够像交换数据一样发起和接收支付。

这件事在 Agent 历史里非常重要，因为“能行动”迟早会碰到价值交换：

- 买 API 调用；
- 支付数据访问；
- 下单服务；
- 结算微任务；
- 在机器之间自动购买资源。

但支付也把风险显著放大。一个 Agent 幻觉一个搜索词只是浪费 token；一个 Agent 幻觉一笔付款会改变真实资产。

因此 Agent 支付天然要求：

- budget；
- spending limit；
- identity / authorization；
- confirmation boundary；
- audit trail；
- dispute / rollback 语义。

x402 并不解决所有这些问题，但它让“Agent 作为交易主体”第一次拥有较明确的开放协议层。

### A2A 一周年：Agent-to-Agent 从规范进入生产

**2026-04-09** — Linux Foundation 在 A2A 发布一周年时宣布：已有 **150+ 组织**支持该协议，并已进入 Google、Microsoft、AWS 等主要平台及多个企业生产环境。[^8]

这使 2025 年 4 月的 A2A 从“一个新协议提案”跨过了另一个门槛：**跨 Agent 协作开始被真实企业部署。**

从系统结构看，A2A 与 MCP 的层次越来越清晰：

| 协议层 | 主要对象 | 典型问题 |
|---|---|---|
| MCP | Agent ↔ tools/data | 我能调用什么？怎样连接与授权？ |
| A2A | Agent ↔ Agent | 我能把任务交给谁？怎样交换状态和产物？ |
| x402 | Agent ↔ value/payment | 我能否在预算内完成交易？ |

这已经开始形成类似网络协议分层的雏形。

### Agents SDK Native Sandbox：Harness 与 Compute 正式解耦

**2026-04-15** — OpenAI 更新 **Agents SDK**，加入 model-native harness 与 **native sandbox execution**。[^9]

Agent 可以在受控 workspace 中：

- inspect files；
- run commands；
- edit code；
- 使用 packages / artifacts；
- 执行 long-horizon task。

OpenAI 尤其强调：**harness 与 compute 可以分离。**

这是 Agent runtime 的关键成熟标志。

早期系统往往把：

> 模型调用 + 状态 + credentials + shell + 文件系统

全部塞在一个进程或容器里。

真正长期运行时，这种结构既不安全也不耐故障。更成熟的设计是：

- orchestration / state 在 sandbox 外；
- 不可信模型生成代码在隔离 compute 中运行；
- credential 尽量不直接暴露给 sandbox；
- sandbox 可销毁、重建、snapshot / rehydrate；
- 任务状态可以继续存在。

这已经非常像传统分布式任务系统。

### Kimi K2.6：Agent Swarm 扩到 300 个子 Agent

**2026-04-20** — Moonshot AI 发布并开放 **Kimi K2.6**，同步升级 Agent Swarm。[^10]

Kimi Help Center 记录的主要规模包括：

- 最多约 **300 个 Subagent instances**；
- 单任务 **4,000+ tool calls**；
- 官方报告在适合并行的场景中相对 single-agent sequential execution 最多约 **4.5× wall-clock speedup**。

从 K2.5 的 100-agent 到 K2.6 的 300-agent，最值得注意的不是数字本身，而是 multi-agent scaling 开始显式遇到**组织学问题**：

- 什么任务可以拆？
- 拆多细？
- 子任务是否独立？
- 怎样防止 serial collapse？
- 怎样防止无意义 spawn？
- 多个结果怎样 reconcile？
- 总 compute 上升是否值得 wall-clock 下降？

因此 Multi-Agent 的本质越来越明确：

> **不是多个模型聊天，而是动态任务图调度。**

### DeepSeek V4 Preview：百万上下文与新的双层模型族

**2026-04-24** — DeepSeek 发布 **DeepSeek-V4 Preview**，同步开放权重并更新 API。官方首次明确公布 V4 两个型号的规模：[^1]

| 型号 | 总参数 | 激活参数 | 上下文 | 定位 |
|------|--------|----------|--------|------|
| DeepSeek-V4-Pro | 1.6T | 49B | 1M | 高能力 Agent、推理、知识工作 |
| DeepSeek-V4-Flash | 284B | 13B | 1M | 高吞吐、低成本日常调用 |

这组数字说明 V4 不是“V3 加到 1M context”这么简单。DeepSeek 同时把**模型尺寸和产品档位**拆成 Pro / Flash：一个购买更高任务完成能力，一个购买更低单位调用成本。

官方将 V4-Pro 的重点放在 Agentic Coding、推理和世界知识，将 V4-Flash 定位成更快、更经济的工作马。API 同时兼容 OpenAI ChatCompletions 风格与 Anthropic 风格接口，旧的 `deepseek-chat` / `deepseek-reasoner` 名称随后逐步退出。[^1][^2]

### 关于“V4 比 GPT-5.5 便宜 370 倍”

4 月发布后，中文互联网广泛传播“V4 价格只有 GPT-5.5 的 1/370”。这个数字来自第三方在特定模型、输入输出比例和汇率条件下的换算，不是 DeepSeek 或 OpenAI 官方给出的直接同口径比较。

因此本书不再把 **1/370** 作为 V4 的核心事实，也不再用它反推 DeepSeek 的真实推理成本。

V4 的历史意义已经不需要这一数字支撑：**1.6T / 49B 的 Pro、284B / 13B 的 Flash、1M context 与 Agent 定位**本身就足以说明 DeepSeek 正从“单一低价 API”转向分层推理服务。[^1]

这个趋势后来在 8 月完全显现：正式版 V4-Pro 与 V4-Flash 价格差拉大，并引入峰谷价格。

### V4 与“国产替代”：应从迁移能力而不是民族叙事理解

2026 年初，多家海外模型服务的地区限制和政策风险使中国开发者更重视替代方案。V4 的发布提供了一个现实条件：

- OpenAI / Anthropic 风格接口兼容；
- 中文能力与代码能力足以承接大量应用；
- 权重可获得；
- 国内 API 与部署渠道存在；
- 后续还能适配本土硬件和推理框架。

因此 V4 的“替代”意义首先是**工程迁移能力**。

它不等于“所有海外模型都已经没有价值”，更不等于“某个 benchmark 上全面胜出”。真正发生的是供应链风险开始进入模型选型：企业会考虑模型强弱，也会考虑**能不能持续调用、能不能换供应商、能不能自己托管**。

### Claude Opus 4.7：Anthropic 继续强化 vision / agent / multi-step

**2026-04-16** — Anthropic 发布 **Claude Opus 4.7**，强化 coding、agents、vision 与 multi-step tasks。[^3]

一天后，这些视觉能力被迅速装进一个新的产品形态。

### Claude Design：模型能力进入视觉工作台

**2026-04-17** — Anthropic Labs 推出 **Claude Design** research preview，由 Claude Opus 4.7 驱动，用自然语言生成和迭代设计、原型、幻灯片、one-pager 与营销视觉。[^4]

Claude 在 2024 年通过 Artifacts 把文本输出变成工作区，2025 年通过 Claude Code 把代码输出变成可执行工程，2026 年 Claude Design 又把同样的逻辑扩展到视觉创作：

> **模型不再只产生答案，而是在专门工作空间里持续修改一个制品。**

### GPT-5.5：OpenAI 把“真实工作”写进旗舰定义

**2026-04-23** — OpenAI 发布 **GPT-5.5**，次日 GPT-5.5 与 GPT-5.5 Pro 进入 API。[^5]

官方没有把发布重点放在某一个传统知识 benchmark 上，而是直接把模型定位成面向复杂真实工作的系统，包括：

- 写代码与调试；
- 在线研究；
- 数据分析；
- 创建文档与电子表格；
- 操作软件；
- 跨工具推进任务直到完成。[^5]

### GPT-5.5 Pro：parallel test-time compute

GPT-5.5 Pro 与 GPT-5.5 使用相同底层模型，但 OpenAI 系统卡说明 Pro 设置使用更高的并行 test-time compute。[^6]

这使 2024 年由 o1 打开的“多想一会儿”进一步演化为：

> **不仅增加推理 token，还可以并行探索多个工作路径。**

因此“模型多强”已经不能只由一个 checkpoint 描述。相同底层模型在不同运行时预算下，可以变成不同产品档位。

### 安全能力也随工作能力一起升级

OpenAI 在 GPT-5.5 System Card 中把 advanced cybersecurity 与 biology 纳入专门的 predeployment evaluation，并针对高能力风险配置相应 safeguard。[^6]

这一点与同年 Anthropic 的 Fable / Mythos 分层遥相呼应：当模型能够真正操作软件、研究复杂主题和长期执行任务时，安全边界越来越需要与**运行时权限和访问等级**绑定，而不只是训练结束后加一个拒答 prompt。

### 4 月的真正共同主题：Agent 有了协议、沙箱、组织与经济层

如果把本月事件只按模型厂商排列，会看到 DeepSeek、Anthropic、OpenAI、Moonshot 各自竞争。

如果按 Agent 系统层排列，则是另一张图：

| 层 | 本月节点 |
|---|---|
| Payment | x402 Foundation |
| Agent interoperability | A2A 进入生产 |
| Runtime / sandbox | Agents SDK native sandbox |
| Multi-agent orchestration | K2.6 300-agent Swarm |
| Model / work capability | GPT-5.5、V4、Opus 4.7 |

这说明“Agent 平台”已经不再是一个 SDK 能概括的东西。

它正在长成完整计算栈。

### 评曰

2026 年 4 月真正的共同主题，是**智能进入工作系统，而工作系统开始反过来定义智能。**

一个模型可能 benchmark 很强，但如果没有安全 sandbox、不能连接其他 Agent、不能管理长期状态、不能在预算下调用付费资源，它仍然很难成为生产级执行者。

反过来，同一个模型放进更好的 harness、tool protocol 和 verifier，任务完成率可能大幅变化。

因此 Agent 时代的 scaling 已经至少有四个轴：

> **scale model → scale reasoning → scale runtime → scale organization。**

K2.6 把“组织”直接做成 300-agent test-time scaling；Agents SDK 把 runtime 与 compute 拆开；A2A 和 x402 则开始处理系统之间的协作与经济关系。

这比“谁便宜 370 倍”更能说明 4 月真正发生了什么。
