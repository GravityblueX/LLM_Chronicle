# 2022年3月

## Chinchilla：算力最优缩放律的修正

> 2022 年春，DeepMind 给大模型竞赛补上了一条硬规矩：在同样训练算力下，不是参数越多越好。模型和数据要一起长，少训数据的大模型，其实是在浪费算力。

### 发布

**2022-03-29** — DeepMind 团队在 arXiv 发布 **Chinchilla** 论文《Training Compute-Optimal Large Language Models》。论文提出：在固定计算预算下，模型参数量与训练 token 数应大致等比例增长；许多当时的大语言模型参数过大、训练数据不足。Chinchilla 采用 70B 参数、约 1.4T token 训练，在与 Gopher（280B 参数、300B token 训练）相同训练算力预算下，用约 4.7 倍数据在各下游任务上全面超过 Gopher，并在 MMLU 上达到 67.5% 平均准确率（5-shot）。arXiv, 2022-03-29[^1]; DeepMind Blog, 2022-04-12[^2]

### 意义

Chinchilla 的要点不是“做了一个更大的模型”，而是反过来说明：**更大不一定更优**。在 GPT-3 和 Gopher 之后，行业很容易把 scaling law 理解成“继续堆参数”。Chinchilla 把这条路上的裂隙指出来——如果训练 token 不够，参数规模会变成昂贵的空壳。

这条经验后来影响很深。Llama、Llama 2、Claude、Gemini 以及后来的开源模型，普遍更重视“参数—数据—算力”的配比，而不是只报一个参数数字。它也让推理成本重新进入模型设计的核心：70B 模型如果训练得更充分，可能比 280B 模型更有用、更便宜、更容易部署。

### 评曰

Chinchilla 是大模型史里少见的“降温”事件。它没有把竞赛推向更夸张的参数规模，而是告诉所有人：先把账算清楚。十年建城的人都懂这个道理——砖不是越多越好，地基、材料、工期要配平；有一处不配平，裂隙迟早会从墙根冒出来。
