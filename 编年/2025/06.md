# 2025年6月

## 「Linear Transformer 世子之争」：Peng Bo vs Songlin Yang

> 一场关于谁才是线性注意力正统的争论，最终以双方决裂、线性 Transformer 系列集体降温收场。

### 背景：百家争鸣的线性注意力

自 2017 年 Transformer 架构以 O(n²) 复杂度的 Softmax Attention 统治序列建模以来，「线性注意力」（Linear Attention）——以 O(n) 复杂度实现近似效果——始终是替代方案中最活跃的方向。2023 年前后，多种线性注意力架构并起：

- **RWKV**（Peng Bo / BlinkDL）：将 RNN 时序衰减与注意力机制融合；[^1]
- **Gated Linear Attention / DeltaNet**（Songlin Yang）：门控线性注意力，并维护 Flash Linear Attention（FLA）高效算子实现；[^2]
- **RetNet**：可并行训练、递归推理；
- **Mamba**：状态空间模型路线。

6 月初，围绕 Zoology benchmark、RWKV-7 的第三方 FLA 实现与公开沟通方式，Peng Bo 与 Songlin Yang 发生公开争论，最终 FLA 宣布停止维护 RWKV 相关代码。中文技术社区围绕“官方实现 vs 第三方复现”“开源维护者责任”“研究者公开沟通方式”展开大量讨论。[^3]

这场争议最值得保留的技术问题不是人物冲突，而是：**新架构 benchmark 对实现细节高度敏感。** 初始化、kernel、state size、短卷积等工程差异都可能改变结果；如果比较对象并非作者认可实现，所谓“架构优劣”可能其实是“实现差异”。

这也是为什么后来本书在 Agent benchmark 中同样强调：必须区分模型本身、harness、工具、环境版本和运行预算。

## A2A 进入 Linux Foundation：Agent-to-Agent 从 Google 规范变成中立项目

**2025-06-23** — Linux Foundation 宣布成立 **Agent2Agent Protocol Project**，接收 Google 发起的 A2A 协议，并在中立治理下继续发展。[^4]

这件事距离 A2A 在 4 月 9 日首次发布只有两个多月。

协议快速进入基金会治理，说明 Agent 生态已经意识到一个现实问题：

> **如果“Agent 怎样和 Agent 沟通”永远属于某一家模型或云厂商，其他企业很难放心把跨系统协作建立在它上面。**

A2A 的目标是让不同框架、不同厂商、不同组织中的 Agent 可以：

- 发现对方能力；
- 建立任务上下文；
- 委派长程工作；
- 交换状态；
- 返回 artifact / result。

这和 MCP 的发展路径逐渐形成呼应：

- MCP 解决 Agent ↔ tools/data；
- A2A 解决 Agent ↔ Agent；
- 二者都从厂商发起，随后追求更中立的生态治理。

### ACP 并入 A2A 路线

IBM Research 推动的 **Agent Communication Protocol（ACP）**后来也明确进入 A2A 路线。[^5]

这并不意味着 2025 年 Agent 协议已经“一统天下”，但它说明早期碎片化协议开始出现收敛压力：真正的互操作标准，价值来自**别人也愿意实现**，而不只是自己的 SDK 支持。

### 从开源代码到开源协议治理

开源模型时代最常讨论的是：

> 权重能不能下载？

Agent 时代又多了一层：

> **系统之间共同依赖的协议由谁控制？**

即使所有 Agent 都是闭源模型，只要 MCP/A2A 等协议开放并由中立机构治理，开发者仍可以降低工具和工作流被单一模型供应商锁死的程度。

因此 Agent 生态的“开放性”不能只看权重，也要看：

- protocol；
- SDK；
- runtime；
- identity / auth；
- artifact format；
- governance。

### 评曰

六月的一边，是几个线性架构研究者因为第三方实现和 benchmark 公平性吵翻；另一边，是 A2A 主动从单一公司走向 Linux Foundation。

两件事意外地共享一个主题：

> **技术一旦需要生态协作，谁有权定义“正确实现”就会变成制度问题。**

模型架构可以靠论文定义；大规模 Agent 网络却不能只靠一篇论文存在。它需要规范版本、兼容性、治理流程和跨厂商共同实现。

这也是 Agent 从研究原型走向基础设施的一个标志。
