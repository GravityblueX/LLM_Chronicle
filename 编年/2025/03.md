# 2025年3月

## Agent 从产品功能变成平台层：Bedrock Multi-Agent、Responses API / Agents SDK 与 Gemini 2.5 Pro

> 2025 年 3 月同时发生了两类变化。一类仍属于模型能力：Gemini 2.5 Pro 把长上下文、多模态和推理进一步合并。另一类更像软件基础设施：AWS 把 multi-agent collaboration 做成正式托管云能力，OpenAI 发布 Responses API 与 Agents SDK，把 tools、handoff、guardrails 和 tracing 做成 Agent 开发组件。**Agent 开始从“某个产品里有一个自主模式”变成可编程的平台层。**

### Amazon Bedrock Multi-Agent Collaboration GA：多 Agent 进入企业云资源

**2025-03-10** — AWS 宣布 **Amazon Bedrock Multi-Agent Collaboration** 正式 GA。[^1]

其基本架构是：

- 一个 supervisor agent 负责理解目标与拆分任务；
- 多个 collaborator / specialist agents 各自处理专业子任务；
- supervisor 汇总结果并返回最终输出。

这与 2023 年 CAMEL、AutoGen、MetaGPT 的多 Agent 实验相比，关键差异不在“多个模型终于会聊天”，而在**企业系统要求**开始进入设计：

- trace；
- monitoring；
- IAM 权限；
- 云资源管理；
- infrastructure-as-code；
- 生产 SLA 与治理。

Multi-Agent 从研究架构变成了云服务资源。

### Responses API 与 Agents SDK：Agent Harness 平台化

**2025-03-11** — OpenAI 发布一组新的 Agent 开发工具，包括 **Responses API、内置工具、Agents SDK 与 tracing**。[^2]

相比早期 Assistants API，这一代接口更明确地围绕“Agent loop”组织：模型可以调用 web search、file search、computer use 等工具，开发者可以定义多个 Agent 之间的 handoff、guardrail 与 trace。

历史意义可以分三层看。

#### 第一层：工具不再只是外部函数

平台开始直接提供内置 web / file / computer tools，Agent 可以在统一调用模式下获取信息、操作环境。

#### 第二层：编排成为第一等对象

Agents SDK 把：

- agent definition；
- handoff；
- tool invocation；
- guardrail；
- tracing

做成明确组件。

这说明行业承认：Agent 的产品层不是某个 prompt，而是一个 **harness**。

#### 第三层：可观测性进入核心

一个聊天回答错了，用户通常只看最终文本。

一个 Agent 做错了，开发者需要知道：

- 它在第几步决定调用什么；
- 工具返回什么；
- 是否发生 handoff；
- 成本花在哪里；
- 哪一步开始偏离目标。

因此 tracing 不是调试附属品，而是 Agent 进入生产系统的基本条件。

### Gemini 2.5 Pro：推理与百万上下文继续合流

**2025-03-25** — Google DeepMind 发布 **Gemini 2.5 Pro**，定位为 thinking model，并继续提供超长上下文与原生多模态能力。[^3]

这一节点在模型史中的意义已经有《Gemini 世家》详述。放到 Agent 史里，它最值得注意的是：

> **Agent 所需的不只是规划能力，还需要在一次任务中读取大量环境状态、代码、文档和工具返回。**

所以 long context 与 reasoning 并不是两条独立军备竞赛。随着任务变长，二者会共同进入 Agent runtime 的成本函数。

但 2026 年回看也必须补一句：大窗口并不能替代外部状态管理。真正的长程 Agent 后来大量依赖 retrieval、memory、compaction、checkpoint 与 durable state，而不是无限增长上下文。

### 从模型 API 到 Agent API

可以把 OpenAI 平台几年的演变连起来：

| 时间 | API 形态 | 系统假设 |
|---|---|---|
| 2020 | Completion API | 模型输出文本 |
| 2023-06 | Function Calling | 模型输出结构化行动意图 |
| 2023-11 | Assistants API | 平台维护 thread、files、tools |
| 2025-03 | Responses / Agents SDK | 平台显式支持 tool loop、handoff、guardrails、trace |
| 2026 | sandbox / long-horizon runtime | 状态、执行环境与任务生命周期进一步分离 |

这张表比“模型参数变大”更能解释 Agent 软件栈是怎样长出来的。

### 评曰

2025 年 3 月最重要的 Agent 变化，是“自主性”第一次被大量拆成普通软件组件。

AutoGPT 时代，开发者像是在召唤一个整体的智能人格：给它目标，然后看它自己想办法。

两年后，AWS 和 OpenAI 的产品语言已经完全不同：supervisor、collaborator、handoff、guardrail、trace、tool、IAM。

这些词没有“AI 员工”那么浪漫，却说明 Agent 真正开始成熟。

因为可靠系统不是靠一个整体人格维持，而是靠**明确的责任边界与可观察结构**维持。

Agent 时代真正的工程化，就是把“它自己会做”逐渐拆成：

> **谁决定、谁执行、谁能访问什么、谁记录、谁验证、失败后谁接管。**
