# 2025年12月

## Agent 开放基础设施开始有自己的基金会：AAIF、GPT-5.2、Seed1.8 与 GPT-5.2-Codex

> 2025 年 12 月的模型竞争依然激烈，但 Agent 历史出现了一个更像 Linux / CNCF 的节点：**12 月 9 日，Linux Foundation 成立 Agentic AI Foundation（AAIF），MCP、goose 与 AGENTS.md 成为首批项目。** 两天后，OpenAI 把 GPT-5.2 直接定义为“面向专业工作和 long-running agents”的旗舰；18 日，字节 Seed 团队发布 generalized agentic model Seed1.8，OpenAI 同日又用 GPT-5.2-Codex 把 compaction、sandbox 与 network policy 写进 agentic coding 系统。模型、运行时和开放治理第一次在同一个月里清晰合流。

### Agentic AI Foundation：Agent 基础设施进入中立治理

**2025-12-09** — Linux Foundation 宣布成立 **Agentic AI Foundation（AAIF）**。首批锚定项目包括：[^1]

- Anthropic 的 **Model Context Protocol（MCP）**；
- Block 的本地优先 Agent 框架 **goose**；
- OpenAI 推动的仓库级 Agent 说明规范 **AGENTS.md**。

AWS、Anthropic、Block、Bloomberg、Cloudflare、Google、Microsoft、OpenAI 等成为基金会的重要参与者。

这件事的历史意义不在于“又多一个 Linux Foundation 项目”，而在于 Agent 生态第一次清楚出现一个**厂商之外的公共治理层**。

此前 Agent 开放性主要讨论模型权重、SDK 和框架能不能开放；AAIF 把问题推进到：

> **如果大量不同厂商的 Agent 都依赖同一套协议、仓库规范和运行组件，这些基础设施最终由谁维护、谁决定版本演进？**

这已经不是模型许可证问题，而是基础设施治理问题。

### Anthropic 把 MCP 捐给 AAIF

同日，Anthropic 宣布将 **MCP 捐给 AAIF**。[^2]

Anthropic 称，当时生态中已经有超过 **10,000 个 active public MCP servers**，并列举 ChatGPT、Cursor、Gemini、Microsoft Copilot、Visual Studio Code 等产品采用 MCP。

这里要区分两件事：

1. MCP 的最初设计与发布来自 Anthropic；
2. 协议走向中立治理后，其生态价值不再取决于 Claude 是否继续占主导。

这是开放协议真正成熟的一个信号：

> **发明者开始愿意放弃独占治理，换取更广泛的互操作信任。**

### AGENTS.md：Agent 也需要仓库里的“本地法律”

AAIF 首批项目中的 **AGENTS.md** 看起来比 MCP 更小，却非常值得写入 Agent 史。

传统 README 是写给人看的。AGENTS.md 则尝试提供一个跨 coding-agent 可识别的仓库级说明位置：告诉 Agent 项目结构、构建方式、测试约定、风格、边界和工作规范。

它反映了一个成熟趋势：

> **当 Agent 能进入同一个代码库工作，仓库需要一种不依赖某个厂商 system prompt 的本地规则。**

Agent 的“宪法”开始从模型供应商层下沉到资源所有者层。

### GPT-5.2：旗舰模型直接面向 Professional Work 与 Long-running Agents

**2025-12-11** — OpenAI 发布 **GPT-5.2**，官方副标题直接写为：**“The most advanced frontier model for professional work and long-running agents.”**[^3]

相比传统“更高 benchmark”发布，GPT-5.2 更强调 spreadsheet、presentation、coding、视觉理解、长上下文、tool calling 与复杂 multi-step project。

前沿模型的产品目标已经发生变化：

> 早期模型问“知道多少”；推理模型问“能想多深”；Agent 模型进一步问“能在工具和环境里连续推进多久，并最终交付什么”。

“Long-running agent”已经直接进入 GPT 主线旗舰的官方定位。

### 12月18日：中美两条 Agent 模型路线同时变得清晰

#### ByteDance Seed1.8：Search、Code、GUI 合成 Generalized Agentic Model

**2025-12-18** — 字节跳动 Seed 团队发布 **Seed1.8**，官方直接将其称为 **generalized agentic model**。[^6]

与只强调某一种 tool calling 的模型不同，Seed1.8 把几类此前经常分离的 Agent 能力放进同一个模型方向：

- Search；
- Code；
- GUI interaction；
- complex workflow；
- 多模态理解与执行。

这在中国 Agent 史里很重要，因为字节的产品层已经拥有扣子、豆包、开发者平台与移动端分发入口。Seed1.8 因此不只是一个“会调用工具的模型”，而是在为更完整的 Agent 产品栈提供底座。

这条路线后来会继续推进到 Seed2.x：模型发布不再只描述语言能力，而把真实任务执行、GUI、搜索和代码明确放在同一个“生产力模型”框架中。

它也说明中国 Agent 竞争并不只发生在 Agent Builder / App 层。**Agent 能力本身正在被训练进基础模型。**

#### GPT-5.2-Codex：Compaction、Sandbox、Network Policy 进入模型发布正文

同日 OpenAI 发布 **GPT-5.2-Codex**，称其为面向复杂真实软件工程的 advanced agentic coding model。[^4]

官方明确列出：

- 通过 **context compaction** 改善 long-horizon work；
- 更强的大规模 refactor / migration；
- 更好的 Windows 环境支持；
- 更强 cybersecurity 能力。

system card 进一步说明产品层安全：[^5]

- **agent sandboxing**；
- **configurable network access**；
- prompt injection 等模型层安全训练。

于是同一天出现两种很有代表性的 Agent 模型定义：

- Seed1.8 强调 **Search + Code + GUI + workflow** 的通用行动能力；
- GPT-5.2-Codex 强调 **long-horizon coding + compaction + sandbox + network policy** 的工程执行能力。

前者更接近“通用软件世界 Agent”；后者更接近“高可靠工程 Agent”。

### 从开放模型到开放 Agent 基础设施

2023—2024 年最显眼的开放问题是模型权重。

2025 年底出现另一种开放层：

- MCP：开放工具连接协议；
- A2A：开放 Agent-to-Agent 协议；
- AGENTS.md：开放仓库行为说明惯例；
- goose：开放 Agent runtime / framework；
- AAIF：开放治理层。

这说明 Agent 时代的“开源”对象已经从一个 `.safetensors` 文件扩展到整个执行系统。

一个闭源模型也可能运行在开放协议上；一个开放权重模型也可能依赖私有云 runtime。开放性开始成为多层属性。

### 评曰

2025 年 Agent 史从 AutoGPT 式“一个程序自己循环”开始时，人们最关心模型有没有自主性。

到年底，行业讨论的词已经变成：

> protocol、governance、GUI、workflow、compaction、sandbox、network access、repository instructions。

这些词听起来远不如“AI 员工”浪漫，却更接近真正的基础设施。

AAIF 的成立说明生态开始建立公共制度；GPT-5.2 / Codex 说明前沿模型开始围绕长程执行与安全运行定义自己；Seed1.8 则说明中国基础模型公司同样把搜索、代码、GUI 和复杂工作流直接收进模型目标。

于是 2025 年末，两条线终于合上：

> **模型越来越适合长程执行，生态越来越适合承载长程执行。**

而 Agent 模型本身也不再只有一种形态：coding、GUI、search、workflow 都开始被训练进底座。
