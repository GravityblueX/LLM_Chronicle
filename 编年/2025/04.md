# 2025年4月

## 模型竞争之外，Agent 开始互相说话：Llama 4、A2A / ADK、o3 与 Qwen3

> 2025 年 4 月表面上仍然非常“模型中心”：Llama 4、o3、Qwen3 接连发布。但 **4 月 9 日** Google 发布 A2A 与 ADK，给 Agent 历史增加了另一条主线：工具调用标准化之后，不同 Agent 之间的发现、委派和协作也开始协议化。模型越来越强的同时，行业开始搭建“多个智能体如何组成系统”的基础设施。

### Llama 4：MoE 旗舰与评测信任争议

**2025-04-05** — Meta 发布 **Llama 4 Scout / Maverick**，Llama 系列首次全面采用 MoE 架构。[^1]

Scout / Maverick 以较低 active parameter count 换取大总容量，并强化多模态和长上下文能力。

发布后，LMArena 所用 Maverick 实验版本与实际公开版本之间的差异引发社区争议。这里不需要把争议夸大成“开源路线崩塌”，但它提醒行业：

> **当 benchmark 已经成为商业叙事，评测版本与用户实际获得版本是否一致，本身就是可验证性问题。**

这条问题后来也会进入 Agent 评测：模型分数、harness、工具、环境设置任何一项变化，都可能改变最终任务完成率。

### A2A：Agent-to-Agent 进入开放协议时代

**2025-04-09** — Google 与超过 50 家技术伙伴共同发布 **Agent2Agent Protocol（A2A）**。[^2]

A2A 试图解决的问题不同于 MCP。

MCP 更接近：

> Agent 怎样访问工具、数据和资源？

A2A 更接近：

> 一个 Agent 怎样发现另一个 Agent、理解它的能力、委派任务、交换状态和收取产物？

在早期多 Agent 框架里，所有 Agent 往往存在于同一个 Python 进程、同一个框架、甚至同一个 prompt 里。真实企业环境却可能同时存在：

- Salesforce Agent；
- Google Agent；
- Microsoft Agent；
- 自建 Agent；
- SaaS 第三方 Agent。

如果每一对都写私有接口，互操作成本会迅速爆炸。

A2A 因而把多 Agent 从**框架内部编排**推进到**跨厂商系统互操作**。

### ADK：多 Agent 开发框架与协议同日发布

同日，Google 发布开源 **Agent Development Kit（ADK）**。[^3]

ADK 支持构建由多个专业 Agent 组成的工作流，并把工具、状态、session、evaluation 和 deployment 视为系统组成。

A2A 与 ADK 同日出现非常有象征性：

- ADK：**我怎样构建一组 Agent？**
- A2A：**我的 Agent 怎样和外部 Agent 协作？**

前者是框架问题，后者是网络问题。

两者一起说明多 Agent 已经从“几个角色互相聊天”的研究演示进入软件架构阶段。

**2025-06-23**，A2A 项目进入 Linux Foundation，由中立治理继续发展。[^4]

到 2026 年 4 月，Linux Foundation 宣布已有 150 多个组织支持，并进入主要云平台及企业生产环境。[^5]

因此 2025 年 4 月的 A2A 不是一次短命 Google API，而是 Agent 协议栈形成过程中的关键节点。

### o3 / o4-mini：推理模型继续产品化工具能力

**2025-04-16** — OpenAI 正式发布 **o3 与 o4-mini**。[^6]

与 2024 年底的预告不同，这次是面向实际产品/API 的正式可用发布。

从 Agent 史看，比单项数学 benchmark 更值得注意的是推理模型越来越与 tools、视觉输入和多步工作流绑定。Test-time compute 的目标开始从“把一道题想对”扩展为“在复杂任务中决定下一步该做什么”。

### Qwen3：混合思考与开放模型族

**2025-04-29** — Qwen 团队发布 **Qwen3** 开放模型系列，提供 dense 与 MoE 多种尺寸，并支持 thinking / non-thinking 两种工作模式。[^7]

Qwen3 的“思考开关”延续了 2025 年初的一条产品趋势：推理预算不再必须通过切换到完全不同模型来获得。

对 Agent 而言，这非常实用。一个长程任务中：

- 读取文件不需要每一步深思；
- 规划架构可能需要更高 reasoning effort；
- 格式转换适合快速模式；
- 冲突仲裁再切到深度推理。

**动态分配推理预算**因此会成为 Agent runtime 的一部分。

### 月度数据小结

| 日期 | 事件 | 主要历史线 |
|---|---|---|
| 04-05 | Llama 4 | MoE / 多模态 / 评测可信度 |
| 04-09 | A2A | Agent ↔ Agent 互操作协议 |
| 04-09 | ADK | Multi-Agent 开发框架 |
| 04-16 | o3 / o4-mini | 推理 + tool-use 产品化 |
| 04-29 | Qwen3 | 开放模型族 + 动态 thinking |

### 评曰

如果只按模型排名看 2025 年 4 月，这个月很容易被写成 Llama、o3、Qwen 谁更强。

但 Agent 历史提供了另一种切法。

Function Calling 解决“一次行动怎样结构化”；MCP 开始解决“工具世界怎样接入”；A2A 则进一步问：

> **如果一个 Agent 自己也可以被当成能力，那么它和工具有什么不同？它怎样被发现、委派和协作？**

这时“多 Agent”才真正走出同一个 prompt 里的角色扮演。

它开始拥有网络协议意义上的边界。
