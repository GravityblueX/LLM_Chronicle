# 2025年7月

## ChatGPT Agent：Research 与 Action 第一次在大众产品中合流

> 2025 年初，OpenAI 还把两类 Agent 分成独立产品：Deep Research 负责“查”，Operator 负责“做”。**7 月 17 日，ChatGPT Agent 把两条线合起来：系统可以自己决定什么时候研究、什么时候运行代码、什么时候使用虚拟浏览器、什么时候请求人类确认。** 这标志着通用消费级 Agent 从“一个专用模式”进入 ChatGPT 主产品。

### 发布

**2025-07-17** — OpenAI 发布 **ChatGPT Agent**。[^1]

官方将它描述为 Operator 与 Deep Research 的自然演进：

- Deep Research 提供多步研究、来源阅读与报告整合；
- Operator 提供 visual browser / computer-use 行动；
- ChatGPT 提供对话、推理和用户协作界面；
- 系统另有 terminal / code execution 等工具用于分析和生成文件。

用户不再需要先判断“这件事应该进 Deep Research 还是 Operator”。Agent 可以根据任务动态切换工具。

### 为什么“Research + Action”合流很重要

此前 Agent 产品往往按工具类型切分：

- 搜索 Agent；
- 浏览器 Agent；
- coding agent；
- data-analysis agent。

但用户目标并不按工具分类。

比如：

> “研究三个竞争对手，比较产品和价格，然后生成一份表格和演示文稿。”

这个目标可能需要：

1. 搜索网页；
2. 阅读文档；
3. 操作网站；
4. 运行代码整理数据；
5. 生成表格；
6. 制作 slides；
7. 在高风险行动前请求用户确认。

真正通用的 Agent 因而必须把工具选择本身交给 runtime，而不是让用户手工进入不同模式。

### Operator 被吸收：Agent 产品从“机器人”回到工作流

OpenAI 在发布时明确表示 Operator 的核心功能被整合进 ChatGPT Agent，独立 Operator 体验随后逐步退出。[^2]

这很值得记。

2025 年 1 月 Operator 的视觉形象非常拟人：一个会替你上网操作的 Agent。

半年后，它不再需要独立品牌。

这说明行业对 Agent 的理解正在变化：真正有价值的不是“有一个会点网页的机器人”，而是：

> **在完整任务中，网页操作只是系统众多行动能力之一。**

### 高风险行动必须重新交还控制权

OpenAI 同时强调 ChatGPT Agent 在有后果的动作前会请求确认，用户可以中断、接管或停止任务。[^1]

Agent 产品越通用，这一层越重要。

一个研究 Agent 读错网页，主要造成错误信息；一个能同时操作网站、文件和第三方应用的 Agent，可能：

- 发出消息；
- 修改文件；
- 提交表单；
- 触发购买；
- 改变账户状态。

因此“统一 Agent”并不意味着“统一权限”。

真正成熟的 runtime 需要按动作风险分层：

- 只读动作可以自动执行；
- 可逆写操作可以低摩擦执行；
- 金钱、发布、删除等高风险动作需要更明确的确认或授权边界。

### 从聊天入口到任务控制面

ChatGPT 最初的交互单位是 message。

ChatGPT Agent 的交互单位越来越像 task：

- 用户定义目标；
- Agent 执行一系列隐藏或可见步骤；
- 用户在必要时确认 / 纠偏；
- 最终得到完成物。

这意味着聊天框本身没有消失，但角色变了。

它从“工作发生的唯一地方”，逐渐变成：

> **目标输入、进度观察、权限确认和异常接管的控制面。**

这一变化后来会在多 Agent workspace、Codex App、GitHub Agents tab 等产品中变得更明显。

### 评曰

ChatGPT Agent 的意义不在于 OpenAI 第一次造出了 Agent。

到 2025 年 7 月，AutoGPT、Devin、Claude Code、Operator、Deep Research、Copilot Agent Mode 都已经存在。

真正的变化是：**Agent 开始停止以“Agent 产品”自居。**

研究、浏览器、代码执行、文件生成、第三方数据访问被合并进同一个任务系统。用户不需要知道后台用了什么工具，只需要定义目标，并在高风险边界上保留控制。

这和个人电脑历史很像：早期用户需要知道某个程序具体操作哪种设备；成熟操作系统则把设备调度藏在系统下面。

Agent 产品也在走同样的路：

> **工具越来越多，用户反而越来越不需要管理工具。**
