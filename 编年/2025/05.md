# 2025年5月

## Coding Agent 获得自己的云电脑：Codex、Terminal-Bench、Remote MCP 与 Claude 4

> 2025 年 5 月把 Agent 从“IDE 里能自己改代码”再推进一层：**Codex 把任务送进独立云沙箱并允许并行执行；Terminal-Bench 开始专门评测终端 Agent；Responses API 引入 remote MCP 与 background mode；Claude 4 则把 extended thinking、parallel tools、code execution、MCP connector 和文件能力打包进 Agent 开发栈。** Agent 的核心问题越来越像运行时工程，而不是提示词工程。

### 关于 Claude Max：先校正旧稿的定价误读

旧版条目把 Claude Max 写成“$200/月基础费 + 最高 $100/月按深度思考附加费”。这个描述不正确。

Anthropic 在 **2025-04-09** 已经发布 Max Plan；其结构是固定月费的不同用量档：**Max 5x 为 $100/月，Max 20x 为 $200/月**，不是按每次 extended thinking 另行附加费用。[^1]

因此本月不再把“按深度思考用量收费”写成 Anthropic 在 5 月发明的新商业模式。Agent 的真实成本问题仍然存在，但应该在 API token、订阅额度、工具调用和任务总成本上讨论，而不是建立在错误的套餐描述上。

### Codex：任务进入独立 Cloud Sandbox

**2025-05-16** — OpenAI 发布 **Codex** research preview，一个云端 software engineering agent。[^2]

Codex 可以：

- 回答代码库问题；
- 修改功能；
- 修复 bug；
- 运行测试 / lint；
- 提交供审查的改动；
- 并行处理多项任务。

真正重要的系统设计是：**每个任务都运行在独立 cloud sandbox 中，预先加载用户 repository。**

这与同屏 IDE Agent 有根本差异。

IDE Agent 通常和人共享同一个工作目录；Codex 把任务委派给后台 worker：

> repository → isolated environment → autonomous edits/tests → result / PR → human review

于是 coding agent 开始像 CI job、build worker 或任务队列，而不是“更聪明的编辑器插件”。

独立环境同时解决多个问题：

- 多任务并行不互相踩文件；
- 依赖与命令可以真实执行；
- 失败任务可以隔离；
- 人类只需要审查最终 diff / test，而不是盯住每次 token 输出。

这套形态后来会成为 Codex App、GitHub coding agent 与大量云端 engineering agents 的共同模式。

### Terminal-Bench：shell 成为 Agent 的通用机器接口

**2025-05-19** — **Terminal-Bench** 发布。[^3]

它专门评测 Agent 在 terminal / shell 环境中完成复杂任务的能力。

这个 benchmark 的意义不仅是“又多了一个代码榜”。终端对 Agent 有特殊优势：

- 输入输出是结构化文本；
- 命令容易记录、重放和审计；
- 可以访问文件、网络、进程、包管理器和编译器；
- 相比 GUI，不需要精确像素定位；
- 相比单一 API，又足够通用。

因此 terminal 逐渐成为 Agent 世界的“通用机器语言”之一。

### Responses API：Remote MCP 与 Background Mode

**2025-05-21** — OpenAI 为 Responses API 增加 **remote MCP server**、Code Interpreter、image generation、改进的 file search，以及 **background mode** 等能力。[^4]

这里有两处 Agent runtime 的关键变化。

#### Remote MCP：工具协议从本地进入云 API

Agent 不再只连接应用内写死的函数，也可以连接远程 MCP server。

这推动 MCP 从“Claude Desktop / 本地开发者工具协议”走向跨产品工具层。

#### Background Mode：任务生命周期与连接生命周期解耦

长程推理和 Agent 任务可能运行几分钟甚至更久。如果一次网络连接断开就等于任务消失，系统无法成为可靠后台 worker。

Background mode 允许异步启动任务，之后轮询或重新接收事件。

这看起来只是 API feature，却代表一个重要转折：

> **Agent task 开始成为有自身生命周期的 durable object，而不是一次 HTTP response。**

### Claude 4：Reasoning 与 Tool Use 交替

**2025-05-22** — Anthropic 发布 **Claude Opus 4 / Sonnet 4**。[^5]

Anthropic 明确把 coding、advanced reasoning 和 AI agents 作为核心场景，并引入 / 强化：

- extended thinking with tool use；
- parallel tool use；
- 更长任务中的 memory 行为；
- 更强的 coding-agent 工作流。

其中最值得 Agent 史记录的是：**推理过程可以在工具调用之间继续。**

早期工具循环常像：

> 想完 → 调工具 → 得结果 → 再重新开始

Claude 4 更明确地把 reasoning 与 tool use 交织成持续循环。

这使 test-time compute 与 Agent runtime 更难分开：模型“多想”不只是生成更长 reasoning，而是可能多搜索一次、多执行一次代码、多验证一条假设。

### Anthropic API：Code Execution、MCP Connector、Files API

同日，Anthropic 发布面向 Agent 的 API 能力，包括：

- **code execution tool**；
- **MCP connector**；
- **Files API**；
- 更长 prompt caching。[^6]

这和 OpenAI 前一天的 remote MCP / background mode 构成非常直接的行业信号：

> Agent 竞争正在从“哪个模型更会规划”变成“哪家平台给模型更完整的运行环境”。

### 五月的 Agent 系统栈

| 日期 | 事件 | Agent 层 |
|---|---|---|
| 05-16 | Codex | cloud sandbox / async delegation |
| 05-19 | Terminal-Bench | executable Agent evaluation |
| 05-21 | Remote MCP | tool protocol integration |
| 05-21 | Background Mode | long-running task lifecycle |
| 05-22 | Claude 4 | reasoning ↔ tools loop |
| 05-22 | Anthropic agent API tools | code / files / MCP runtime |

### 评曰

2023 年的 Agent 问题是：**它会不会自己循环？**

2025 年 5 月的问题已经变成：

> **循环在哪里跑？任务状态放在哪里？工具怎样连接？环境怎样隔离？结果怎样验证？断线以后怎样继续？**

这说明 Agent 已经从语言模型技巧进入计算机系统工程。

Codex 的 cloud sandbox、Terminal-Bench 的 shell 环境、Remote MCP、Background Mode、Claude 的 code execution 和 files，看起来是不同公司的不同功能，实际上都在补同一台“Agent 计算机”的不同部件。

Agent 时代真正成熟的标志，不是模型越来越像一个人。

而是围绕模型，**操作系统开始长出来了。**
