# 2023年8月

## Code Llama：Meta 正式进入 AI 编程助手赛道

> Llama 2 发布仅一个月，Meta 就把它"再训"了一次——这次只用代码数据。Code Llama 不是一个独立的模型，而是 Llama 2 的代码特化版。Meta 用这个动作宣布：开源世界的 AI 编程助手，不必依赖 OpenAI。

**2023-08-24** — Meta AI 发布 **Code Llama**，基于 Llama 2 的代码专用大语言模型家族。[^1] 提供四个参数规模：7B、13B、34B、70B，同时推出两个变体：**Code Llama - Python**（Python 专项优化）和 **Code Llama - Instruct**（指令跟随优化）。所有模型均以研究许可开放权重，与 Llama 2 保持一致。

> 📖 详见《Llama 世家》《Codex / GitHub Copilot 列传》。

### 模型家族

| 版本 | 参数 | 训练基础 | 核心定位 |
|------|------|---------|---------|
| Code Llama 7B | 7B | Llama 2 7B + 代码数据 | 轻量本地部署，低延迟补全 |
| Code Llama 13B | 13B | Llama 2 13B + 代码数据 | 性能与速度的平衡点 |
| Code Llama 34B | 34B | Llama 2 34B + 代码数据 | 高质量代码生成 |
| Code Llama 70B | 70B | Llama 2 70B + 代码数据 | 旗舰，对标 GPT-3.5 级编程能力 |
| Code Llama - Python 7B/13B/34B | 同上 | Code Llama + Python 数据续训 | Python 专项优化 |
| Code Llama - Instruct 7B/13B/34B | 同上 | Code Llama + 指令微调 | 对话式编程和指令跟随 |

训练方法上，Code Llama 在 Llama 2 的基础上，用约 500B tokens 的代码数据进行了续训（continued pretraining）。[^1] 数据来源包括公开的 GitHub 代码仓库和与代码相关的自然语言文本（如 StackOverflow 问答）。这不是从头训练——而是用代码数据"刷新"一个已经学会了语言和推理的通用模型，让它把能力聚焦到代码领域。

### 性能

Code Llama 70B 在 HumanEval 上达到 **53.7%**（pass@1），在当时是开源代码模型的最高分。[^1] 作为对比：

| 模型 | HumanEval pass@1 | 发布时间 |
|------|:--:|:--:|
| Codex 12B（OpenAI） | 28.8% | 2021-08 |
| Code Llama 7B | 29.9% | 2023-08 |
| Code Llama 34B | 48.8% | 2023-08 |
| Code Llama 70B | 53.7% | 2023-08 |
| GPT-4（OpenAI） | 67.0% | 2023-03 |
| Claude 3.5 Sonnet（Anthropic） | 92.0% | 2024-06 |

Code Llama 70B 的 53.7% 虽然远低于 GPT-4 的 67%，但作为一个开放权重模型，它为社区提供了 GPT-3.5 级别的编程能力——不需要 API 调用费用，可以本地部署、自由微调、适配私有代码库。

值得注意的是，Code Llama 7B（29.9%）已经超过了 Codex 12B（28.8%）。[^1] 一个 7B 的开源模型，在两年内追平了 OpenAI 的开创性工作。这是 Llama 系列"小而高效"路线在代码领域的延续。

### 长上下文能力

Code Llama 引入了一个关键技术特性：**长上下文微调（Long Context Fine-Tuning）**。[^1] 标准 Llama 2 的上下文窗口为 4K tokens；Code Llama 通过额外的长上下文微调阶段，将上下文窗口扩展到 **100K tokens**。

这个能力在代码场景中至关重要：理解一个中等规模的代码库、处理一个长函数、分析跨文件的依赖关系——这些任务都需要比 4K tokens 更大的上下文。100K tokens 意味着 Code Llama 可以一次"看到"约数千行代码，这对于代码补全和代码问答来说是一个质的提升。

### Meta 的战略位置

Code Llama 的发布，标志着 Meta 在 AI 编程助手赛道上的正式入局。在此之前，AI 编程助手的竞争主要在 OpenAI（Codex / Copilot）和 GitHub 之间展开；Anthropic 的 Claude 虽然有编程能力，但尚未以编程助手为核心定位。Code Llama 改变了格局——它证明开源模型也可以做代码专用模型，而且可以做到相当强。

从 Llama 生态的角度看，Code Llama 是 Meta "通用基座 + 专业特化"策略的第一次实践：

- **Llama 2**（2023-07）：通用语言模型基座
- **Code Llama**（2023-08）：代码专业版
- 后续还有 **Llama Guard**（安全）、**Purple Llama**（红队测试）等特化模型

这种"一个基座、多个特化"的策略，让 Llama 生态从一个单一模型变成了一个模型家族——每个特化模型都继承了基座的语言理解能力，同时在特定领域获得了显著增强。

### 开源编程助手生态的起点

Code Llama 发布后，社区迅速将其整合到各种 AI 编程工具中。HuggingFace 上出现了大量基于 Code Llama 的微调版本——针对特定编程语言（Rust、Go、Java）、特定框架（React、Django）、甚至特定代码风格的定制模型。Ollama、llama.cpp 等本地运行工具让 Code Llama 可以在消费级硬件上运行——一个 7B 量化后的 Code Llama 只需 4GB 显存。

这为后来的开源编程助手生态（如 Continue、Tabby、Aider 等开源 Copilot 替代品）奠定了模型基础。在 Code Llama 之前，"开源版 Copilot"缺的不是前端工具，而是一个足够强的底层模型。Code Llama 填上了这个缺口。

### 评曰

Code Llama 本身不是一个惊天动地的发布——它是 Llama 2 的代码续训版本，技术路线直接、没有架构创新。但它的位置很重要：**它是开源社区获得"可商用、可微调、可本地部署"的代码模型的起点。**

在 Code Llama 之前，想做"开源 Copilot"的开发者面对的问题是：底层模型不够强（StarCoder 在 HumanEval 上约 33%），或者模型太强但不允许商用（Codex）。Code Llama 70B 的 53.7% + 开放商用许可，第一次让"基于开源模型的 AI 编程助手"成为一个现实选项。

Meta 的策略一如既往地清晰：不靠卖模型赚钱，靠开源建立生态。Code Llama 越多人用，Llama 生态就越不可替代。这个逻辑在 Code Llama 上和在 Llama 2 上完全一样——开源不是慈善，是竞争。
