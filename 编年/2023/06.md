# 2023年6月

## Function Calling：Agent 的“手”从 Prompt Hack 变成 API 原语

> 2023 年春天的 Agent 热潮最吸睛的是 AutoGPT：给 GPT-4 一个目标，让它自己循环、搜索、执行。但真正决定 Agent 能否从演示走向软件工程的变化，往往没有那么戏剧化。**2023 年 6 月 13 日，OpenAI 把函数调用做成了 API 原语。** 从这一天起，“模型想调用一个工具”不必再伪装成一段约定格式的自然语言文本，而可以被表达为结构化函数名和 JSON 参数。

### 发布

**2023-06-13** — OpenAI 发布 GPT-4 / GPT-3.5 Turbo API 更新，引入 **Function Calling**。开发者可以向模型提供函数描述与 JSON Schema；模型根据用户请求判断是否需要调用函数，并生成与 schema 对齐的函数参数。[^1]

这项能力本身不执行函数。真正的执行仍由应用程序完成：

1. 应用把可用函数及 schema 发给模型；
2. 模型返回函数名与结构化参数；
3. 应用验证参数并执行真实工具；
4. 工具结果重新送回模型；
5. 模型结合结果继续回答或选择下一步行动。

这个流程后来成为主流 LLM Agent 的基本工具循环。

### 在它之前：工具调用是一种脆弱的 Prompt Hack

ReAct 在 2022 年已经清楚展示了 `Thought → Action → Observation` 的闭环；Toolformer 又在 2023 年初研究模型怎样学习何时调用外部 API。[^2][^3]

但工程实现仍然很粗糙。开发者常在 prompt 里要求模型输出：

```text
SEARCH("latest weather in Paris")
```

或者：

```text
CALL_WEATHER(city="Paris")
```

程序再用正则、字符串解析或手写 parser 猜模型究竟想干什么。

这有几个显然的问题：

- 少一个引号或括号就可能解析失败；
- 参数类型只能靠模型自觉遵守；
- 文本回答和行动意图混在同一个通道；
- 工具越多，prompt 越长，约定越复杂；
- 模型幻觉一个不存在的工具时，系统很难判断是语言错误还是执行请求。

Function Calling 的价值，就是把“**行动意图**”从普通文本中剥离出来。

### 结构化调用并不等于安全执行

Function Calling 解决的是**表示层**，不是完整的 Agent 安全问题。

一个模型可以非常正确地生成：

```json
{"recipient":"all@example.com","body":"..."}
```

但这不代表系统就应该真的把邮件发出去。

因此，从 Function Calling 开始，Agent 工程逐渐出现一条后来越来越重要的分层：

- **模型决定想做什么**；
- **schema 决定参数应长什么样**；
- **应用决定这个动作是否允许**；
- **执行环境真正改变外部状态**；
- **结果再作为 observation 回到模型。**

权限、确认、sandbox、审计和 rollback 都还在后面，但一个基本边界已经出现：**模型不应该等于执行器。**

### 与 Plugins、AutoGPT 的关系

三个月前，ChatGPT Plugins 已经向大众展示了模型调用外部服务的可能；AutoGPT 随后把自主循环推到极端。[^4]

Function Calling 的意义不同。

Plugins 更像产品生态：**“ChatGPT 可以接什么服务？”**

AutoGPT 更像自主性实验：**“如果不给模型逐步指导，它能自己跑多久？”**

Function Calling 回答的是更基础的工程问题：

> **“模型怎样稳定地告诉软件：我现在想调用哪个工具，以及参数是什么？”**

后来的 Anthropic Tool Use、Google Function Calling、OpenAI Responses / Agents SDK，以及 MCP 上层的大量工具调用系统，都建立在类似的结构化思想上。

### 从文本生成器到控制面

在 GPT-3 时代，模型的输出主要供人阅读。

Function Calling 之后，模型输出的一部分开始直接供**程序消费**。

这是一条很重要的边界变化：

> 自然语言模型开始不只是生成信息，也开始生成机器可执行系统的**控制信号**。

模型仍然不直接拥有权限，但它已经进入应用程序的控制回路。

这正是后来 Agent 时代的基础。

### 评曰

2023 年 6 月的 Function Calling 很容易被更热闹的 AutoGPT 掩盖。

AutoGPT 给人的印象是：“AI 已经可以自己做事了。”Function Calling 做的却更像基础建设：它没有让模型突然更聪明，也没有让模型多会一种任务，只是让“行动”从脆弱文本变成结构化数据。

但历史常常是这种不起眼的接口变化更持久。

一个自主系统若连自己的行动意图都不能稳定表达，就谈不上可靠执行。**先让行动变得机器可读，才可能进一步谈权限、验证、恢复和审计。**

从这个意义上说，2023 年春天的 Agent 热潮证明了人们想把任务交给模型；6 月的 Function Calling 则开始回答：

> **怎样把这种愿望做成软件。**
