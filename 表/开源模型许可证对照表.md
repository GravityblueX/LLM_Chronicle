# 开放权重模型许可证对照表

> **先改名。** 本表过去叫“开源模型许可证对照表”，但其中 Llama、Gemma、RAIL、DeepSeek-V3 等并不都满足传统开源 / OSAID 意义。本表因此改用更准确的“开放权重模型”。

## 说明

大模型至少可能同时存在：

- **代码许可证**：推理 / 训练仓库代码；
- **模型许可证**：权重及其衍生物；
- **上游基座限制**：蒸馏 / 微调模型继承原基座条件；
- **用途限制**：禁止某些应用；
- **规模限制**：达到一定用户规模需额外授权。

**不要看到 GitHub 仓库写 MIT，就自动推断模型权重也是 MIT。** DeepSeek-V3 正是典型反例：代码 MIT，但模型权重使用 DeepSeek Model License。[^8]

本表也不自行给模型盖“OSAID 合格”章。OSI 的 Open Source AI Definition 是判断框架；是否满足应根据权重、代码、数据与使用自由逐项分析。[^1]

## 三种经常被混淆的情况

### 1. 仓库 MIT，模型不是 MIT

**DeepSeek-V3**：

- `LICENSE-CODE`：MIT；
- `LICENSE-MODEL`：DeepSeek License Agreement，并带 use-based restrictions。[^7][^8]

所以写“DeepSeek-V3 是 MIT 模型”不准确。

### 2. 主模型 MIT，蒸馏版继承别人的限制

**DeepSeek-R1** 主模型权重与代码明确 MIT，但：

- R1-Distill-Qwen 继承 Qwen2.5 上游许可；
- R1-Distill-Llama 继承 Llama 3.x 上游许可。[^9]

“这个仓库 MIT”不能抹掉 derivative model 的上游条款。

### 3. 权重开放，但许可证不属于经典开源许可证

**Kimi K3 License**给予非常宽的复制、修改、部署、衍生和分发权，但仍是 Moonshot 自定义许可证。[^14]

所以最清楚的写法是：

> “Kimi K3 开放权重，采用 Kimi K3 License。”

而不是把它强行归进 MIT / Apache。

---

## 许可证宽松度不等于实际开放度

2026 年以后还必须考虑**可运行性**。

| 模型 | 权重自由度 | 普通个人运行难度 | 现实控制权 |
|---|---|---|---|
| Kimi K3 2.8T | 高 | 极高 | 常需大型集群 / 云托管 |
| Qwen3.8 2.4T | 高 | 极高 | 推理基础设施成为核心门槛 |
| Muse Glimmer 30B | Apache 2.0 | 可在消费级硬件运行 | 用户可掌握本地 runtime |

因此“许可证更宽松”只回答法律自由度，不能回答用户是否真正拥有运行权。

## 推荐术语

| 情况 | 本项目建议用词 |
|---|---|
| 只确认权重可以下载 | **开放权重 / open-weight** |
| 代码是 MIT / Apache，但权重另有条款 | 分别写代码许可证、模型许可证 |
| 满足传统宽松许可证但训练数据不完整 | “MIT / Apache 开放权重”，不要自动写“完全开源 AI” |
| 数据、代码、权重、训练信息都高度透明 | 可进一步讨论“全栈开放” |
| 纯 API | 闭源 / 托管模型 |

---

## OSAID 与许可证不是一回事

OSI 的 Open Source AI Definition 关注的不只是许可证名字，还包括使用、研究、修改和分享系统所需的首选修改形式信息。[^1]

因此：

- Apache 2.0 是 OSI 批准的软件许可证；
- 这不自动证明某个 AI 系统完整满足 OSAID；
- 权重许可证宽松，也不自动解决训练数据 / 训练方法透明度问题。

旧版表中“OSI 认证 ✅”一列因此删除，避免把**软件许可证认证**和**AI 系统开放定义**混成同一个判断。
