# 训练计算量与成本对比表

> **说明**：大模型“训练成本”是最容易被媒体数字误导的指标之一。技术报告通常披露的是 FLOPs、accelerator hours、token 数或最终训练 run；媒体再乘一个假设的云 GPU 单价，就得到“成本”。这并不等于总研发成本，更不等于公司为了得到这个模型一共花了多少钱。
>
> 本表因此分开记录：**官方/论文披露的计算事实** 与 **外部换算/估计**。没有可靠数据就写“未披露”。

---

## 一、官方 / 论文可追溯的训练事实

| 模型 | 发布时间 | 已公开规模 | 官方 / 论文披露的训练事实 | 能否直接得出美元总成本？ | 出处 |
|---|---|---|---|:--:|---|
| GPT-3 | 2020 | 175B dense | 论文披露模型、数据与计算规模，可据 FLOPs 做外部估算 | ❌ | [^1] |
| Chinchilla | 2022 | 70B dense | 1.4T tokens；论文研究 compute-optimal scaling | ❌ | [^2] |
| PaLM | 2022 | 540B dense | 6,144 TPU v4，论文披露训练规模与计算 | ❌ | [^3] |
| GPT-4 | 2023 | **未披露** | OpenAI 技术报告明确不披露架构、参数、硬件和训练 compute | ❌ | [^4] |
| Llama 2 70B | 2023 | 70B dense | 论文披露预训练数据与 carbon / compute 信息，但美元成本不是官方数字 | ❌ | [^5] |
| Llama 3.1 405B | 2024 | 405B dense | Llama 3 报告披露 405B 训练计算 / accelerator 使用等工程信息 | ❌ | [^6] |
| DeepSeek-V3 | 2024-12 | 671B total / 37B active | **整个 V3 训练流程共 2.788M H800 GPU-hours；报告将其折算为约 $5.576M**（按 $2/H800-hour 的假设） | ✅，但只代表报告定义的训练计算成本 | [^7] |
| DeepSeek-R1 | 2025-01 | 基于 V3 | 论文披露 RL 方法、训练阶段与数据流程，**没有披露一个可核验的“R1 总美元训练成本”** | ❌ | [^8] |
| Qwen3 | 2025-04 | 最大 235B-A22B | 技术报告 / 发布材料披露架构与训练方法，美元总成本未公开 | ❌ | [^9] |
| Kimi K2 | 2025-07 | 1T / 32B active | 论文 / repo 披露架构、15.5T tokens 等训练信息；美元成本未公开 | ❌ | [^10] |
| Kimi K3 | 2026-07 | 2.8T / 104B active | 技术报告披露结构、训练方法和 scaling；美元总训练成本未公开 | ❌ | [^11] |
| Qwen3.8-2.4T-A95B | 2026-08 | 2.4T / ~95B active | 官方披露模型规模 / 结构 / 1M context；美元训练成本未公开 | ❌ | [^12] |
| DeepSeek V4 系列 | 2026 | Pro / Flash 等 | 已公开模型 / API 资料不等于完整训练成本披露 | ❌ | [^13] |

## 二、为什么 DeepSeek-V3 的“$5.576M”经常被误读

DeepSeek-V3 Technical Report 写道，完整训练需要 **2.788M H800 GPU hours**，并按 **$2 per H800 GPU-hour**折算为 **$5.576M**。[^7]

这是一项非常重要的工程数据，但它不能被改写成：

> “DeepSeek 只花 557 万美元就做出了 V3。”

因为该数字不自动包含：

- 研究人员薪酬；
- 数据采购 / 清洗 / 存储；
- 前置架构实验；
- 失败 run；
- 集群建设资本开支；
- 网络、机房、电力、冷却；
- inference / eval；
- 组织长期研发投入。

它最适合表述为：

> **V3 技术报告披露的最终训练计算预算，按报告采用的 H800-hour 单价折算约 $5.576M。**

这仍然足够惊人，不需要把它夸成整个项目 TCO。

## 三、外部估算可以用，但必须和官方数据分开

一些模型的训练美元成本只有外部研究机构估算。

| 模型 | 常见外部估算 | 为什么不应写成事实 |
|---|---|---|
| GPT-3 | 数百万美元量级 | GPU 价格、利用率、集群折旧假设不同 | [^14] |
| GPT-4 | 数千万到上亿美元量级 | OpenAI 未披露模型规模和训练硬件；任何精确参数 / 集群数都属估计 | [^14] |
| Llama 3 405B | 数千万美元量级 | Meta 披露 compute 比美元更可靠；云 GPU 单价不是自建集群真实成本 | [^6][^14] |

在史料里，**“外部估算 $X”**和**“厂商披露 $X”**必须是两种句式。

---

## 四、为什么“云 GPU 单价 × GPU 小时”只是影子价格

大厂很少按公有云挂牌价购买每个 GPU hour。

训练基础设施可能是：

- 自购 GPU / TPU；
- 多年折旧；
- 自建机房；
- 长期电力合同；
- 内部网络 / 调度；
- 设备同时承担多个训练和推理 workload。

所以 `GPU hours × $2/hour` 更像**机会成本 / 影子价格**，不是财务报表里的现金支出。

不同机构即使使用同样 1M GPU hours，真实财务成本也可能很不同。

---

## 五、训练成本不应该只按“总参数”预测

MoE 使总参数和训练 / 推理 FLOPs 解耦。

例如：

- DeepSeek-V3：671B total / 37B active；
- Kimi K3：2.8T total / 104B active；
- Qwen3.8：2.4T total / ~95B active。

因此“2.8T 比 405B 大七倍，所以训练一定贵七倍”没有意义。

训练成本还取决于：

- token 数；
- active parameters；
- forward/backward precision；
- expert routing；
- sequence length；
- parallelism；
- hardware utilization；
- communication overhead；
- optimizer / architecture efficiency。

总参数只是其中一个变量。

---

## 六、预训练也不再是唯一昂贵阶段

2024 以前，人们常把“训练成本”几乎等同于 pretraining。

Agent / reasoning 时代至少还包括：

- SFT；
- preference training；
- RL / verifiable rewards；
- synthetic data generation；
- environment rollouts；
- tool-use training；
- safety / red-team training；
- multimodal continued pretraining。

R1 就是典型：它建立在 V3 base 上，价值主要来自 reasoning 后训练。[^8]

如果只问“R1 训练多少钱”，首先要明确：

> 你是在问 V3 base 的 pretraining、R1-specific RL，还是从零得到整个系列的累计成本？

不定义口径，数字没有可比性。

---

## 七、训练成本与推理成本可以朝相反方向变化

一个更大的模型可能训练更贵，但推理因为：

- MoE；
- MLA / efficient attention；
- quantization；
- better routing；
- cache；
- higher task success rate

而拥有更低的**每个成功任务成本**。

反过来，一个训练便宜的模型如果推理时需要大量重试，也可能商业上更贵。

所以“训练成本排行榜”不能直接推出“哪家公司最有成本优势”。

> 📖 详见《论·推理经济学》《论·价格战》。

---

## 八、最值得长期记录的训练指标

与其维护未经验证的美元数字，本项目未来应优先记录：

| 指标 | 价值 |
|---|---|
| Training FLOPs | 跨硬件相对可比较的计算量 |
| Accelerator hours | 实际集群占用 |
| Accelerator type | H100/H800/TPU 等效率不同 |
| Training tokens | 数据规模 |
| Active params | MoE 计算量关键 |
| Precision | FP8 / BF16 等影响吞吐 |
| Duration | 工程 / 并行效率 |
| Energy / carbon（若披露） | 基础设施成本另一维 |
| Post-training rollouts | reasoning / Agent 成本越来越重要 |
| 官方美元计算估算 | 仅当厂商明确给出时记录 |

这比“据说花了几千万”更适合作为历史资料。

---

## 九、当前可下的结论

截至 2026 年，可以比较确定地说：

1. **前沿训练仍然是高度资本密集的活动；**
2. 架构和工程效率可以把同等能力所需 compute 大幅压低；
3. MoE 让“总参数”越来越不适合作为训练成本代理；
4. reasoning / Agent 后训练使 pretraining 不再代表全部模型研发；
5. 绝大多数闭源前沿模型的真实美元训练成本外界并不知道。

不知道就是重要事实。

一部编年史不需要替公司填满缺失的数据。
