# 开放权重模型生态影响力观察表

> **说明**：本文件路径保留“排行表”以避免破坏旧链接，但正文不再做一个伪精确的实时排名。Hugging Face 下载量、GitHub Stars、搜索命中数每天变化，而且不同模型族拆仓库 / 合仓库方式不同，直接相加并不公平。2026 年以后，2T—3T 旗舰和本地 Agent 又让“下载次数”更无法代表实际影响。
>
> 本表改为观察更稳定的**生态影响维度**：是否成为下游基座、推理框架覆盖、本地运行、许可证、旗舰开放程度、架构传播和产业影响。

---

## 一、为什么取消固定 Top 10 排名

旧版使用：

- Hugging Face 累计下载；
- GitHub Stars；
- 搜索关键词得到的“衍生模型数”。

这些指标有几个结构性问题：

1. **下载统计口径不一致**：模型是否拆成 Base / Instruct / quantized / branch 会改变计数；
2. **Stars 是仓库热度，不是模型部署量**；
3. **搜索命中数不是 lineage 统计**，模型名出现在 README 也会命中；
4. 小模型下载一次和 2.8T 模型托管一次的“影响”不能同权；
5. 统计快照很快过期，却会在 Git 历史里看起来像永久事实。

因此以后若要做精确排行，应由脚本在指定日期调用 API 生成 snapshot，而不是人工写死。

## 二、2026 年主要开放权重生态的结构性影响

| 模型族 | 开发方 | 代表开放节点 | 权重 / 许可特点 | 最明显的生态影响 | 本地 / 自托管位置 | 出处 |
|---|---|---|---|---|---|---|
| **Llama** | Meta | LLaMA → Llama 2 → 3.1 405B → Llama 4 | 自定义 Community License | 2023 开放权重爆发的最大起点；llama.cpp / GGUF / LoRA 等大量工具围绕其成熟 | 从消费级小模型到 405B 旗舰；本地生态极深 | [^1][^2] |
| **Qwen** | Alibaba | Qwen1.x → 2/2.5 → Qwen3 → **Qwen3.8 2.4T-A95B** | 多代际许可逐步放宽；Qwen3 主线 Apache；3.8 需按具体 release 核对 | 中文 / 多语言下游、代码 / VL、多尺寸基座；2026 Max 级旗舰进入开放权重 | 小尺寸可本地，大旗舰需要集群 | [^3][^4] |
| **DeepSeek** | DeepSeek | V2 → V3 → **R1** → V4 系列 | V3 代码 MIT / 模型自定义；R1 主模型 MIT | MLA、MoE、reasoning RL、蒸馏路线产生全球技术扩散；R1 是开放 reasoning 标志 | 蒸馏模型本地影响大；大模型需服务器 / 集群 | [^5][^6] |
| **Mistral** | Mistral AI | Mistral 7B / Mixtral | Apache 2.0 代表性强 | 证明欧洲团队可用小模型 / MoE 和宽松许可建立独立生态 | 7B / Mixtral 推动自托管与企业使用 | [^7] |
| **Kimi** | Moonshot | K2 → **K3 2.8T-A104B** | Kimi 自定义开放许可证 | 把开放权重推进到 3T 级、原生视觉、1M context 和 long-horizon Agent | K2 相对可部署；K3 高性能使用高度依赖大型集群 | [^8] |
| **Gemma** | Google | Gemma 1/2/3/4 系列 | Gemma 条款 / 具体版本许可 | Google 的小型开放模型路线，多模态 / edge 生态 | 重点是可部署尺寸，与 Gemini 闭源旗舰形成双轨 | [^9] |
| **Phi** | Microsoft | Phi-2 / Phi-3 / Phi-4 等 | 多个版本采用 MIT 等宽松许可，按模型卡核对 | small language model / synthetic data 路线影响大 | 边缘 / 本地是核心价值 | [^10] |
| **Muse Glimmer** | Meta | **30B（2026-08）** | Apache 2.0 | 把“开放影响力”重新定义为 always-on local Agent，而非只拼旗舰大小 | **明确面向 Mac / PC / 单张消费 GPU** | [^11] |
| **EleutherAI** | 社区 | GPT-Neo / J / NeoX / Pythia | MIT / Apache 等 | 数据、代码、训练日志、权重的全栈开放传统；研究可复现性标杆 | 不再是前沿能力竞争主角，但开放研究史影响极深 | [^12] |

## 三、影响力应该拆成五条轴

### 1. 基座影响（Base-model influence）

谁被最多下游拿去：

- fine-tune；
- distill；
- LoRA；
- domain adaptation。

Qwen、Llama 在这一轴上尤其重要；DeepSeek-R1 的蒸馏又反过来大量使用 Qwen / Llama 基座。[^6]

### 2. 工具链影响（Runtime influence）

一个模型是否迅速获得：

- Transformers；
- vLLM；
- SGLang；
- llama.cpp / GGUF；
- Ollama；
- quantization 工具；
- serving provider

支持，决定它能否从“发布权重”变成真正生态。

有时 runtime support 的价值比 GitHub Stars 更大。

### 3. 架构影响（Technical diffusion）

DeepSeek 的 MLA / MoE / reasoning RL，Mistral 的 Mixtral，Qwen 的 dense+MoE 全谱系，Kimi K3 的 KDA / Gated MLA / AttnRes，都属于这种影响。

即使下游不直接部署原模型，架构思路也可能被全行业吸收。

### 4. 部署影响（Deployability）

“开放”不等于“跑得起”。

2026 年尤其要区分：

- 消费级本地：Muse Glimmer、各种 Qwen/Phi/Gemma 小模型；
- 单机 / 多卡服务器：70B 级及部分 MoE；
- 大型集群：Qwen3.8 2.4T、Kimi K3 2.8T。

同样是开放权重，对用户实际控制权完全不同。

### 5. 产业议程影响（Agenda-setting）

有的模型改变的不只是下载量，而是整个行业讨论：

- LLaMA 泄漏 / Llama 2：开放权重是否会成为主流；
- Llama 3.1 405B：开放旗舰能否追闭源；
- DeepSeek-R1：reasoning 是否必须闭源高价；
- Kimi K3 / Qwen3.8：前沿权重开放后算力是不是新瓶颈；
- Muse Glimmer：Agent 的“开放”是否应该看本地运行权。

这种议程影响没有一个 API 数字能准确表示。

## 四、DeepSeek-R1 蒸馏生态：为什么 lineage 比下载榜更有意义

R1 同步发布基于 Qwen 与 Llama 的蒸馏模型。[^6]

| 系列 | 上游基座 | 生态意义 | 许可注意 |
|---|---|---|---|
| R1-Distill-Qwen | Qwen2.5 多尺寸 | 把 reasoning 行为迁移到更小、更易部署模型 | 继承 / 受上游 Qwen 许可影响 |
| R1-Distill-Llama | Llama 3.x | reasoning 与 Llama 生态结合 | 仍需遵守 Llama 上游许可 |

这个例子说明“DeepSeek 模型下载很多”不如另一句话重要：

> **它制造了一条跨模型族的 reasoning 能力传播链。**

开放模型影响力越来越需要 lineage graph，而不是 leaderboard。

## 五、推理工具本身已经成为开放生态的核心资产

开放权重之所以真正可用，很大程度上依赖模型之外的项目：

| 工具 | 作用 | 为什么重要 |
|---|---|---|
| llama.cpp | CPU / 边缘 / GGUF 推理 | 把 Llama 起家的本地生态扩展到大量模型族 | [^13] |
| Ollama | 本地模型管理 / 服务 | 把下载、启动、本地 API 简化成消费级体验 | [^14] |
| vLLM | 高吞吐 GPU serving | PagedAttention / continuous batching 等推动开放模型云部署 | [^15] |
| SGLang | LLM / VLM 高性能 serving 与 Agent workload | 对复杂生成 / tool workload 越来越重要 | [^16] |
| Transformers | 模型加载 / 生态 API | 事实上的开放模型通用分发层 | [^17] |
| PEFT | LoRA / adapters | 让下游能力不必复制完整权重 | [^18] |

所以开放生态的“赢家”未必是某个模型仓库，也可能是让所有模型都跑得起来的基础设施。

## 六、2026：超大开放旗舰与本地开放 Agent 分叉

### 超大旗舰

- Kimi K3：2.8T / 104B active；
- Qwen3.8：2.4T / ~95B active。

它们把前沿能力推到开放权重，却让高效部署进入资本密集区。

### 本地 Agent

Muse Glimmer 选择 30B 和消费级硬件。

它不争“世界最大开放模型”，而争另一种影响力：

> **让用户真正拥有运行时。**

因此 2026 年以后，“影响最大”可能同时有两个完全相反的答案：

- 谁把最高能力开放？
- 谁让最多人真的自己跑起来？

两者都值得单独记录。

## 七、许可证也是生态摩擦系数

许可证影响：

- 企业法务是否愿意批准；
- 云厂商是否愿意托管；
- 下游能否商用；
- 衍生模型如何分发。

旧版把 DeepSeek 全系概括 MIT，会高估 V2/V3 的许可宽松度。

本项目现在统一以《开放权重模型许可证对照表》为准，代码许可和模型许可分开记录。

## 八、如果未来要重新做“排行”，应该怎么做

真正可复现的生态排名需要固定日期和自动抓取脚本，至少同时抓：

1. HF 官方模型 downloads / likes；
2. 衍生模型 lineage（不能用关键词搜索代替）；
3. GitHub releases / contributors / stars；
4. vLLM / SGLang / Transformers 支持状态；
5. Ollama / GGUF 等本地格式覆盖；
6. 云托管 provider 数；
7. 许可证摩擦；
8. 下游论文 / fine-tune 引用。

并且每个快照都应注明日期。

否则“排名”更像一次随手截图，而不是历史数据。

## 九、当前的结构性判断

不做 1—10 排名后，反而能看到更稳定的历史位置：

- **Llama**：开放权重生态的奠基者；
- **Qwen**：全尺寸、多模态、中文与全球下游基座的重要中心，并把 Max 旗舰推进开放；
- **DeepSeek**：效率 / reasoning / 蒸馏与架构议程影响极强；
- **Mistral**：宽松许可和小而强路线的代表；
- **Kimi**：把开放前沿推进 3T 与 long-horizon Agent；
- **Muse Glimmer**：把 2026 讨论重新拉回“本地运行权”；
- **EleutherAI**：即使不再站在性能榜顶端，仍是全栈开放研究传统的重要源头。

这些位置比某一天的 Stars 更不容易过期。
