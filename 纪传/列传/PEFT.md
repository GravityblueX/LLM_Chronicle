# 《PEFT 列传》

> 全量微调一个 175B 参数的模型，需要几百 GB 显存、几十块 GPU、数周时间。PEFT 用了一个朴素但致命的洞察回答这个问题：不必动全部参数。只调几千个、几万个、几十万个——模型的能力大部分还在，但成本降到了一个人、一张卡的尺度。从 Adapter 到 LoRA，参数高效微调把大模型从"大公司才能碰的玩具"变成了"每个人都能改的工具"。

---

## 一、技术背景

2018—2019 年，BERT 和 GPT 先后确立了"预训练 + 微调"的范式。做法很直接：在大规模无标注文本上预训练一个通用模型，然后在下游任务上**更新全部参数**——跑几轮梯度，拿到一个专属于某个任务的模型。

这套范式在 BERT-base（110M）和 BERT-large（340M）的时代是可行的。一张 V100 能跑，一个研究生能调。但到 GPT-2（1.5B，2019 年 2 月）和 T5（11B，2019 年 10 月）出现时，情况变了：全量微调需要的显存已经不是个人研究者能负担的，保存和部署每个任务的独立副本更是一笔隐性成本——如果给 N 个下游任务各存一份完整的模型权重，存储开销随任务数线性膨胀。

更根本的问题在于 BERTology 研究中反复观察到的一个现象：大模型在下游任务上的微调，大部分参数的变化其实很小。语言理解的核心能力在预训练中已经学会，微调只是在表面上做一点适配。既然如此，为什么要动全部参数？

这个问题在 2019 年被 Houlsby 等人用一个简洁的想法回答了：**在预训练模型里插入小模块，冻结原模型，只训练新插入的部分。**[^1]

---

## 二、核心创新

PEFT 的演化脉络清晰：每一步都在"插入什么、插在哪里、怎么训练"三个维度上做选择。从 Adapter 的串行瓶颈到 LoRA 的并行低秩分解，每次迭代都在减少参数量和推理延迟。

### 2.1 Adapter (2019)：在层间插入瓶颈模块

2019 年，Houlsby 等人（Google）提出 Adapter。做法是在 Transformer 的每一层之间插入一个小型神经网络——两层全连接，中间有瓶颈（bottleneck），先降维再升维。预训练模型的所有参数冻结不更新，只训练这些 adapter 模块。[^1]

举个例子：Transformer 的隐藏维度是 768。Adapter 设计成 768 → 64 → 768 的瓶颈结构。可训练参数只占原模型的约 2%，但 GLUE 基准上的表现接近全量微调（差不到 1%）。

Adapter 的优势是参数量极少、存储极省——每个下游任务只需保存一个几百 KB 的 adapter，而不用复制整个模型权重。但它有一个结构性问题：adapter 插在层间，**串行**执行，每层都要多算两次矩阵乘法。这意味着推理时会有额外延迟——在 Transformer 里，每层的计算时间是瓶颈，加 adapter 等于加了一道不能跳过的工序。后来的方法都在尝试绕开这个延迟代价。

### 2.2 Prefix Tuning (2021)：把所有适配压缩成"虚拟前缀"

2021 年，Li 和 Liang 提出 Prefix Tuning。他们不再插入模块，而是在输入序列的前面拼接一组可训练的"虚拟 token"——前缀向量。这些前缀向量不来自任何词表，纯由梯度学习，但会参与后续所有 token 的注意力计算。[^2]

核心直觉：生成任务中，prompt 可以大幅改变模型的输出。与其让人手工设计 prompt，不如让模型自己学—组最优的"前缀"。这组前缀就像一种连续的、可微的 prompt——它不对应任何自然语言词，但激活了模型里做特定任务所需的注意力模式。

Prefix Tuning 的参数量比 Adapter 更少——一组前缀向量通常只有几十到几百个 token 的 embedding，总量不超过原模型参数的 0.1%。在 GPT-2 和 BART 上的实验表明，它在表格到文本、摘要等生成任务上达到了与全量微调持平的效果。

但 Prefix Tuning 也有代价：前缀占用了输入序列的位置，压缩了实际输入可用的上下文窗口。对于上下文窗口本就紧张的长序列任务，这不是小问题。

### 2.3 LoRA (2021)：用低秩矩阵分解替代全量更新

2021 年 6 月，微软的 Hu 等人提出 LoRA（Low-Rank Adaptation），一举成为 PEFT 领域最被广泛采纳的方法。[^3]

LoRA 的洞察基于一个经验观察：大模型在微调时，参数更新矩阵虽然是满秩的，但它的"本质维度"（intrinsic dimension）很低。换句话说，模型微调不是在所有方向上均匀更新——绝大多数变化集中在少数几个关键方向上。

LoRA 的做法因此极其优雅：不做加法，不注入新模块。它在 Transformer 的注意力层（Q、K、V、O 投影矩阵）旁边并联两个低秩矩阵 A 和 B——A 降维（d → r），B 升维（r → d），其中 r 远小于 d（典型值 r=8 或 r=16）。预训练权重冻结，只训练 A 和 B。推理时，BA 的乘积可以直接与原始权重矩阵合并（W' = W + BA），**不增加任何推理延迟**。[^3]

这是 LoRA 相比 Adapter 的关键优势：推理时没有任何额外计算。训练时参数量极小——对 GPT-3 175B，r=16 的 LoRA 可训练参数仅约 120M，不到全量的 0.07%。

LoRA 论文在 GPT-2 和 GPT-3 上的实验涵盖了 NLU 和 NLG 任务，结果显示 LoRA 在参数量比 Adapter 更少的情况下达到了相近或更好的效果。论文还发现，r 可以非常小（r=1 有时也有效），这进一步证实了"模型微调的更新是低秩的"这一核心假设。

### 2.4 QLoRA (2023)：把 LoRA 送进 4-bit 世界

2023 年，Dettmers 等人提出 QLoRA。它的贡献不在算法创新，而在**让 LoRA 在量化模型上也能跑**。[^4]

当时 4-bit 量化已经能把 65B 的 Llama 塞进 48GB 显存，但量化后的模型再微调，精度损失不可控。QLoRA 用三个技术把量化模型的微调稳住了：NF4 量化格式（专门为神经网络权重分布设计的 4-bit 格式）、双重量化（对量化常数再做一次量化）、分页优化器（把 optimizer state 暂时溢出到 CPU 内存）。

结果：**65B 的 Llama 在单张 48GB GPU 上可以微调**。QLoRA 把 PEFT 的硬件门槛从一个 GPU 集群降到了一张消费级显卡。这之后，"在自己电脑上微调大模型"才真正成为可能——不是算法上可做，是硬件上可做。

### 2.5 后继变体与竞争方法

LoRA 之后，社区涌现了大量改进：

- **IA³ (2022)**：Liu 等人提出"通过可学习向量缩放激活值"——比 LoRA 更轻量，每个任务只需几个向量参数，在 T0 基准上超越全量微调。[^5]
- **AdaLoRA (2023)**：Zhang 等人让 LoRA 的秩 r 在不同层之间自适应分配。关键层多放秩，不关键层少放——避免"所有层给相同 r"的浪费。[^6]
- **DoRA (2024)**：Liu 等人把权重更新分解为"方向"和"幅度"两部分——方向用 LoRA 更新，幅度用可学习向量缩放。在较小数据量的微调中效果显著优于标准 LoRA。[^7]
- **VeRA (2024)**：Kopiczko 等人把 LoRA 的两个低秩矩阵 A 和 B 进一步冻结为随机初始化，只训练可学习的缩放向量。可训练参数降至原来的几十分之一，但效果几乎不打折。[^8]

### 2.6 关键数据

| 方法 | 时间 | 可训练参数占比（以 GPT-3 175B 为基准） | 推理延迟 | 核心出处 |

## 三、影响与后继

### 3.1 对研究和开源生态的冲击

LoRA 出现之前，微调大模型是"有钱人的游戏"。一篇论文如果要在 GPT-3 上做微调实验，要先解决算力问题——要么有 OpenAI 的 API 访问权限，要么有几百块 GPU。LoRA 和 QLoRA 把这道墙拆了。

2023 年，开源 LLM 的微调生态爆炸性增长。Alpaca、Vicuna、UltraChat、Orca——这些基于 Llama（自 LLaMA 权重泄露后）的微调模型，绝大多数用的是 LoRA/QLoRA。不是因为他们选了这个方法——是因为除此外别无他法。一张 4090，加载 4-bit 量化的 7B Llama，加上 LoRA，一个下午就能跑出能用的 chat 模型。这个门槛的降低直接催生了 2023 年的"全民微调"浪潮。

### 3.2 从"模型分发"到"Adapter 分发"

PEFT 改变了大模型的部署逻辑。在 Adapter 出现之前，分发模型意味着传输整个权重文件——一个 7B 的模型就要 14GB 的磁盘空间。PEFT 把这个变成了"发基础模型一次，后续只发几十 MB 的 LoRA 权重"。

这个概念在 2024 年被 Civitai（Stable Diffusion 的模型社区）推到了极致：数十万个 LoRA 模型——每个角色、每种画风、每个场景——都只占用几百 MB 甚至几十 MB。用户下载一个基础模型，叠加十几个 LoRA，生成混合风格。这是 PEFT 最接近"App Store"时刻的产物：大模型是操作系统，LoRA 是上面的应用。

### 3.3 在工业界的采纳

到 2025-2026 年，LoRA 已成为大模型微调的事实标准：

- **HuggingFace PEFT 库**：集成了 LoRA、QLoRA、IA³、Prefix Tuning 等主流方法，截至 2025 年累计下载数千万次。
- **HuggingFace、vLLM、Ollama** 等推理框架原生支持 LoRA adapter 的动态加载和热插拔。
- **大模型平台化**：OpenAI（GPT 微调 API）、Anthropic、阿里云等平台的微调服务底层大多迁移到了 LoRA 或其变体。LoRA 的可合并、可插拔特性天然适配多租户的推理架构——每个用户的 LoRA 权重独立存储，推理时动态挂载到共享的基础模型上。

### 3.4 衰落或被吸收

PEFT 没有被衰落，它被吸收了。

到 2026 年，"微调大模型"这个词的含义已经发生了语义变迁。如果没有特别说明"全量微调"（full fine-tuning），默认就是指某种 PEFT 方法——绝大多数情况下是 LoRA。PEFT 从"一种省钱的替代方案"变成了"默认做法"。

这和注意力机制的命运一样：当一项技术从论文标题沉入默认配置，它其实已经赢了。PEFT 不再是一个需要解释的"新技术"，而是大模型工程中的一个标准步骤——就像 Batch Normalization 之于 CNN，Residual Connection 之于深度网络。

## 评曰

PEFT 的核心贡献不是"让微调更快"——是**让大模型变成每个人都能修改的东西**。

在 LoRA 之前，大模型像一个黑箱：你可以跟它对话，可以给它 prompt，但你不能真正"拥有"它——因为改不了。全量微调 175B 的成本门——算力、时间、存储——把模型的所有权锁在了大公司和极少数研究机构手里。LoRA 把这个锁打开了。一张消费级显卡、几 MB 的权重文件、一个下午的训练时间——就能把一个通用模型变成你自己的模型。

这个改变的深度超出了技术层面。Civitai 上数十万个 LoRA 模型、"花五百美元买个微调的 7B 模型"的小生意、HuggingFace 上以 LoRA 形式分享的社区微调——这些不是 PEFT 的论文预测过的，但它们是一张显卡就能改大模型这件事的必然结果。当工具的持有成本降到足够低，工具就变成了表达。

从 Adapter 到 Prefix Tuning 到 LoRA 到 QLoRA，PEFT 的每一步都在做减法：减参数、减延迟、减硬件。这条线的尽头不是某个更聪明的算法，而是一个已成常识的事实——你不需要碰全部参数才能控制一个模型。这句朴实的话，让 2023 年之后的 AI 故事从"大公司之间的军备竞赛"变成了"每个人的创作自由"。
