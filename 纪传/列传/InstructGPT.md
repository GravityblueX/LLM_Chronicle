# 《InstructGPT 列传》

> InstructGPT 不是最大的模型，也不是最聪明的模型。它是第一个学会了"听话"的模型。1.3B 参数的 InstructGPT 在人类评估中优于 175B 参数的 GPT-3——这句话改变了整个行业对"好模型"的定义。没有 InstructGPT，就没有 ChatGPT；没有 ChatGPT，大模型可能至今还停留在 API 和论文里。

---

## 一、技术背景

GPT-3（2020-06）展示了大规模语言模型的涌现能力：给 10-100 个示例，它就能做翻译、算术、编程。但 GPT-3 有一个根本性的产品缺陷：**它不知道用户想要什么**。

用户让 GPT-3 写一封邮件，它可能继续补全提示词文本；用户问一个危险问题，它可能照答不误；用户要求事实性回答，它可能编造得非常流畅。GPT-3 的问题不在于能力不足——而在于它在训练时学到的目标（预测下一个 token）和用户使用时的期望（按照指令完成任务）之间存在一道裂缝。

在 InstructGPT 之前，解决这个问题的主要方法是**监督微调（SFT）**：让人类标注员为每个提示词写出理想回答，然后用这些样本训练模型。这个方法有效，但扩展性差——要覆盖所有可能的提示词和场景，需要的标注数据量大到不切实际。而且很多时候，人类说不清"最佳回答"该怎么写，但能轻松判断"回答 A 比回答 B 好"。[^1]

RLHF（Reinforcement Learning from Human Feedback）抓住的就是这个洞察：**不需要标准答案，只需要排序**。这个想法最早在 OpenAI 2017 年的一项工作中被验证——用人类偏好训练强化学习智能体完成游戏和机器人任务。[^2] InstructGPT 的贡献是把这套方法从游戏和机器人迁移到了语言模型上——并证明了它在工业上可行。

---

## 二、核心创新

### 2.1 三步法：SFT → 奖励模型 → PPO

InstructGPT 的训练流程分三步，这个三步法后来成为整个大模型后训练的标准范式：[^1]

**第一步：监督微调（SFT）**。从 GPT-3 的 API 用户提示词中采样，由标注员写出"理想回答"，用这些示范数据微调 GPT-3。这一步的目的是给模型一个初始的"指令遵循"能力——让它至少知道"用户说的不是需要补全的文本，而是需要回答的问题"。

**第二步：训练奖励模型（Reward Model）**。对同一个提示词，让 SFT 模型生成多个回答（通常 4-9 个），由标注员对这些回答进行排序——"A 比 B 好，B 比 C 好"。用这些排序数据训练一个奖励模型，让它学会给任意回答打一个分数，预测"人类会觉得这个回答有多好"。

**第三步：PPO 强化学习优化**。用奖励模型的分数作为奖励信号，通过 PPO（Proximal Policy Optimization）算法优化语言模型——让模型学会生成更高分数的回答。为了防止模型在优化过程中"走偏"（只追求高分而丢失语言能力），训练时加入了一个 KL 散度惩罚项，约束优化后的模型不要偏离 SFT 模型太远。

这个三步法的精妙之处在于：**它把"人类觉得好"这个模糊的概念，变成了一个可训练的数值信号**。标注员不需要写完美答案，只需要比较。奖励模型再把这些局部比较推广到更广泛的提示词上。PPO 再把奖励信号反向传播回语言模型的参数里。

### 2.2 小模型打赢大模型

InstructGPT 最具冲击力的实验结果是：**1.3B 参数的 InstructGPT 在人工评估中优于 175B 参数的 GPT-3**。[^1]

这个结果的意义是深远的——它第一次明确证明了：**模型"好不好用"不只取决于参数规模**。一个 1.3B 的模型经过对齐训练后，在"遵循指令""有帮助""减少有害输出"三个维度上全面超越了 100 倍大的未经对齐模型。

这个发现直接改变了行业对"好模型"的评价标准。2020 年，"好模型"意味着"在 benchmark 上分数高"；2022 年之后，"好模型"意味着"在真实使用中让人满意"。InstructGPT 把"用户体验"引入了模型评估的核心——这对一个长期由 benchmark 驱动的领域来说，是一次范式转变。

### 2.3 关键数据

| 指标 | 数值 | 说明 |
|------|------|------|
| 基座模型 | GPT-3（175B） | InstructGPT 基于 GPT-3 的不同规模版本[^1] |
| 最小对齐版本 | 1.3B | 在人工评估中优于 175B GPT-3[^1] |
| 标注员数量 | 约 40 人 | 来自 Upwork 和 OpenAI 内部标注团队[^1] |

## 三、影响与后继

### 3.1 ChatGPT：InstructGPT 的产品化

InstructGPT 是技术论文，ChatGPT 是产品。二者之间的关系很简单：**ChatGPT 就是 InstructGPT 方法应用到 GPT-3.5 上的结果**。

2022 年 11 月 30 日，OpenAI 发布 ChatGPT——把经过 SFT + RLHF 对齐的 GPT-3.5 放进聊天界面。五天百万用户，两个月一亿月活。ChatGPT 没有发明 RLHF，也没有发明聊天界面——它只是把 InstructGPT 的方法和一个简单的 UI 结合在一起，结果创造了一个全新的产品品类。

从技术角度看，ChatGPT 相比 InstructGPT 的改进是渐进的——更好的基座模型（GPT-3.5 vs GPT-3）、更多的对话数据、更精细的安全边界。但从产品角度看，它是质变：当 RLHF 对齐的大模型被放进一个普通人就能使用的聊天框时，"AI"从一个专业术语变成了大众动词。

（详见《GPT 世家》《RLHF 列传》）

### 3.2 "预训练 → SFT → RLHF"成为工业标准

InstructGPT 之后，"预训练 → SFT → RLHF"三步法成为所有闭源大模型的默认训练流水线。Claude 使用 Constitutional AI 变体（用 AI 反馈替代部分人类反馈）；Gemini 使用自研的偏好优化方法；Llama-Chat 使用 DPO（Direct Preference Optimization）替代 PPO——但基本框架始终是 InstructGPT 确立的那三步。

这个标准化的影响超出了技术层面。它带来了新的组织需求：公司需要标注团队、红队测试、政策文档、拒答规则、评估集和安全报告。**对齐不再是研究员在论文里写的价值观，而是产品发布前必须过的一整套流程**。InstructGPT 把"对齐"从学术概念变成了工业基础设施。

### 3.3 对 RLHF 的后续挑战

InstructGPT 确立的 RLHF 范式不是没有争议。

Anthropic 的 **Constitutional AI**（2022-12）提出了第一次系统性挑战：用"宪法原则 + AI 自我批评"替代部分人类标注，降低标注成本和主观偏见。[^4]

**DPO**（2023-05）绕开了显式奖励模型和 PPO，直接用偏好数据优化语言模型——训练更简单，工程复杂度更低。[^5]

**DeepSeek-R1**（2025-01）提出了更激烈的挑战：对推理能力来说，最好的奖励信号不是"人类觉得好"，而是"答案是否正确"。R1-Zero 跳过 SFT，直接用规则奖励和 GRPO 训练推理能力——证明了 RLHF 不是唯一的后训练路径。[^6]

这些挑战共同指向一个结论：InstructGPT 的三步法是起点，不是终点。它确立了"后训练"的必要性，但后来者在"用什么信号""如何优化""是否需要人类偏好"等问题上找到了不同的答案。

### 3.4 衰落或被吸收

InstructGPT 作为独立的产品早已从 OpenAI 的 API 中退役——被 ChatGPT（GPT-3.5/4）取代。但它确立的方法论——SFT + 偏好优化——至今仍是所有大模型后训练的核心框架。

它最辉煌的遗产是 ChatGPT。它最重要的思想贡献是：**模型好不好用，不只取决于它有多大，还取决于它多"听话"**。这句话在 2022 年之前是少数人的直觉，在 2022 年之后成了全行业的常识。

## 评曰

InstructGPT 的贡献，是让大模型学会了在人类面前收住自己。

GPT-3 证明了规模可以涌现出能力，但没有给模型分寸——它不知道什么该说、什么不该说、什么语气让人信任。InstructGPT 用偏好排序补上了这道分寸。1.3B 的 InstructGPT 打赢 175B 的 GPT-3，不是因为 1.3B 的模型"更聪明"——而是因为它更懂得用户想要什么。

这个发现的深远影响在于：它把"模型能力"从一个一维的标尺（benchmark 分数）变成了二维的（能力 × 对齐）。一个能力很高但不对齐的模型，用户体验可能不如一个能力较低但对齐良好的模型。这个洞察改变了整个行业的资源分配逻辑——从"花所有钱堆预训练"到"预训练和后训练同等重要"。

InstructGPT 的技术细节——SFT、奖励模型、PPO——很快就被超越和替代。但它的核心洞察——"人类偏好是可训练的信号"——至今仍是所有大模型后训练的基石。从 RLHF 到 DPO 到 RLAIF 到规则奖励，后来者改变的是方法，不变的是 InstructGPT 首先证明的那个道理：大模型需要学会听话，才能变得有用。
