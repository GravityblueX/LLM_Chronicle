# The Agent Era

> From AutoGPT's one million stars to Claude Computer Use's mouse and keyboard, large language models spent two years proving one thing: the gap between making a model "converse well" and making a model "act effectively" is not about technical capability — it is about engineering patience, trust boundaries, and ecosystem maturity.

## I. AutoGPT: The overpromise of the Agent concept (2023)

On **2023-03-30**, an open-source project called AutoGPT appeared on GitHub. What it did was simple: give GPT-4 a set of tools — web browsing, file read/write, code execution — and let the model plan tasks autonomously, execute them, and decide the next step. Within two weeks, it became one of the fastest-growing projects in GitHub history, surpassing 100,000 stars.[^1]

AutoGPT's explosion was not because it actually worked well. In fact, most users quickly discovered that it would get stuck in loops, lose context, make absurd decisions, and burn through vast numbers of tokens accomplishing nothing.[^2] A typical failure case: a user asked AutoGPT to "research and write a blog post about quantum computing." It would bounce between search engines and the file system, consuming hundreds of API calls, ultimately producing a post of abysmal quality — far inferior to simply asking GPT-4 directly.

But the explosion itself revealed something: **there was enormous, unmet demand in the market for "AI that doesn't just chat, but does things for you."** AutoGPT's GitHub star count (breaking 100,000 in a single week) was not an endorsement of code quality — it was a vote for the Agent concept. The public was saying with their stars: "We want more than chatbots."

AutoGPT's technical approach — using a natural language loop to drive an LLM through repeated tool calls — quickly exposed its naivety. Large language models are not universal planners. They are already strong enough at single-step reasoning, but have virtually no reliable capability in multi-step planning, state management, error recovery, or long-term memory. Wrapping a chatbot into an autonomous agent is like sending a talented translator to serve as a general — the translator is not unintelligent; their skill set simply was not designed for this task.

By the end of 2023, AutoGPT had largely faded. Its contribution was not technical implementation, but **conceptual proof**: the word "Agent" moved from academic jargon into public consciousness. Every Agent product that followed — whether Devin, Cursor, Claude Code, or OpenAI's Operator — lives in the expectation and shadow that AutoGPT planted.

## II. Function calling: Agent infrastructure quietly laid (2023)

The year 2023 was when Agent infrastructure was laid.

After AutoGPT receded, what truly moved Agent from "demo" to "engineering" was Function Calling.

On **2023-06-13**, OpenAI added Function Calling capabilities to the GPT-3.5 and GPT-4 APIs. The model no longer only output text — it could output structured JSON, precisely selecting which function to call and what parameters to pass.[^3] This appeared to be a minor feature, but it was the foundation of Agent capability.

Before Function Calling, making a model invoke tools required extensive prompt engineering. You had to describe all available tools in the system prompt and hope the model would output its call intent in the correct format — format errors, hallucinated parameters, and wrong tool selections were the norm. Function Calling transformed this from a "prompting trick" into a "protocol": models learned during training how to correctly express tool-call intent. This seemingly small shift was a watershed moment for Agent engineering — from "relying on luck to get the model to do it right" to "relying on protocol to guarantee it." From then on, tool calling was no longer the Agent bottleneck — the bottleneck shifted upward: to planning, state management, and error recovery.

Anthropic added similar Tool Use capabilities to the Claude 3 series at the end of 2023, and Google implemented function calling in Gemini. By 2024, virtually every major model provider treated "the model can call tools" as a baseline capability.[^4]

The historical significance of Function Calling lies in this: it decomposed the Agent from a "monolithic system" into a composable architecture of "model + protocol + tools." AutoGPT had tried to let the model do everything — planning, execution, judgment. Post-Function Calling, Agent systems took a different path: the model is responsible only for decision-making and dispatch; execution is delegated to specialized tools. This was an engineering concession — and a practical advance.

## III. Claude Computer Use: Agent enters the operating system (2024)

On **2024-10-22**, Anthropic released a feature called Computer Use. Claude was no longer limited to calling APIs or tools — it could operate a computer like a human: viewing the screen, moving the mouse, clicking buttons, typing text, reading on-screen content.[^5]

This was not the first attempt to "let AI operate a computer." Various RPA (robotic process automation) tools had existed before, and AutoGPT had experimented with browsers. But Computer Use was different because a mainstream model provider formalized "GUI interaction" as an official API capability. The model receives screenshots as input and outputs mouse and keyboard actions — a completely different Agent paradigm from API calls.

The breakthrough of Computer Use was that it bypassed the "API barrier." Not all software has APIs, not all APIs have documentation, and not all documentation is accurate. But all software has a GUI. An Agent capable of operating GUIs could, in theory, use any software — including legacy systems with no APIs, no plugins, and no developer integrations. This was profoundly significant for enterprise automation scenarios.

But Computer Use also exposed the most fundamental vulnerability of Agents. GUI operations are fragile: changes in screen resolution, UI layout updates, popup obstructions, network latency — any tiny variable can cause the Agent's operation to fail.[^6] The deeper problem is that Agents lack "semantic understanding" when operating GUIs — they see pixels, not intent. They know "there is a button here," but do not always know "what this button means in this context."

This is the classic paradox of the Agent era: **the more general the interface, the more fragile it is; the more specialized the interface, the more reliable.** API calls are precise but narrow in coverage; GUI interaction is broad but unreliable. Real Agent products must find a balance between the two. The MCP protocol (see §VIII) attempts to find a third path in this paradox: neither relying on GUIs nor fixed APIs, but using a standardized protocol layer to establish reliable yet flexible connections between Agents and tools. Whether this path works depends on the speed of MCP ecosystem growth.

## IV. Claude Code's capability leap: From autocomplete to autonomous refactoring

In **January 2025**, Anthropic released Claude Code — a coding Agent running in the terminal.[^7] Before this, the mainstream forms of AI programming assistance were "in-editor autocomplete" (Copilot) and "conversational Q&A" (ChatGPT). Claude Code took a different path: it is not an editor plugin but an independent Agent running in the terminal that can directly read and write files, execute commands, and operate Git repositories.

The true breakthrough of Claude Code was a fundamental shift in work mode: from "you ask one question, it gives one answer" to "you assign a task, and it works independently for hours." A user describes a task objective — such as "migrate this project from React 15 to React 18" or "fix all TypeScript type errors" — and Claude Code will autonomously plan steps, read files, modify code, run tests, adjust its approach based on errors, and continue working until completion or until it encounters a problem it cannot solve.

By mid-2025, Claude Code could independently complete large-scale code refactoring, cross-file migrations, complex bug fixes, and similar tasks. Cases reported by the developer community include: refactoring hundreds of files in a single session, working continuously for hours to complete migrations from one framework to another, automatically running tests and adjusting strategies based on failure results.[^8] Some developers reported that Claude Code completed refactoring tasks in a single session that would have taken humans several days — and the quality was not low.

This capability leap raised new trust problems. When Claude Code refactored half a codebase, human developers could not review every change line by line the way they would review a colleague's Pull Request. The output volume exceeded human review capacity. This produced a paradox: **the more capable the Agent, the harder it is for humans to verify whether it did the job correctly.**

In coding scenarios, compilers and test suites provide partial automated verification. But passing compilation and passing tests does not equal good code quality — an Agent might write code that runs but has terrible maintainability, just as a student might pass an exam without truly understanding the material. More dimensions of code quality — readability, maintainability, naming conventions, architectural soundness — cannot be covered by automated testing and still require human judgment. This means that even in the most favorable environment (with compilers and test suites), Agents still have a layer of quality that requires human oversight.

Another notable feature of Claude Code is its "work log" — it outputs in real time what it is doing, why, and what problems it encountered. This provides a degree of observability — humans can follow the Agent's reasoning process rather than just seeing the final output. But "observable" is not the same as "comprehensible" — when an Agent modifies 200 files in three hours, even the work log exceeds human reading capacity.

Claude Code's success also redefined what "programming assistant" means. GitHub Copilot (first released **2021-06**) was originally "autocomplete a line of code" — the human writes most of the code, AI fills in a small portion. Cursor (**2023-03**) expanded to "conversational programming within an editor" — the human describes intent, AI generates code snippets. Claude Code advanced to "autonomously completing complex tasks with humans only setting goals and reviewing results" — the human defines the task, AI handles execution. This is not incremental improvement — it is a qualitative leap from "tool" to "collaborator." The human role shifts from "writing code" to "defining intent, reviewing results, and bearing responsibility."

This role shift has profound implications for software engineering. When a senior engineer uses Claude Code to complete in two hours a refactoring task that would have taken two days, productivity indeed increases. But it also means: the "write foundational code" tasks traditionally assigned to junior engineers are being consumed by Agents. The core value of junior engineers — accumulating experience and intuition through writing large volumes of code — is being bypassed. Agents are not just changing "how code is written"; they are changing "who writes code" and "what skills code writers need." The programmer's skill stack is migrating from "writing code" toward "reviewing code, defining requirements, and managing Agents."

## V. Devin's marketing vs. reality: The narrative bet behind a $2B valuation

On **2024-03-12**, Cognition Labs released Devin, positioning it as "the world's first AI software engineer" — not a programming assistant, not a code completion tool, but an Agent capable of independently completing the entire workflow from requirements analysis to coding, testing, and deployment.[^9] Cognition Labs was founded by Scott Wu, and team members largely came from competitive programming backgrounds. Devin's name itself hints at its positioning — not Copilot (a co-pilot), but Devin (an independent engineer).

Devin's launch demo showcased impressive capabilities: it could understand natural language requirements, formulate development plans, write code, run tests, debug errors, and even deploy applications. In the demo, Devin completed multiple real Upwork freelance tasks. But independent testers quickly found that Devin's actual capabilities fell far short of the demo — frequent failures on many simple tasks, limited planning ability, and unreliable error recovery.[^10]

Despite this, Cognition Labs secured a valuation of approximately $2 billion.[^11] This valuation was not based on current product capabilities, but on a narrative bet: **the ultimate form of AI programming is not "assisting humans" but "replacing humans."** Cursor and Claude Code position themselves as tools that augment human productivity — the programmer is still there, just more efficient. Devin positions itself as replacing the programmer entirely — a programmer's role can be taken over by an Agent. The market's enthusiastic response to the latter reveals that what investors and business owners truly want is not "making people more efficient" but "not needing people."

Devin and Claude Code represent two philosophies of Agent development. Claude Code's philosophy is "augmentation" — humans remain the primary actors, Agents are capability amplifiers. Devin's philosophy is "replacement" — Agents are the primary actors, humans are responsible only for review and acceptance. The former is more readily accepted by programmers; the latter is more popular with investors and management. The tension between these two philosophies will define human-machine relationships in the Agent era — are Agents programmers' tools, or their competitors?

Devin's case exposed a structural risk of the Agent era: **the chasm between demo and reality.** AutoGPT's demo made people think the Agent era had arrived (it hadn't); Devin's demo made people think AI engineers were already viable (they still required extensive human intervention). The valuation of Agent products is heavily dependent on narrative — and narrative can run far ahead of technology.

This narrative-reality chasm did not narrow in 2025. OpenAI Operator's demo showed Agents automatically completing online tasks, but early user feedback indicated frequent errors on complex web pages. Google Project Mariner's demo was impressive, but it had not yet undergone large-scale public testing. The state of the Agent industry in 2025 can be summarized as: **everyone is proving Agents work in demos, but few are proving Agents are reliable in production environments.** This gap is becoming the greatest uncertainty of the Agent era.

Notably, the narrative-reality chasm manifests differently in capital markets versus user markets. In capital markets, narrative runs ahead — Devin's $2B valuation and the high funding rounds of various Agent startups are all based on the narrative that "Agents are about to change everything." In user markets, reality lags behind — most enterprise users remain in "watching" or "small-scale pilot" mode regarding Agents, with cases of truly embedding Agents into core production workflows being extremely rare. When the gap between capital narrative and user reality widens to a certain point, a market correction arrives — between 2024 and 2025, several Agent startups had already shut down or pivoted.

## VI. Google's "agentic era" declaration

On **2024-12-11**, Google DeepMind released Gemini 2.0 Flash. Unlike previous model releases, Google CEO Sundar Pichai and DeepMind lead Demis Hassabis explicitly positioned Gemini 2.0 as the foundation for entering the "agentic era" — AI that no longer merely answers questions but can act on behalf of users.[^12] Pichai wrote in the release blog: "If 2023 was the year AI awakened, then 2025 will be the year Agents awaken." This statement marked the world's largest internet company officially designating Agents as the strategic direction for the next phase.

On the same day, Google released Project Mariner — an Agent running inside the Chrome browser that can understand web content, perform operations, and complete tasks.[^13] Mariner's technical approach is similar to Anthropic's Computer Use (viewing the screen, operating the GUI), but the integration differs: Computer Use is an API capability requiring developer invocation; Mariner is a browser extension aimed directly at end users.

Google's Agent strategy has deeper layers. Gemini 2.0 Flash itself is a multimodal model — capable of processing text, image, audio, and video inputs while supporting real-time interaction. This means Agents are no longer limited to "reading text" — they can see screens, hear speech, and understand video. Google Search's advantage lies in indexing the most comprehensive information on the internet; Gemini's multimodal capability lies in understanding this information in all its forms; the Agent's value lies in acting on behalf of users based on this information. The three together form Google's most complete value chain in the Agent era.

Google's "agentic era" declaration marked an important turning point: **all three major AI labs (OpenAI, Anthropic, Google) explicitly designated Agents as their core direction for the next phase between 2024 and 2025.** OpenAI has Operator (**2025-01**), Anthropic has Computer Use (**2024-10**), Google has Project Mariner (**2024-12**). The three companies' paths differ — OpenAI builds standalone products, Anthropic builds API capabilities, Google builds browser integrations — but the direction is the same: **from dialogue to action, from answering questions to doing things for you.**

But Google's Agent path faces a unique challenge. Google's core business is search advertising — if Agents directly complete tasks for users (booking flights, purchasing goods, filling out forms), users don't need to click ad links in search results. The more successful the Agent, the greater the threat to Google's existing business model. This is Google's "innovator's dilemma" in the Agent era: you need to cannibalize your revenue source to ride the next wave. In 2024, Google's search advertising revenue was approximately $198 billion, accounting for roughly 57% of Alphabet's total revenue. If Agents replace the "search-click-convert" chain, this revenue base erodes. Google must find a delicate balance between Agent capability and advertising protection — a balance that may never be comfortable.

Google's advantage lies in distribution channels. The Chrome browser has over 3 billion users, and the Android operating system covers the majority of smartphones globally. If Google can deeply integrate Agent capabilities into Chrome and Android, it possesses an Agent distribution channel larger than any competitor's. Technical capability can be caught up with, but a distribution channel of 3 billion users cannot be replicated. Google's strategy may be: using Gemini's model capability as the foundation, Chrome's browser as the Agent's runtime environment, and Google Search's information index as the Agent's knowledge base. The three together form a complete chain from "understanding the world" to "acting on behalf of users."

## VII. Agent failure modes: Why most Agent projects failed

Between 2023 and 2025, a massive number of Agent projects emerged — and a massive number failed. From AutoGPT to various enterprise Agent solutions, failure rates far exceeded success rates. Understanding Agent failure modes is more valuable than understanding success stories — because failure modes reveal structural limitations of the current technological stage, rather than defects of individual products.

**Insufficient planning capability** is the first hard barrier. LLMs are already strong enough at single-step reasoning but remain unreliable at multi-step planning. Research shows that even the strongest models experience significant success rate drops on tasks requiring more than 5 reasoning steps.[^14] This is not about models being "not smart enough" — it reflects fundamental limitations of the current Transformer architecture in long-horizon planning. It excels at predicting "the next token" but struggles with reasoning about "the dependencies among each of the next 20 steps." AutoGPT attempted to circumvent this limitation by "having the model repeatedly think about the next step" — but repeated thinking consumes vast numbers of tokens without guaranteeing convergence to the correct solution. A more effective engineering approach is to decompose complex tasks into simple subtasks, each executed independently — but this decomposition itself requires planning ability, creating a circular dependency.

**Hallucination accumulation** is the second hard barrier. In multi-step tasks, each step can introduce small errors. If single-step accuracy is 95%, after 10 steps overall accuracy drops to approximately 60% — after 20 steps, to roughly 36%. This is a multiplicative effect; each step's reliability is amplified by subsequent steps. AutoGPT's failures on complex tasks were largely due to error accumulation within loops — small errors at each step caused subsequent inputs to drift further from the correct direction, ultimately resulting in complete failure.

In coding scenarios, hallucination accumulation manifests as: the Agent misreads a function signature at the first step, and all subsequent modifications based on that understanding go wrong. The compiler can catch some errors, but not semantic ones — a function call that is syntactically correct but logically wrong will not trigger a compiler error.

**The human-in-the-loop dilemma.** One proposed solution is to insert human checkpoints into Agent workflows — the Agent pauses at critical decision points and requests human confirmation. This improves reliability but undermines the premise of "autonomy" — if an Agent needs human confirmation every three steps, it is not an "autonomous Agent" but an "assistant requiring frequent approval." The more practical problem: the cognitive cost for humans to review an Agent's intermediate outputs may not be lower than the cost of humans completing the task themselves. When review costs approach execution costs, the Agent's productivity advantage is nullified.

**Real-world constraints on trust boundaries.** In scenarios like credit assessment, medical decision-making, and legal documents, the consequences of Agent errors are irreversible. If a coding Agent writes incorrect code, CI can catch it; if a medical Agent makes a wrong diagnosis, who catches it? The trust threshold in these scenarios is extremely high, and Agent reliability is far from reaching it.

The deeper problem is: **Agents do not have a "sorry" option for their errors.** When an autonomous driving system errs, the consequence may be physical harm. When a financial Agent executes an incorrect trade, the consequence may be irreversible capital loss. In these high-risk scenarios, "rollback after the fact" is not always feasible. This means that deploying Agents in high-risk scenarios must come with extremely strict permission controls — Agents can only execute "reversible" operations. But this limits the Agent's scope of autonomy — how different is an Agent that can only execute "reversible operations" from an "assistant that requires human confirmation at every step"?

**The cost-value balance.** Agents may be more expensive than humans on simple tasks (API call costs exceeding labor costs) and potentially cheaper on complex tasks (saving significant time). But in the middle ground — tasks that are "neither simple nor complex" — the cost-value calculation is blurry. The enterprise decision to deploy Agents ultimately depends on whether they can generate positive ROI on "enough" tasks — and this requires large-scale empirical data that is currently extremely scarce.

**Context window limitations** are also an underestimated cause of failure. When an Agent executes long-horizon tasks, it needs to maintain understanding of the entire task state. But LLM context windows are finite — even the latest 100K+ window models lose early information when processing extremely long task histories. AutoGPT's loop problems were partly due to context overflow causing the Agent to forget solutions it had already tried.

**Cost issues** also constrain actual Agent deployment. A single Claude Code session processing hundreds of files for refactoring may consume tens of dollars in API fees. When Agents need to repeatedly attempt and roll back, costs inflate further. For enterprises, the cost of an Agent completing a task may exceed the cost of hiring a junior human engineer — unless the task is complex enough and the timeline urgent enough.

These failure modes point to a common conclusion: **the bottleneck of Agents is not model capability, but system reliability.** The most successful Agent products of 2025 — Cursor, Claude Code — succeeded precisely because they restricted the Agent's scope of action to a safe sandbox with compilers, test frameworks, and version control. Within this sandbox, errors can be automatically detected and rolled back. Outside this sandbox — operating GUIs, browsing the web, interacting with the real world — Agent reliability drops precipitously. The real world has no `git revert`.

## VIII. MCP and the Agent ecosystem: Protocol competition is platform competition

On **2024-11-25**, Anthropic released the Model Context Protocol (MCP), an open protocol for standardizing connections between LLMs and external tools and data sources.[^15] MCP's design goal is to allow any tool — databases, file systems, APIs, internal systems — to be callable by Agents through a unified protocol.

MCP's emergence marked a shift in Agent ecosystem competition from "whose model is stronger" to "whose protocol is more universal." This has structural similarities to the early internet's browser wars and the mobile internet's OS wars: when underlying capabilities converge, platform victory depends on ecosystem richness. What MCP does, by analogy, is like how USB standardized device connections — before USB, every peripheral had its own interface; after USB, any peripheral could plug and play. MCP attempts to do the same for Agents: let any tool be "plug-and-play" callable by Agents.

By 2025, MCP had achieved considerable community adoption — a large number of developers had written MCP Servers for various services. But the Agent protocol war was far from over. OpenAI released the Agents SDK and enhanced versions of function calling, Google launched its own Agent framework, and Microsoft deeply integrated the Copilot ecosystem with Microsoft Graph.[^16]

The competition among these protocols is essentially a contest for the position of "Agent operating system." Whoever defines the standard interface between Agents and tools controls the entry point of the Agent ecosystem. This follows the same historical logic as the Android vs. iOS struggle, the HTTP vs. Gopher contest: **the victory of a technical standard ultimately depends on ecosystem adoption speed, not the technical elegance of the protocol itself.**

MCP's historical significance lies in this: it is the first open protocol promoted by a mainstream AI company aimed at standardizing Agent-tool connections. Before MCP, every Agent framework had its own tool-calling approach — LangChain had its Tool interface, AutoGPT had its plugin system, and every company's API had its own function calling format. MCP attempted to unify these fragmented interfaces so that a tool only needs to write one MCP Server to be callable by any MCP-supporting Agent. The benefits of such standardization are enormous — it reduces integration costs for tool developers and for Agent developers alike. But the success of standardization does not depend on technical design — it depends on adoption speed. Whether MCP becomes the USB of Agents depends on how many tool providers are willing to write MCP Servers.

## IX. From tools to colleagues: The real threshold of the Agent era (2025—)

By 2025, Agents had moved from demos to products, and from products to ecosystems. But whether the "Agent era" has arrived depends on your definition of "arrived."

In 2025, Agent products began to present two clear directions:

**Coding Agents** were the first successfully deployed scenario. Cursor, GitHub Copilot, Claude Code, Windsurf, Devin — these products proved one thing: code is the most natural working environment for Agents. Code can be compiler-checked, test-verified, and diff-reviewed. This means Agent output can be automatically verified without line-by-line human review.[^17] When errors can be automatically detected, the Agent reliability problem shifts from "absolutely cannot fail" to "acceptable error rate." The coding Agent market in 2025 was fiercely competitive — Cursor captured developer mindshare through editor integration, Claude Code built its technical reputation through prolonged autonomous work, and GitHub Copilot occupied distribution channels through the Microsoft-GitHub ecosystem. Devin took a differentiated approach — positioning not as an "assistant" but as an "engineer" — but its actual market performance remains to be verified.

**General-purpose Agents** remain in early stages. OpenAI's Operator (released **2025-01**) lets users browse the web and complete online tasks through Agents. Google's Project Mariner embeds Agent capabilities in Chrome.[^18] But the core problem facing general-purpose Agents remains unsolved: they are still unreliable on complex, multi-step tasks requiring judgment. When a coding Agent writes bad code, CI tells you; when a general-purpose Agent books the wrong flight, who tells you?

General-purpose Agents also face a problem that coding Agents do not: **environmental change.** Code repositories are relatively stable — API documentation and compiler rules do not change daily. But web interfaces change frequently — button positions, form fields, and popup logic can update at any time. GUI Agents need to be robust to such changes — but current Agents have extremely limited adaptability to environmental change. An Agent that successfully books a flight today may completely fail tomorrow when the website redesigns.

The real threshold of the Agent era is not "whether models can do things" — by 2025, models are already strong enough on many tasks. The threshold is **reliability** and **trust.** And reliability and trust are not model attributes — they are system attributes. An Agent's reliability depends on the entire tech stack: model capability, tool interfaces, error detection, rollback mechanisms, human oversight, and permission controls. The model is just one layer in this stack.

This systems perspective explains why success rates vary so dramatically across Agent products. Cursor and Claude Code achieve higher success rates in coding scenarios not because their models are stronger than GPT-4 (in fact, Claude 3.5 Sonnet and GPT-4o are close on benchmarks), but because the coding environment provides the best "safety net": compilers check syntax, test suites check behavior, version control systems provide rollback. Once you place an Agent in an environment without a safety net — operating GUIs, browsing the web, interacting with humans — success rates drop precipitously.

A human can hand a task to an Agent, but the human needs to know when the Agent will fail. This requires:

- **Observability**: every step of the Agent's decision-making and actions must be traceable;
- **Boundary awareness**: the Agent must know the limits of its capabilities and request human intervention when uncertain;
- **Error recovery**: the Agent must be able to roll back when it errs, rather than continuing further down the wrong path;
- **Permission control**: the scope and consequences of Agent operations must have clear boundaries.

The absence of any one of these four conditions demotes an Agent from "colleague" to "toy." AutoGPT's failure was not that it "could not" do things, but that it lacked all four — unobservable, unaware of its own boundaries, unable to recover from errors, and without permission controls. The most successful Agent products of 2025 — Cursor, Claude Code — succeeded precisely because they restricted the Agent's scope of action to a safe sandbox with compilers, test frameworks, and version control. Within this sandbox, all four conditions can be met (at least partially). Outside this sandbox, all four become challenges.

## Commentary

The Agent era did not arrive on the day AutoGPT hit one million stars, nor on the day Claude Computer Use was announced. It is arriving — slowly, unevenly, gaining foothold first in specific scenarios.

Coding Agents were the first battlefield to prove that "models can do things, not just talk," because code is the only language in which errors can be automatically verified. Claude Code's capability leap from "autocomplete a line" to "independently refactoring half a codebase" demonstrated the potential of Agents in coding scenarios — but also exposed a new trust problem: when an Agent's output exceeds human review capacity, what is the foundation of trust? The compiler? The test suite? Or the empiricism of "it did well before, so it will do well this time too"? The last of these is engineering-wise unacceptable.

Devin's $2B valuation proves that the market has enormous appetite for the "AI replaces programmers" narrative, but the chasm between demo and reality reminds us that narrative can run far ahead of technology. Devin and Claude Code represent two fundamentally different Agent philosophies — "replacement" and "augmentation" — and their competition will define human-machine relationships in the Agent era.

The difficulty of general-purpose Agents lies not in models being insufficiently intelligent, but in the real world having no compilers or test suites. Google declared its direction with an "agentic era" manifesto, but the "innovator's dilemma" facing its search advertising business model suggests that the winners of the Agent era may not be the largest companies, but those most capable of adapting to business model restructuring. Agent failure modes — insufficient planning, hallucination accumulation, trust barriers — are not defects of individual products but structural limitations of the current technological stage. Until these limitations are systematically solved, the applicable scope of Agents will be strictly confined to "verifiable" domains.

The true Agent era is not one in which models are omnipotent, but one in which **humans have learned to share tasks and share risk with models.** Function Calling laid the protocol, MCP laid the ecosystem, Computer Use bypassed the API barrier — but what ultimately determines how far Agents go is not the upper bound of model capability, but how low engineering systems can push the cost of their mistakes. The diffusion path of Agents begins with "verifiable domains" — code, data, mathematics — and then slowly expands toward "unverifiable domains." This path may take decades, or it may never be fully completed.

AutoGPT proved that demand exists. Function Calling proved that protocols work. MCP proved that ecosystems can be built. Claude Code proved that coding Agents can "work independently for hours." Devin proved that the market will pay $2B for the "AI engineer" narrative. The next thing that needs proving is: Agents can be trusted in the real world without compilers and test suites. This is not a model problem — it is a system design problem, and a trust engineering problem.

The final paradox of the Agent era is this: **Agents are most successful in precisely the domains where humans can most easily verify their output (coding); Agents are most challenged in precisely the domains where humans can least easily verify their output (real-world decisions).** This means the diffusion path of Agents may not be from simple to complex, but from "verifiable" to "unverifiable." In verifiable domains (code, math, data processing), Agents will grow ever stronger. In unverifiable domains (creative judgment, interpersonal relations, moral decisions), Agents will continue to face trust barriers. The dividing line between these two worlds is not technical capability — it is verification cost.

This paradox also explains why the MCP ecosystem is so important. What MCP does is reduce the connection cost between Agents and tools — but its deeper significance is building standardized infrastructure for "verifiable domains." When an Agent calls an API with clear input-output specifications, the verifiability of its output is far higher than when an Agent operates a GUI. Behind the Agent protocol war is an infrastructure war between two Agent paradigms: "verifiable" and "unverifiable." Whoever first builds the infrastructure for "verifiable domains" gains the first foothold.

From AutoGPT's one million stars to Claude Code's hours of autonomous work, Agents took less than two years to travel from "concept hype" to "productivity tool." But this was only the first step. The next step — making Agents work reliably in the real world without compilers or test suites — may take far longer than two years, or may require us to redefine what "reliable" means. The story of the Agent era has only just begun. What the historian must record is not who reaches the finish line first — because perhaps no one knows where the finish line is — but what footprints each step leaves along the way.
