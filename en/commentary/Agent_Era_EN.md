# The Agent Era

> From AutoGPT's one million stars to Claude Computer Use's mouse and keyboard, large language models took two years to prove one thing: making a model "good at chatting" and making it "good at doing things" are separated not by technical capability but by engineering patience, trust boundaries, and ecosystem maturity.

## I. AutoGPT: The Overpromise of the Agent Concept (2023)

On 2023-03-30, an open-source project called AutoGPT launched on GitHub. What it did was simple: give GPT-4 a set of tools — web browsing, file read/write, code execution — then let the model plan tasks on its own, execute them on its own, and decide what to do next. Within two weeks, it became one of the fastest-growing projects in GitHub history, surpassing 100,000 stars.[^1]

AutoGPT's viral popularity wasn't because it actually worked well. In fact, the vast majority of users quickly discovered: it would get stuck in loops, lose context, make absurd decisions, and burn through massive amounts of tokens accomplishing nothing.[^2] A typical failure case: a user asked AutoGPT to "research and write a blog post about quantum computing," and it would bounce between search engines and the file system, consuming hundreds of API calls, ultimately producing an article of extremely low quality — far worse than simply asking GPT-4 to answer in one shot.

But the viral popularity itself revealed something: **the market has a massive, unmet desire for "AI that doesn't just chat but does things for you."** AutoGPT's GitHub star count (surpassing 100,000 in one week) was not an endorsement of code quality but a vote for the Agent concept. The public said with their stars: "We want more than chatbots."

AutoGPT's technical approach — using a natural language loop to drive an LLM to repeatedly invoke tools — quickly exposed its naivety. Large language models are not universal planners. They are already strong enough at single-step reasoning but have virtually no reliable capability in multi-step planning, state management, error recovery, and long-term memory. Wrapping a chatbot model directly into an autonomous agent is like sending a brilliant translator straight to serve as a general — the translator isn't unintelligent; their skill stack just wasn't designed for this task.

By the end of 2023, AutoGPT had largely gone silent. Its contribution was not a technical implementation but a **proof of concept**: the word "Agent" moved from an academic concept into the public consciousness. Every Agent product that followed — whether Devin, Cursor, Claude Code, or OpenAI's Operator — lives in the expectations and shadow that AutoGPT planted.

## II. Function Calling: Agent Infrastructure Quietly Takes Shape (2023)

2023 was the year Agent infrastructure was laid.

After AutoGPT receded, what truly moved Agent from "demo" to "engineering" was Function Calling.

On 2023-06-13, OpenAI added Function Calling capabilities to the GPT-3.5 and GPT-4 APIs. Models no longer just output text — they could output structured JSON, precisely selecting which function to call and what parameters to pass.[^3] This may seem like a small feature, but it was the foundation of Agent capability.

Before Function Calling, getting a model to invoke tools required extensive prompt engineering. You had to describe all available tools in the system prompt and hope the model would output the call intent in the correct format — while format errors, hallucinated parameters, and wrong tool selections were the norm. Function Calling transformed this from a "prompt trick" into a "protocol": models learned during training how to correctly express tool-call intents. This shift may seem minor, but it was the watershed for Agent engineering — from "relying on luck for the model to get it right" to "relying on a protocol to ensure the model gets it right." From this point, tool invocation was no longer the bottleneck of Agent systems — the bottleneck shifted upward to planning, state management, and error recovery.

Anthropic added similar Tool Use capabilities to its Claude 3 series at the end of 2023, and Google implemented function calling in Gemini. By 2024, virtually all major model providers had made "models can call tools" a baseline capability.[^4]

The historical significance of Function Calling lies in: it decomposed Agent from a "monolithic system" into a composable architecture of "model + protocol + tools." AutoGPT tried to make the model do everything — plan, execute, judge. Agent systems after Function Calling took a different path: the model is only responsible for decision-making and dispatch, while execution is delegated to specialized tools. This was an engineering concession and a practical advance.

## III. Claude Computer Use: Agents Enter the Operating System (2024)

On 2024-10-22, Anthropic released a feature called Computer Use. Claude was no longer just calling APIs or tools — it could operate a computer like a human: viewing the screen, moving the mouse, clicking buttons, typing text, and reading on-screen content.[^5]

This was not the first attempt to "let AI operate a computer." There had been various RPA (Robotic Process Automation) tools before, and AutoGPT had tried using a browser. But Computer Use was different: a mainstream model provider made "GUI interaction" a formal API capability. The model receives screenshots as input and outputs mouse and keyboard operations — this is a completely different Agent paradigm from API calls.

Computer Use's breakthrough was that it bypassed the "API barrier." Not all software has APIs, not all APIs have documentation, and not all documentation is accurate. But all software has a GUI. An Agent that can operate a GUI can theoretically use any software — including legacy systems with no APIs, no plugins, and no developer integrations. This is significant for enterprise automation scenarios.

But Computer Use also exposed the most fundamental fragility of Agent systems. GUI operations are brittle: changes in screen resolution, UI layout updates, pop-up overlays, network latency — any tiny variable can cause an Agent operation to fail.[^6] The deeper problem is that when operating GUIs, Agents lack "semantic understanding" — they see pixels, not intent. They know "there's a button here" but don't always know "what this button means in this context."

This is the classic paradox of the Agent era: **the more universal the interface, the more fragile it is; the more specialized the interface, the more reliable it is.** API calls are precise but narrow in coverage; GUI interactions are broad but low in reliability. A real Agent product must find a balance between the two. The MCP protocol (see §VIII) attempts to find a third path in this paradox: not relying on GUIs, nor relying on fixed APIs — but using a standardized protocol layer to establish reliable yet flexible connections between Agents and tools. Whether this path works depends on the speed of MCP ecosystem adoption.

## IV. Claude Code's Capability Leap: From Autocomplete to Autonomous Refactoring

In January 2025, Anthropic released Claude Code — a coding Agent running in the terminal.[^7] Before this, the mainstream forms of AI programming assistance were "in-editor autocomplete" (Copilot) and "conversational Q&A" (ChatGPT). Claude Code took a different path: it is not an editor plugin but an independent Agent running in the terminal that can directly read/write files, execute commands, and operate Git repositories.

Claude Code's true breakthrough lies in a fundamental shift in working mode: from "you ask one question, it gives one answer" to "you assign a task, and it works independently for hours." Users describe a task goal — such as "migrate this project from React 15 to React 18" or "fix all TypeScript type errors" — and Claude Code autonomously plans steps, reads files, modifies code, runs tests, adjusts its approach based on errors, and continues working until completion or until it encounters an unsolvable problem.

By mid-2025, Claude Code was capable of autonomously completing large-scale code refactoring, cross-file migrations, and complex bug fixes. Cases reported by the developer community include: processing hundreds of files in a single session, working continuously for hours to complete a framework migration, automatically running tests and adjusting based on failure results.[^8] Some developers reported that Claude Code completed refactoring tasks in a single session that would have taken humans multiple days — and the quality was not low.

This capability leap raised new trust questions. When Claude Code refactors half a codebase, human developers cannot review every single change line by line the way they would review a colleague's Pull Request. The output volume exceeds human review capacity. Thus a paradox emerges: **the more capable the Agent, the harder it is for humans to verify whether it did things correctly.**

In coding scenarios, compilers and test suites provide partial automated verification. But passing compilation and passing tests does not equal good code quality — an Agent might write code that runs but has terrible maintainability, just as a student might pass an exam without truly understanding the material. More dimensions of code quality — readability, maintainability, naming conventions, architectural soundness — cannot be covered by automated testing and still require human judgment. This means that even in the most favorable environment (with compilers and test suites), Agents still have a layer of quality dimensions that require human oversight.

Another important feature of Claude Code is its "work log" — it outputs in real time what it's doing, why it's doing it, and what problems it encountered. This provides a degree of observability — humans can track the Agent's thought process rather than just seeing the final output. But "observable" does not equal "understandable" — when an Agent modifies 200 files in 3 hours, even the work log exceeds human reading capacity.

Claude Code's success has also redefined what "programming assistant" means. GitHub Copilot (first released 2021-06) was originally "autocomplete one line of code" — humans wrote most of the code, AI filled in a small portion. Cursor (2023-03) expanded to "conversational programming within the editor" — humans describe intent, AI generates code snippets. Claude Code advanced to "autonomously completing complex tasks, with humans only setting goals and reviewing results" — humans define the task, AI completes the execution. This is not incremental improvement — it is a qualitative shift from "tool" to "collaborator." The human role has shifted from "writing code" to "defining intent, reviewing results, and bearing responsibility."

This role transformation has profound implications for software engineering. When a senior engineer uses Claude Code to complete a refactoring task in 2 hours that would have taken 2 days, productivity has indeed increased. But this also means: the "writing basic code" tasks traditionally assigned to junior engineers are being swallowed by Agents. Junior engineers' core value — accumulating experience and intuition through writing large amounts of code — is being bypassed. Agents are not just changing "how code is written" — they are changing "who writes code" and "what skills code-writers need." The programmer's skill stack is migrating from "writing code" toward "reviewing code, defining requirements, and managing Agents."

## V. Devin's Marketing vs. Reality: The Narrative Bet Behind a $2B Valuation

On 2024-03-12, Cognition Labs released Devin, positioning it as "the world's first AI software engineer" — not a programming assistant, not a code autocomplete tool, but an Agent capable of independently completing the entire process from requirements analysis to coding, testing, and deployment.[^9] Cognition Labs was founded by Scott Wu, and team members largely came from competitive programming backgrounds. The name Devin itself suggests the positioning — not Copilot (a co-pilot), but Devin (an independent engineer).

Devin's launch demo showcased impressive capabilities: it could understand natural language requirements, formulate development plans, write code, run tests, debug errors, and even deploy applications. In the demo, Devin completed multiple real Upwork freelance tasks. But independent testers quickly discovered that Devin's actual capabilities fell far short of the demo — frequently failing on many simple tasks, with limited planning ability and unreliable error recovery.[^10]

Despite this, Cognition Labs still achieved a valuation of approximately $2 billion.[^11] This valuation was not based on current product capabilities but on a narrative bet: **the ultimate form of AI programming is not "assisting humans" but "replacing humans."** Cursor and Claude Code are positioned as tools that enhance human productivity — the programmer is still there, just more efficient. Devin was positioned as replacing the programmer themselves — a programmer's role can be taken over by an Agent. The market's enthusiastic response to the latter demonstrated that what investors and business owners truly want is not "making people more efficient" but "not needing people."

Devin and Claude Code represent two philosophies of Agent development. Claude Code's philosophy is "augmentation" — humans remain the subject, Agents are capability amplifiers. Devin's philosophy is "replacement" — Agents are the subject, humans are responsible only for review and acceptance. The former is more readily accepted by programmers; the latter is more favored by investors and management. The tension between these two philosophies will define human-machine relationships in the Agent era — are Agents programmers' tools or their competitors?

Devin's case exposed a structural risk of the Agent era: **the chasm between demo and reality.** AutoGPT's demo made people think the Agent era had arrived (it hadn't); Devin's demo made people think AI engineers were viable (they still required extensive human intervention). Agent product valuations are highly dependent on narrative — and narratives can run far ahead of technology.

This narrative-reality chasm did not narrow in 2025. OpenAI Operator's demo showed Agents automatically completing online tasks, but early users reported frequent errors in operations on complex web pages. Google Project Mariner's demo was impressive, but it had not yet undergone large-scale public testing. The state of the Agent industry in 2025 can be summarized as: **everyone demonstrates in demos that Agents work, but few prove in production environments that Agents are reliable.** This gap is becoming the greatest uncertainty of the Agent era.

Notably, the narrative-reality chasm manifests differently in capital markets and user markets. In capital markets, narratives run ahead — Devin's $2B valuation and the high funding amounts of various Agent startups are based on the narrative that "Agents are about to change everything." In user markets, reality lags behind — most enterprise users are still in the "watching" or "small-scale pilot" phase with Agents, and cases of Agents being truly embedded in core production processes are few and far between. When the gap between capital narratives and user reality widens to a certain degree, market correction will arrive — between 2024 and 2025, multiple Agent startups have already shut down or pivoted.

## VI. Google's "Agentic Era" Declaration

On 2024-12-11, Google DeepMind released Gemini 2.0 Flash. Unlike previous model releases, this time Google CEO Sundar Pichai and DeepMind head Demis Hassabis explicitly positioned Gemini 2.0 as the foundation for entering the "agentic era" — AI that is no longer just a system that answers questions but one that can take actions on behalf of users.[^12] Pichai wrote in the release blog: "If 2023 was the year AI awakened, then 2025 will be the year Agents awaken." This statement marked the world's largest internet company officially defining Agents as its next strategic direction.

On the same day, Google released Project Mariner — an Agent running in the Chrome browser that can understand web content, execute operations, and complete tasks.[^13] Mariner's technical approach is similar to Anthropic Computer Use (viewing the screen, operating the GUI), but its integration method differs: Computer Use is an API capability that developers must invoke; Mariner is a browser extension that directly serves end users.

Google's Agent layout has deeper layers. Gemini 2.0 Flash itself is a multimodal model — capable of processing text, image, audio, and video inputs, and supporting real-time interaction. This means Agents are no longer limited to "reading text" — they can see screens, hear speech, and understand video. Google Search's advantage lies in indexing the most comprehensive information on the internet; Gemini's multimodal capability lies in understanding this information in all its forms; the Agent's value lies in taking action on behalf of users based on this information. The three together constitute Google's most complete value chain in the Agent era.

Google's "agentic era" declaration marked a significant turning point: **all three major AI labs (OpenAI, Anthropic, Google) explicitly positioned Agents as the core direction for the next phase during 2024-2025.** OpenAI has Operator (2025-01), Anthropic has Computer Use (2024-10), and Google has Project Mariner (2024-12). Their paths differ — OpenAI builds standalone products, Anthropic builds API capabilities, Google builds browser integrations — but the direction is the same: **from conversation to action, from answering questions to doing things for you.**

But Google's Agent path faces unique challenges. Google's core business is search advertising — if Agents directly complete tasks for users (booking flights, buying products, filling out forms), users don't need to click on ad links in search results. The more successful the Agent, the greater the threat to Google's existing business model. This is Google's "innovator's dilemma" in the Agent era: you need to cannibalize your revenue stream to ride the next wave. In 2024, Google's search advertising revenue was approximately $198 billion, accounting for about 57% of Alphabet's total revenue. If Agents replace the "search-click-convert" chain, this revenue base erodes. Google must find a delicate balance between Agent capability and advertising protection — a balance that may never be comfortable.

Google's advantage lies in distribution channels. Chrome browser has over 3 billion users; Android covers the majority of smartphones globally. If Google can deeply integrate Agent capabilities into Chrome and Android, it will have an Agent distribution channel larger than any competitor's. Technical capability can be caught up with, but a distribution channel of 3 billion users cannot be replicated. Google's strategy may be: using Gemini's model capability as the foundation, Chrome's browser as the Agent's operating environment, and Google Search's information index as the Agent's knowledge base. The three together form a complete chain from "understanding the world" to "acting on behalf of users."

## VII. Agent Failure Modes: Why Most Agent Projects Failed

Between 2023 and 2025, a flood of Agent projects emerged — and a flood failed. From AutoGPT to various enterprise-grade Agent solutions, the failure rate far exceeded the success rate. Understanding Agent failure modes is more valuable than understanding success cases — because failure modes reveal structural limitations of the current technological stage, not defects of individual products.

**Insufficient planning capability** is the first fundamental wound. LLMs are already strong enough at single-step reasoning but remain unreliable at multi-step planning. Research shows that even the most powerful models experience significantly reduced success rates on tasks requiring more than 5 reasoning steps.[^14] This is not because models are "not smart enough" — it's because the current Transformer architecture has fundamental limitations in long-horizon planning. It excels at "next token" prediction but struggles with reasoning about "the dependency relationships across the next 20 steps." AutoGPT tried to circumvent this limitation by "having the model repeatedly think about the next step" — but repeated thinking consumes massive amounts of tokens and does not guarantee convergence to the correct solution. A more effective engineering approach is to decompose complex tasks into simple subtasks, each executed independently — but this decomposition itself requires planning ability, creating a circular dependency.

**Hallucination accumulation** is the second fundamental wound. In multi-step tasks, each step can introduce small errors. If single-step accuracy is 95%, after 10 steps the overall accuracy drops to about 60% — after 20 steps, to about 36%. This is a multiplicative effect; each step's reliability is amplified by subsequent steps. AutoGPT's failures on complex tasks were largely due to error accumulation within loops — small errors at each step caused subsequent steps' inputs to drift increasingly from the correct direction, ultimately leading to complete failure.

In coding scenarios, hallucination accumulation manifests as: an Agent misreads a function signature at the first step, and all subsequent modifications based on that understanding go wrong. The compiler can catch some errors, but not semantic-level errors — a function call may be syntactically correct but logically wrong, and the compiler won't flag it.

**The human-in-the-loop dilemma.** One solution is to add human checkpoints in the Agent workflow — the Agent pauses at critical decision points to request human confirmation. This improves reliability but undermines the premise of "autonomy" — if an Agent needs human confirmation every three steps, it's not an "autonomous Agent" but an "assistant requiring frequent approval." The more practical problem is: the cognitive cost for humans to review an Agent's intermediate output may not be lower than the cost of humans completing the task themselves. When review cost approaches execution cost, the Agent's productivity advantage is negated.

**Real-world constraints of trust boundaries.** In scenarios such as credit assessment, medical decision-making, and legal documents, the consequences of Agent errors are irreversible. When a coding Agent writes incorrect code, CI can catch it; when a medical Agent makes a wrong diagnosis, who catches it? The trust threshold in these scenarios is extremely high, and Agent reliability is far from reaching it.

The deeper problem is: **Agents don't have a "sorry" option for their errors.** When an autonomous driving system makes a mistake, the consequence may be physical harm. When a financial Agent executes an erroneous trade, the consequence may be irreversible financial loss. In these high-risk scenarios, "rollback after the fact" is not always feasible. This means that deploying Agents in high-risk scenarios must come with extremely strict permission controls — Agents can only execute "reversible" operations. But this limits the Agent's autonomous scope — how different is an Agent that can only execute "reversible operations" from an assistant that "needs human confirmation for every step"?

**The cost-value balance.** Agents may be more expensive than humans on simple tasks (API call costs exceed labor costs) and may be cheaper on complex tasks (saving significant time). But in the middle ground — tasks that are "neither simple nor complex" — the cost-value calculation is fuzzy. The enterprise decision to deploy Agents ultimately depends on whether they can generate positive ROI on "enough" tasks — and this requires large-scale empirical data, which is currently extremely scarce.

**Context window limitations** are also an underestimated cause of failure. When Agents execute long-horizon tasks, they need to maintain an understanding of the entire task state. But LLM context windows are finite — even the latest 100K+ window models lose early information when processing extremely long task histories. AutoGPT's looping problem was partly because context overflow caused the Agent to forget which approaches it had already tried.

**Cost problems** also constrain actual Agent deployment. A Claude Code session processing hundreds of files for refactoring may consume tens of dollars in API fees. When Agents need to repeatedly attempt and roll back, costs inflate further. For enterprises, the cost of an Agent completing a task may exceed hiring a junior human engineer — unless the task is complex enough and time-sensitive enough.

These failure modes point to a common conclusion: **the bottleneck of Agents is not model capability but system reliability.** The most successful Agent products of 2025 — Cursor, Claude Code — succeeded precisely because they restricted the Agent's scope of action to a safe sandbox with a compiler, test framework, and version control. Within this sandbox, errors can be automatically detected and rolled back. Outside this sandbox — such as operating GUIs, browsing the web, or interacting with the real world — Agent reliability drops sharply. The real world has no `git revert`.

## VIII. MCP and the Agent Ecosystem: Protocol Wars Are Platform Wars

On 2024-11-25, Anthropic released the Model Context Protocol (MCP), an open protocol for standardizing connections between LLMs and external tools and data sources.[^15] MCP's design goal is to let any tool — databases, file systems, APIs, internal systems — be callable by Agents through a unified protocol.

MCP's emergence marked a shift in Agent ecosystem competition from "whose model is stronger" to "whose protocol is more universal." This has a structural similarity to the browser wars of the early internet and the operating system wars of mobile internet: when underlying capabilities converge, platform victory depends on ecosystem richness. What MCP does, by analogy, is like how USB standardized device connections — before USB, every peripheral had its own interface; after USB, any peripheral could plug and play. MCP attempts to do the same for Agents: let any tool be "plug-and-play" callable by Agents.

By 2025, MCP had achieved fairly widespread community adoption — large numbers of developers wrote MCP Servers for various services. But the Agent protocol war was far from over. OpenAI released an Agents SDK and enhanced versions of function calling, Google launched its own Agent framework, and Microsoft deeply integrated the Copilot ecosystem with Microsoft Graph.[^16]

The competition between these protocols is essentially a contest for the position of "the Agent operating system." Whoever defines the standard interface between Agents and tools controls the entry point of the Agent ecosystem. This follows the same historical logic as Android vs. iOS, HTTP vs. Gopher: **the victory of a technical standard ultimately depends on the speed of ecosystem adoption, not the technical elegance of the protocol itself.**

MCP's historical significance lies in: it is the first open protocol promoted by a mainstream AI company aimed at standardizing Agent-tool connections. Before MCP, every Agent framework had its own way of calling tools — LangChain had a Tool interface, AutoGPT had a plugin system, and every company's API had its own function calling format. MCP attempted to unify these fragmented interfaces, so that a tool only needs to write one MCP Server to be callable by any MCP-supporting Agent. The benefits of this standardization are enormous — it reduces the integration cost for tool developers and the integration cost for Agent developers. But standardization's success doesn't depend on technical design — it depends on adoption speed. Whether MCP becomes the USB of Agents depends on how many tool providers are willing to write MCP Servers.

## IX. From Tools to Colleagues: The True Threshold of the Agent Era (2025–)

By 2025, Agents moved from demos to products, and from products to ecosystems. But whether the "Agent era" has arrived depends on your definition of "arrived."

In 2025, Agent products began to emerge along two clear directions:

**Coding Agents** were the first successful landing scenario. Cursor, GitHub Copilot, Claude Code, Windsurf, Devin — these products proved one thing: code is the Agent's most natural working environment. Code can be compiler-checked, test-verified, and diff-reviewed. This means Agent output can be automatically verified without humans reviewing every line.[^17] When errors can be automatically detected, the Agent reliability problem shifts from "absolutely cannot make mistakes" to "acceptable error rate." The coding Agent market's competition became fierce in 2025 — Cursor captured developer mindshare with editor integration, Claude Code built technical reputation through extended autonomous work, and GitHub Copilot claimed distribution channels through the Microsoft-GitHub ecosystem. Devin took a differentiated route — not "assistant" but "engineer" — but its actual market performance remains to be verified.

**General-purpose Agents** are still in their early stages. OpenAI's Operator (released January 2025) lets users browse the web and complete online tasks through Agents. Google's Project Mariner embedded Agent capabilities in Chrome.[^18] But the core problem facing general-purpose Agents remains unsolved: they are still unreliable on complex, multi-step tasks requiring judgment. When a coding Agent writes bad code, CI tells you; when a general-purpose Agent books the wrong flight, who tells you?

General-purpose Agents also face a problem that coding Agents don't: **environment change.** Code repositories are relatively stable — API documentation and compiler rules don't change daily. But web interfaces change frequently — button positions, form fields, and pop-up logic can update at any time. GUI Agents need to be robust against such changes — but current Agents' ability to adapt to environmental changes is extremely limited. An Agent that successfully books a flight today may completely fail tomorrow when the website redesigns.

The true threshold of the Agent era is not "whether models can do things" — 2025's models are already strong enough for many tasks. The threshold is **reliability** and **trust.** And reliability and trust are not model properties — they are system properties. An Agent's reliability depends on the entire tech stack: model capability, tool interfaces, error detection, rollback mechanisms, human oversight, and permission control. The model is just one layer of this stack.

This system perspective explains why different Agent products have vastly different success rates. Cursor and Claude Code have higher success rates in coding scenarios not because their models are stronger than GPT-4 (in fact, Claude 3.5 Sonnet and GPT-4o don't differ much on benchmarks) but because the coding environment provides the best "safety net": the compiler checks syntax, the test suite checks behavior, and version control provides rollback. Once you place an Agent in an environment without a safety net — such as operating GUIs, browsing the web, or interacting with humans — the success rate drops sharply.

A human can delegate a task to an Agent, but the human needs to know when the Agent will fail. This requires:

- **Observability**: Every decision and action of the Agent must be traceable;
- **Boundary awareness**: The Agent must know the limits of its own capabilities and request human intervention when uncertain;
- **Error recovery**: When the Agent does something wrong, it must be able to roll back rather than continuing down the wrong path;
- **Permission control**: The scope and consequences of Agent operations must have clear boundaries.

The absence of any one of these four conditions degrades an Agent from "colleague" to "toy." AutoGPT's failure was not that it "couldn't" do things — it was that it was deficient in all four points: unobservable, unaware of its own boundaries, unable to recover from errors, and without permission controls. The best Agent products of 2025 — Cursor, Claude Code — succeeded precisely because they restricted the Agent's scope of action to a safe sandbox with a compiler, test framework, and version control. Within this sandbox, all four conditions can be met (at least partially). Outside this sandbox, all four become challenges.

## Afterword

The Agent era did not arrive on the day AutoGPT hit one million stars, nor on the day Claude Computer Use was announced. It is arriving — slowly, unevenly, establishing footholds in specific scenarios first.

Coding Agents are the first battlefield to prove "models can do things, not just talk," because code is the only language where errors can be automatically verified. Claude Code's capability leap from "autocomplete one line" to "independently refactoring half a codebase" demonstrates the potential of Agents in coding scenarios — but also exposes new trust questions: when Agent output exceeds human review capacity, what is the foundation of trust? The compiler? The test suite? Or the empiricism of "it did well before, so it will do well this time too"? The last one is unacceptable in engineering.

Devin's $2B valuation proves the market has a huge appetite for the "AI replacing programmers" narrative, but the chasm between demo and reality reminds us: narratives can run far ahead of technology. Devin and Claude Code represent two fundamentally different Agent philosophies — "replacement" and "augmentation" — and their competition will define human-machine relationships in the Agent era.

The difficulty of general-purpose Agents does not lie in models not being smart enough, but in the real world having no compiler or test suite. Google declared the direction with its "agentic era" manifesto, but the "innovator's dilemma" facing its search advertising business model suggests: the winners of the Agent era may not be the biggest companies but those most able to adapt to business model restructuring. Agent failure modes — insufficient planning, hallucination accumulation, trust thresholds — are not defects of individual products but structural limitations of the current technological stage. Until these limitations are systematically addressed, Agents' applicable scope will be strictly confined to "verifiable" domains.

The true Agent era is not a time when models can do anything, but a time when **humans learn to share tasks and share risks with models.** Function Calling laid the protocol, MCP laid the ecosystem, Computer Use bypassed the API barrier — but what ultimately determines how far Agents go is not the upper limit of model capability but how low the engineering system can press the cost of their mistakes. The path of Agent diffusion is "verifiable domains" first — code, data, mathematics — then slowly expanding into "unverifiable domains." This path may take decades, or it may never be completed.

AutoGPT proved demand exists. Function Calling proved protocols work. MCP proved ecosystems can be built. Claude Code proved coding Agents can "work independently for hours." Devin proved the market is willing to pay $2B for the "AI engineer" narrative. The next step that needs to be proven is: Agents can be trusted in the real world without compilers and test suites. This is not a model problem but a system design problem — and a trust engineering problem.

The final paradox of the Agent era is: **the domains where Agents are most successful are precisely the domains where humans can most easily verify their output (coding); the domains where Agents struggle most are precisely the domains where humans can least easily verify their output (real-world decision-making).** This means the path of Agent diffusion may not be from simple to complex, but from "verifiable" to "unverifiable." In verifiable domains (code, math, data processing), Agents will grow stronger. In unverifiable domains (creative judgment, interpersonal relationships, moral decisions), Agents will continue to face trust barriers. The dividing line between these two worlds is not technical capability — but verification cost.

This paradox also explains why the MCP ecosystem is so important. What MCP does is reduce the connection cost between Agents and tools — but the deeper significance is that it builds standardized infrastructure for "verifiable domains." When an Agent calls an API with clear input-output specifications, the verifiability of output is far higher than when an Agent operates a GUI. Behind the Agent protocol war is an infrastructure war between "verifiable" and "unverifiable" Agent paradigms. Whoever first builds the infrastructure for "verifiable domains" gains the first foothold.

From AutoGPT's one million stars to Claude Code's hours of autonomous work, Agents took less than two years to travel from "concept hype" to "productivity tool." But this is only the first step. The next step — making Agents work reliably in the real world without compilers and test suites — may take far longer than two years, or may require us to redefine the meaning of "reliable." The story of the Agent era has only just begun. What historians need to record is not who reaches the finish line first — because no one may know where the finish line is — but what footprints were left at each step along the way.
