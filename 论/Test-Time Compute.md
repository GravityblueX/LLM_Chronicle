# Test-Time Compute：推理时计算的范式革命

> Scaling Law 有过三次修正。第一次（Kaplan，2020）告诉行业：堆更多参数、更多数据、更多算力，模型就会更强。第二次（Chinchilla，2022）修正了参数和数据的比例。第三次发生在 2024 年 9 月——OpenAI 发布 o1，让行业第一次意识到：推理时的计算本身也是一种可规模化的资源。这不是对前两次的否定，而是在训练侧 scaling 的边界处，打开了一个全新的维度。

## 一、三次修正：Scaling Law 的演进史

要理解 test-time compute 的位置，需要先看清它在 Scaling Law 演进中的坐标。

2020 年 1 月，OpenAI 的 Jared Kaplan 等人发表了"Scaling Laws for Neural Language Models"。这篇论文的核心发现是：模型的性能（以交叉熵损失衡量）与三个因素呈幂律关系——参数数量（N）、数据集大小（D）和训练计算量（C）。[^1] 在这个框架下，只要同步扩大这三个要素，模型就会持续变强。GPT-3 的训练策略就是这一思想的直接产物：1750 亿参数，3000 亿 token，投入了当时最大规模的训练计算。[^2]

Kaplan 法则的隐含假设是：三个变量中，参数规模最重要，数据和计算只需配合。实际训练中，很多模型的参数量远大于 Chinchilla 后来认定的最优配比——GPT-3 的 1750 亿参数只用了 3000 亿 token 训练，按照后来的标准，这个数据量严重不足。

2022 年 3 月，DeepMind 的 Hoffmann 等人发表了"Chinchilla"论文，对 Kaplan 法则做了第一次重大修正。Chinchilla 论文论证：在固定计算预算下，参数数量和训练数据量应同步增长，最优比例大约是 20 个 token 对应 1 个参数。[^3] 按照这个配比，GPT-3 级别的计算预算应该训练一个约 700 亿参数、1.4 万亿 token 的模型——参数更少，数据更多，效果反而更好。Chinchilla 用 700 亿参数击败了 Gopher 的 2800 亿参数，证明了这一修正的正确性。[^3]

Chinchilla 修正了 Kaplan 对数据的忽视，但两者共享同一个前提：**所有能力提升都发生在训练阶段。** 模型训练完成后，能力就被"冻结"在权重里。用户调用模型，只是在消费已经封装好的能力——推理阶段不产生新能力，只输出已有能力。

这个前提在 2024 年被动摇。

2024 年 8 月，Charlie Snell 等人发表了"Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters"，系统性地论证了一个此前被低估的维度：在推理阶段投入更多计算，可以在不增大模型的前提下，显著提升模型的有效表现。[^4] 论文提出了 test-time compute 的最优分配策略：不同的问题应该获得不同的推理计算预算——有些问题需要深度搜索，有些问题快速回答即可。

一个月后，2024 年 9 月 12 日，OpenAI 发布 o1，将这一理论转化为商业产品。[^5] Test-time compute 从论文概念变成了用户可以触摸的东西。这就是第三次修正：**推理时的计算本身也是一种可规模化的资源。**

## 二、o1：把推理计算变成产品

o1 之后，大模型行业的产品逻辑发生了根本变化。此前的模型都是"即问即答"——输入 prompt，输出回答，推理过程是瞬时的。o1 引入了一个新的时间维度：模型在给出最终答案之前，会消耗大量内部推理 token，生成一个用户不可见的思维链，再把整理后的答案交给用户。[^5]

这个"先想再答"的机制与传统的 chain-of-thought prompting 有根本区别。传统 CoT 是显式的：用户要求模型"一步一步想"，模型就把推理过程写在输出里，用户可以阅读、检查、纠正。o1 的"思考"是隐式的：推理过程被系统拦截，用户只看到最终结论，看不见模型如何从问题到达结论。[^5] OpenAI 称之为 hidden chain-of-thought。

隐式推理带来了惊人的性能跃升。在 AIME 2024 数学竞赛上，o1 达到 74.4% 的正确率，而 GPT-4o 仅为 12.1%。[^5] 这不是一个渐进式的提升——它是指数级的。差距的来源不是更大的训练参数，不是更多的训练数据，而是模型在回答每个问题时投入了远多于前代的推理计算。如果把这 62 个百分点的差距换算为训练时 scaling，可能需要数倍甚至数十倍的训练投入才能达到。

这就是 test-time compute 的核心价值主张：**推理时计算可以在不增加模型参数的情况下，显著提升有效表现。** 换句话说，推理计算可以替代一部分训练计算。与其花费数十亿美元训练一个更大的模型，不如在推理阶段花更多 token 让现有模型"多想一想"。

但 o1 的设计也埋下了两个结构性问题。第一是透明度问题：隐藏推理过程让用户无法判断模型的思考是否可靠，模型可以说"我想过了"，但你无法验证它是否真的想了，以及想了什么。这个问题在《推理模型的分水岭》一文中已有详细讨论。[^6] 第二是成本问题：推理时多消耗的 token 是要花钱的。当 test-time compute 从学术概念变成商业产品时，谁来为模型的"思考时间"买单，就从技术问题变成了经济问题。

## 三、DeepSeek-R1：推理计算的另一条路

o1 证明了推理计算的有效性，但它的技术路线并不是唯一可能的。DeepSeek-R1 在 2025 年 1 月 20 日给出了一个根本不同的答案。[^7]

o1 的推理能力来自人工设计的训练方案：OpenAI 精心构造了大量监督数据，教模型如何一步步推理，然后用这些数据训练模型按特定方式"思考"。这可以理解为人类把自己的推理方法论"编程"进了模型的权重。推理计算在 o1 中是一种被训练出来的、预设的技能。

DeepSeek-R1-Zero 采取了完全不同的路径。它没有使用任何传统的监督微调——没有用人类标注的"正确推理过程"来教模型怎样一步步想。它只用了一个基础模型、GRPO（Group Relative Policy Optimization）强化学习算法，和规则奖励：数学题答案是否正确、代码是否通过测试。[^7]

结果是，R1-Zero 在训练过程中自发涌现出了推理行为——自我验证、回溯反思、分步检查。这些行为不是从人类标注数据中模仿来的，而是在 RL 的奖励驱动下"长"出来的。[^7]

两条路径的差异揭示了对推理计算的不同理解。在 o1 的框架下，推理时计算是一种**被设计的能力**：需要人类先定义"好的推理长什么样"，再训练模型复制这种推理模式。在这种框架下，test-time compute 的上限取决于人类设计者的认知边界——人类只能把自己知道的推理方法教给模型。

在 R1-Zero 的框架下，推理时计算是一种**被引导的行为**：人类只提供任务和奖励信号，模型自己探索出最有效的推理策略。在这种框架下，test-time compute 的上限取决于奖励信号的质量和搜索空间的大小——理论上可以超越人类的推理模式。

这不只是技术路线之争，而是两种研究范式的分野。o1 的路线更接近传统的监督学习：有标注数据，有明确的学习目标，工程可控性强。R1-Zero 的路线更接近进化论式探索：没有预设目标，只有选择压力，结果更具涌现性。前者的推理能力上限是人类设计者；后者的推理能力上限是算法和算力。

当然，R1-Zero 并非完美。纯 RL 涌现的推理行为存在可读性差、语言混杂、格式不规范等问题，DeepSeek 在最终的 R1 中加入了冷启动数据来改善这些工程缺陷。[^7] 但 R1-Zero 作为实验的意义不在于它的工程成熟度，而在于它证明了一件事：推理能力可以从 RL 奖励中自然生长出来，不需要人工设计推理流程。

## 四、推理计算的经济学

预训练成本和推理成本有着根本不同的经济学结构。预训练是一次性投入：一个前沿模型的训练成本从数千万美元到数亿美元，训练完成后这笔钱就花完了，无论模型表现如何，沉没成本已经不可收回。推理成本是边际成本：每次用户调用模型都产生计算费用，调用次数越多，总成本越高，但单次调用的成本可以很低。

test-time compute 改变了推理成本的结构。传统模型的推理成本大致与输出 token 数量线性相关——生成 1000 个 token 的成本约是生成 100 个 token 的十倍。推理模型的推理成本引入了一个新变量：**思考深度**。o1 回答一个数学问题可能消耗数千个推理 token，而这些推理 token 用户看不见，也不产生直接信息价值，但它们是模型得出正确答案的必要投入。

这就产生了一个定价难题：推理 token 怎么收费？

一种方案是把推理 token 算在总 token 里一起计费。这是大多数 API 的做法——用户按照总 token 数（包含推理 token）付费。这种方案简单透明，但对用户来说有一个风险：推理 token 数量不透明（尤其在 o1 这种隐藏推理过程的模型中），用户无法预测单次调用的成本。同一个问题，模型这次想了 500 token，下次想了 5000 token，费用可能相差十倍。

另一种方案是订阅制。OpenAI 推出了 ChatGPT Pro（2024 年 12 月，200 美元/月），提供 o1-pro 的无限制使用。[^8] Anthropic 推出了 Claude Max 计划（约 100-200 美元/月），提供更高的使用配额。[^9] 这些高端订阅的核心价值主张，正是为重度用户的推理计算需求提供一个可预测的固定成本。

订阅制的经济逻辑是：把推理计算的成本从"每次调用的可变成本"变成"每月固定的订阅费"，平台承担了推理 token 的不确定性风险。这对重度用户（每天调用数十次推理模型的研究者、开发者）是划算的，对轻度用户（偶尔问一个问题的普通人）则不然。

更深层的经济学问题是：**用户愿意为"更慢但更准确"的答案付多少钱？**

这个问题没有统一答案。在数学竞赛中，12.1% 到 74.4% 的差距意味着从"基本不会"到"大部分会"——如果正确答案的价值足够高（比如科研中的关键计算、金融中的风险建模），推理计算的额外成本可能微不足道。但在日常对话、创意写作、情感陪伴等场景中，"更准确"的价值难以量化，推理计算的边际收益可能很小。

这意味着 test-time compute 的商业模式可能不是一个统一的定价问题，而是一个场景化的价值问题。在高价值、可验证的场景中，推理计算有明确的付费逻辑；在低价值、主观化的场景中，快速回答可能就够了。这与《推理模型的分水岭》中讨论的产品分层逻辑一脉相承：推理模型不是取代通用模型，而是在通用模型之上开辟了一个新的价值层级。[^6]

## 五、推理计算的产品化：三层价格梯度

test-time compute 最深远的产品影响，是把 AI 服务从单一产品变成了**可变计算预算的服务梯度**。

传统的大模型产品只有一种计算模式：输入 prompt，模型生成回答，输出 token 计费。所有用户、所有任务都使用相同的推理路径和相同的计算量。区别只在于模型的大小——GPT-3 便宜但弱，GPT-4 贵但强。

推理模型引入了第二个维度：**同一模型内的计算深度**。同一个问题，可以用快速回答处理（少花计算），也可以用深度思考处理（多花计算）。这就形成了三层价格梯度：

**第一层：快速回答。** 使用最小计算量，模型直接生成答案，不进行深度推理。适用于简单查询、日常对话、格式化任务。价格最低，延迟最短。

**第二层：扩展思考。** 模型进行中等程度的推理，消耗一定数量的推理 token。适用于中等难度的分析、写作、编程辅助。价格中等，延迟可接受。

**第三层：深度推理。** 模型投入大量计算进行搜索、验证、自我纠错。适用于高难度数学、复杂代码生成、多步推理。价格最高，延迟最长。

OpenAI 的产品线已经体现了这种分层：o1-mini 处理简单推理任务，o1 处理标准推理任务，o1-pro 处理高难度任务。[^8] Anthropic 则走了另一条路：在 Claude 3.7 Sonnet 中把"思考"做成一个可切换的开关——同一个模型，普通模式快速回答，extended thinking 模式深度推理。[^10] 后者的用户体验更连贯，但定价更复杂。

这种分层的产品含义是深远的。它意味着 AI 服务不再是"一种商品"，而是"一个计算预算的梯度"——用户可以根据任务复杂度和预算灵活选择推理深度。这更接近云计算的定价模式（按需付费、弹性伸缩），而非传统软件的固定许可模式。

但这也带来新的用户体验问题。如果推理深度可以调整，谁来决定调整——用户还是模型？用户手动选择会增加使用负担（"这个任务应该用快速模式还是深度模式？"）；模型自动判断又可能误判（该深度思考时给了快速回答，或该快速回答时花了大量推理 token）。这个问题尚无成熟解法，但它将是推理模型产品化的核心设计挑战之一。

## 六、理论含义：智能的天花板在哪里？

Test-time compute 最深层的理论含义，是对"智能"这个概念的重新定义。

在 Kaplan-Chinchilla 时代，行业对智能的理解可以简化为一个函数：**Intelligence = f(训练算力)**。模型的智能上限在训练阶段确定，推理阶段只是在消费这个上限。更多的训练投入意味着更高的智能上限，这是 scaling law 的基本逻辑。

Test-time compute 把这个函数修正为：**Intelligence = f(训练算力, 推理算力)**。训练算力决定模型的**能力上限**——模型"知道"多少，能"做"什么。推理算力决定模型在每次任务中**接近这个上限的程度**——面对具体问题时，模型实际能发挥出多大比例的潜力。

这个修正的理论意义在于：智能不再是一个静态属性（"这个模型有多聪明"），而是一个动态过程（"这个问题上，模型用了多少计算来接近它的能力上限"）。同一个模型，在简单问题上快速回答（低推理计算），在复杂问题上深度推理（高推理计算），表现出的"智能"截然不同。

这就引出一个激进的假设：**如果推理时计算也能 scale，那是否意味着"足够聪明的基础模型 + 无限推理时间"可以解决一切问题？**

这个假设在某些条件下接近成立。在数学和代码这类可验证任务上，推理计算的扩展确实展现出持续的收益——模型可以尝试多种解法、自我验证、回溯纠错，直到找到正确答案。在这个意义上，推理计算把"思考"从一个瞬时行为变成了一个搜索过程：搜索空间越大（推理 token 越多），找到正确答案的概率越高。

但这个假设在另一些条件下会失效。对于需要主观判断、审美感知、情感理解的任务，更多的推理计算不一定会产生更好的结果。一个文学评论问题没有唯一的正确答案，模型多想十倍的时间，未必能让评论更有洞察力——因为最终的判断标准不在模型的能力范围内，而在人类的接受范围内。

这里存在一条关键分界线：**任务的可验证性**。在可验证任务上（有明确正误标准），推理计算可以通过搜索和自我检验来扩展有效能力。在不可验证任务上（标准模糊或主观），推理计算的扩展收益递减，因为模型无法知道自己是否在"逼近"正确答案。

这意味着 test-time compute 不是万能药。它在可验证任务上是训练计算的有效补充，但在不可验证任务上，基础模型的能力上限仍然是决定性的。

即便在可验证任务上，推理计算的扩展也面临收益递减。当模型已经找到正确答案时，继续投入推理 token 是浪费资源。推理计算的最优配置是"恰好够用"——多一分是浪费，少一分是不足。这与训练侧 scaling law 的最终命运是一样的：随着投入增加，边际收益下降，直到成本超过收益。

智能的天花板，可能不在于任何单一维度的 scaling——无论是训练计算还是推理计算——而在于**三个维度的交集**：基础模型的能力上限、推理计算的投入深度、以及任务本身的可验证程度。任何一个维度的不足都会成为天花板。三者同时扩展，才可能逼近理论上的能力极限。

## 评曰

Scaling Law 的三次修正，画出了一条关于"智能从何而来"的认知演进线。

2020 年的 Kaplan 法则相信：智能来自更多参数、更多数据、更多算力。这个信念驱动了从 GPT-3 到 GPT-4 的数年狂飙。2022 年的 Chinchilla 修正了一个技术细节：数据和参数要平衡。行业的注意力从"堆参数"转向"堆数据"。2024 年的 test-time compute 打开了一扇全新的门：智能不只在训练时产生，也可以在推理时通过计算来提升。

三次修正的因果链很清晰。Kaplan 法则让行业不计成本地堆训练算力，直到训练成本飙升到数十亿美元量级。Chinchilla 指出数据和参数要匹配，推动行业重新思考训练效率。当训练侧的优化空间逐渐收窄——数据墙逼近、边际收益递减、前沿模型的训练成本接近极限——行业自然把目光转向推理侧。o1 不是凭空出现的灵感，而是训练侧 scaling 逼近天花板后，行业的理性选择：训练算力的增长曲线在放缓，那就在推理侧寻找新的增长曲线。

但 test-time compute 不是一劳永逸的突破。它有自己的经济学约束——推理 token 要花钱，用户愿意为"更慢但更准"的答案付多少钱，决定了它的真实市场规模。它有自己的理论边界——只在可验证任务上能持续扩展，对主观判断类任务的贡献有限。它有自己的信任问题——推理过程的隐藏与公开，仍然是一个悬而未决的治理难题。

Test-time compute 的真正历史意义，是把"智能"从一个静态概念改写为一个动态过程。过去，"这个模型有多聪明"是一个可以给出确定答案的问题——参数多少、数据多少、benchmark 多高，模型的能力就是多少。现在，"这个模型有多聪明"取决于它在具体任务上愿意花多少推理计算。模型的能力不再是一个固定的点，而是一条曲线——横轴是推理计算投入，纵轴是有效表现，曲线的形状由训练质量决定。

Kaplan 修正了算力认知，Chinchilla 修正了数据认知，Test-Time Compute 修正了推理认知。三者叠加，构成了当代 AI scaling 的完整图景：智能不是来自训练或推理中的任何一方，而是来自两者共同作用的总和。这个总和是否有上限，取决于我们对"智能"本身的理解——而这个理解，显然还在修正之中。
