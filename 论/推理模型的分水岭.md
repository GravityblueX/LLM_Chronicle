# 推理模型的分水岭

> 2024 年以前，大模型竞争主要问一个问题：训练时堆多少数据、多少参数、多少算力。o1 之后，问题变成了另一个：模型回答时，愿意花多少时间思考？这不是小修小补，而是大模型史上一道真正的分水岭。

## 一、分水岭不在“会不会推理”，而在“推理被产品化”

早期大模型当然也能推理。GPT-3、GPT-4、Claude、Gemini 都能做题、写代码、分析文本。只是那时的推理更像语言能力的副产品：模型把题目读进去，凭训练中学到的模式直接往下生成。你可以用 prompt 要它“一步一步想”，但这仍然是外部提示技巧，不是模型产品形态本身。

**o1 改变的是产品定义。**OpenAI 在 2024 年 9 月把“先想再答”做成了一个独立模型品类：模型不再只是即时续写，而是在回答前消耗额外计算，生成内部推理轨迹，再把整理后的答案交给用户。OpenAI 将这称为“learning to reason”，并明确展示了它在数学、编程、科学推理上的跃升。[^1]

这件事的关键不在“链式思维”四个字。Chain-of-thought 作为提示方法早已存在。真正的新意在于：**推理时间成为可购买、可调度、可计价的计算资源**。从此，大模型的能力增长不只发生在训练阶段，也发生在推理阶段。过去的 scaling 是“模型训练得更久、更大”；新的 scaling 是“模型回答时想得更久、更深”。

这就是 test-time compute 的历史位置。它把“聪明”从一个静态属性，改写成一个动态过程：同一个问题，可以用便宜的快答，也可以用昂贵的慢想。模型不再只是一个压缩了知识的参数包，而是一个会在运行时分配计算预算的系统。

## 二、o1 的开创与代价：能力突破，信任收缩

o1 的历史功绩很清楚：它让行业相信，训练时 scaling 遇到收益递减后，推理时 scaling 仍然能打开新空间。AIME、Codeforces、GPQA 这些基准的跃升，使“推理模型”不再是论文概念，而成为商业产品。[^1]

但 o1 同时埋下了一个问题：**它把推理过程藏了起来**。

OpenAI 的理由是安全。隐藏原始思维链，可以减少用户从模型内部推理中学习绕过安全策略的机会；也可以避免模型把未经整理的中间想法、错误尝试、敏感推断直接暴露给用户。这个理由不是完全没有道理。真实的模型思维轨迹未必等于可靠解释，它可能包含试错、幻觉、偏见和安全风险。

问题在于，隐藏思维链也带来另一种风险：外部世界无法判断模型到底如何得出结论。用户看到的是一个更强的黑箱。它会说“我想过了”，但你看不见它怎么想；供应商说“这是为了安全”，但你也无法独立验证这套安全逻辑。

于是，o1 一面开创了推理模型，一面把推理模型的信任问题推到台前。以前的黑箱主要是训练数据、权重和系统提示；o1 之后，黑箱又多了一层：**运行时思考本身**。

这就是 o1 的两面性。它证明了 test-time compute 的价值，却没有回答 test-time compute 应该怎样被信任。

## 三、DeepSeek-R1：把推理能力从奢侈品变成公共品

DeepSeek-R1 的意义，不能只看作“又一个追上 o1 的模型”。如果只是闭源 API 对闭源 API，它不过是价格战和性能战。R1 真正改变格局的是三件事放在一起：推理能力、开放权重、可观察思维链。

DeepSeek 在 2025 年 1 月发布 R1，并公开论文、模型权重和蒸馏模型。论文中，R1-Zero 通过强化学习和规则奖励，在没有传统冷启动监督微调的情况下发展出推理行为；R1 则在此基础上加入冷启动数据，改善可读性和稳定性。[^2] 这使行业第一次清楚看到：推理能力不一定必须由封闭实验室用不可见流程“炼成”，它可以被论文描述、被社区复现、被小模型蒸馏。

R1 对 o1 的冲击，不只是“我也会推理”，而是“我让别人也能拥有推理”。这是一种生态层面的降维打击：

- o1 把推理做成高价、闭源、隐藏过程的服务；
- R1 把推理做成可下载、可改造、可蒸馏的能力；
- o1 让用户相信供应商；
- R1 让用户至少有机会自己验证。

当然，公开思维链并不等于绝对真实，也不等于绝对安全。模型展示的 `<think>` 可能仍然是经过训练塑形的可读轨迹，不必然等同于全部内部机制。把“显示出来的思考”直接当成“真实原因”，也是一种天真。但历史上重要的不是它是否提供了哲学意义上的透明，而是它改变了行业默认值：推理模型不必天然隐藏。

R1 之后，推理模型的合法性不再只来自“我更强”，还来自“我是否允许你检查、部署和替换”。这正是它的分水岭意义。

## 四、Claude 3.7：推理不必是另一个模型，也可以是一个开关

OpenAI 的路线是分立：普通模型处理日常任务，o 系列处理复杂推理。这个设计清楚，用户也容易理解——想推理就换推理模型。但它带来一个实际问题：很多任务并不天然分成“要推理”和“不要推理”。写代码可能需要深想，也可能只是补一个函数；聊天可能只需快答，也可能突然进入复杂决策。

Claude 3.7 Sonnet 给出了另一种回答：同一个模型里放入普通回答和 extended thinking，让用户或系统决定何时打开思考。Anthropic 在发布中称 Claude 3.7 Sonnet 是其首个 hybrid reasoning model，并强调它既能即时回答，也能在需要时进行扩展思考。[^3]

这一步的史学意义，是把推理从“型号差异”改成“运行模式差异”。

如果说 o1 把推理模型独立成一个新品类，那么 Claude 3.7 则提醒行业：推理不一定要以新品类长期存在。它可能只是未来通用模型的一种工作状态。就像人不会分裂成“日常人”和“推理人”，而是在不同任务中分配不同注意力；模型也未必需要分裂成快模型和慢模型，而可以在同一主体内切换。

这种混合推理解决了 o1 的一个产品痛点：用户不总是愿意为“深思熟虑”付出等待。对简单问题，慢想是浪费；对复杂问题，快答是不负责任。混合推理的核心，就是把 test-time compute 从固定成本变成可变成本。

但它也带来新问题：谁来决定什么时候该思考？用户手动开关会增加使用负担；模型自动判断又可能误判。推理预算一旦成为产品体验的一部分，UI、计费、延迟、可靠性都会卷入技术路线。这说明推理模型的竞争已经不只是模型论文竞争，而是系统设计竞争。

## 五、Qwen3：混合推理进入开源全谱系

Qwen3 的位置，正是在 Claude 3.7 之后，把“思考/非思考”双模式带入开源模型系列。阿里在 2025 年 4 月发布 Qwen3，覆盖从小参数到 MoE 旗舰的多个规模，并在项目说明中突出 thinking mode 与 non-thinking mode 的切换。[^4]

这件事的重要性有两层。

第一，混合推理不再只是闭源产品体验。开源社区可以拿到支持思考开关的模型，做本地部署、微调、量化、代理系统和行业适配。推理能力由此进入“全谱系”阶段：不是只有最贵的旗舰模型能慢想，小模型也可以在自己的能力边界内分配思考预算。

第二，Qwen3 使推理模型的竞争从单点模型转向家族生态。R1 的强项是用一次开源发布打穿 o1 的封闭叙事；Qwen3 的强项则是完整：多个尺寸、统一许可、混合推理、工程可用。对企业和开发者来说，这种完整性有时比单一榜单第一更重要。因为真实部署从来不是“选世界最强模型”这么简单，而是要在成本、延迟、硬件、语言、许可证、可维护性之间取平衡。

从 o1 到 R1，再到 Claude 3.7 和 Qwen3，推理模型完成了一次形态演化：

1. **独立推理模型**：o1 证明慢想有效；
2. **开放推理模型**：R1 证明慢想可以开源和蒸馏；
3. **混合推理模型**：Claude 3.7 证明慢想可以成为开关；
4. **开源混合推理系列**：Qwen3 证明这个开关可以进入完整生态。

这条链路比任何单次 benchmark 更重要。

## 六、隐藏与公开：思维链不是答案，而是治理问题

围绕推理模型，最容易吵成口号的是“隐藏思维链”与“公开思维链”。但这不是一道简单的道德选择题。

隐藏思维链有合理性。模型的原始思考可能暴露安全策略、泄漏敏感推断、误导用户把中间猜测当成事实。尤其在医疗、法律、金融、网络安全等领域，未经整理的推理过程可能造成新的风险。供应商不公开原始链条，并不必然等于作恶。

公开思维链也有合理性。用户需要知道模型为什么这样回答，研究者需要分析模型失败在哪里，开发者需要调试 agent 行为。完全隐藏会让推理模型变成“神谕机”：它给结论，却不给可检查路径。能力越强，这种神谕化越危险。

所以真正的问题不是“公开还是隐藏”，而是**公开到什么层级、面向谁公开、以什么形式公开**。

可能的稳定形态不是把所有原始 token 倾倒给用户，也不是永远只给一个结论，而是分层：

- 面向普通用户，给可读、简洁、经过安全处理的理由；
- 面向开发者，给推理摘要、工具调用轨迹、置信度和失败信号；
- 面向审计者，在受控条件下开放更细的日志和评估材料；
- 对高风险任务，要求模型把关键假设、证据来源和不确定性显式列出。

换句话说，思维链不是单纯的“解释文本”，而是一种治理接口。o1 把它收回供应商内部；R1 把它推向公开；Claude 3.7 和 Qwen3 则把它做成可切换体验。未来真正成熟的推理系统，很可能会把“思考”拆成多个层级，而不是在全藏和全露之间二选一。

## 七、真正的分水岭：从模型能力史进入计算预算史

推理模型的分水岭，表面上是 o1、R1、Claude 3.7、Qwen3 几个模型的接力；深层其实是大模型史的叙事重心变了。

在 GPT-3 到 GPT-4 的时代，大家关心的是训练：多少参数、多少 token、多少 GPU、多少数据。模型发布后，它的能力大体被固定在权重里。用户调用模型，只是在消费已经封装好的能力。

推理模型时代，能力不再完全固定。模型可以在运行时用更多 token 搜索、验证、反思、调用工具、生成候选答案再筛选。于是，问题变成：

- 什么时候值得多想？
- 多想多少才划算？
- 思考过程能不能被信任？
- 推理成本由谁支付？
- 开源模型能否把这种能力下放到本地和行业场景？

这就是 test-time compute 的真正含义。它不是“模型输出更长”这么浅，而是把 AI 系统的核心资源从训练中心扩展到推理现场。训练时算力决定模型的上限，推理时算力决定每次回答愿意接近这个上限到什么程度。

因此，o1 是开门者，DeepSeek-R1 是拆墙者，Claude 3.7 是改造产品形态者，Qwen3 是把新形态铺进开源生态者。四者共同完成了一个转折：大模型不再只是越训越大的语言机器，而开始变成会在任务现场分配计算预算的推理系统。

## 评曰

推理模型的分水岭，不是某一天模型突然“有了思想”。更准确地说，是行业承认：智能不只藏在训练好的参数里，也发生在回答问题的过程里。

o1 让慢思考成为商品，R1 让慢思考成为公共能力，Claude 3.7 让慢思考成为开关，Qwen3 让这个开关进入开源全谱系。隐藏思维链与公开思维链之争，只是这场转向的表层；更深处的变化，是计算预算、信任机制和产品形态一起重组。

以后评价一个模型，不能只问“它有多强”，还要问“它怎样思考、何时思考、谁能检查它的思考、用户能否负担它的思考”。这四个问题，正是推理模型时代的基本问题。
