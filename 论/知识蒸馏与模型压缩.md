# 知识蒸馏与模型压缩

> 知识蒸馏最初只是“让小模型学大模型”的工程方法。到了大模型时代，它同时变成了四件事：模型压缩、能力迁移、开放生态传播手段，以及 API 商业模式中的产权冲突点。2026 年 Anthropic 将部分竞争者行为称为“industrial-scale distillation attacks”，并不意味着蒸馏本身变成了攻击技术；真正发生变化的是**teacher 是否属于你、输出如何取得、服务条款是否允许、衍生模型继承什么许可证**。

---

## 一、起点：teacher 不只给答案，还给结构

2015 年，Geoffrey Hinton、Oriol Vinyals、Jeff Dean 发表《Distilling the Knowledge in a Neural Network》。[^1]

核心思想是：大模型输出的概率分布包含比 one-hot 标签更丰富的信息。student 不只学习“正确答案是什么”，还学习 teacher 如何区分相似选项。

因此蒸馏从一开始就包含一个重要前提：

> **训练信号可以来自另一个模型，而不只来自原始标注数据。**

早期用途主要是压缩：服务器模型教手机模型，降低延迟、内存和推理成本。

---

## 二、从压缩到能力迁移

BERT 时代，DistilBERT 等工作仍主要围绕“更小、更快”。[^2]

到大模型时代，teacher 输出本身越来越丰富：

- 指令跟随回答；
- 代码；
- 数学解题轨迹；
- 工具调用序列；
- 长程 Agent trajectory；
- 视觉与多模态中间结果。

于是蒸馏的目标从“保留原模型大部分能力”逐渐变成：

> **把某类高价值能力迁移到另一种尺寸、架构或成本结构。**

这和量化不同。量化尽量不改变同一个模型的行为；蒸馏则重新训练 student，因此 student 是新的模型。

---

## 三、DeepSeek-R1：推理能力进入批量蒸馏

**2025-01**，DeepSeek 发布 DeepSeek-R1、R1-Zero，以及六个基于 Qwen / Llama 基座的蒸馏模型。[^3]

R1 主模型基于 DeepSeek-V3-Base，V3 系列总参数为 **671B**。这里不能再沿用旧稿“660B”的近似写法。

DeepSeek 官方仓库说明，蒸馏模型使用约 800k 由 DeepSeek-R1 整理的样本对相应基座进行微调。[^3]

### 3.1 这不是简单“把 671B 压成 32B”

R1-Distill-Qwen-32B 等模型不是通过逐层压缩 R1 权重得到，而是：

1. 选已有 dense 基座；
2. 用 R1 生成 / 整理的高质量训练样本；
3. 对基座进行 fine-tuning；
4. 让 student 学习 teacher 的推理模式和答案分布。

所以它更准确地属于**能力迁移**，而不是传统意义上直接压缩同一网络。

### 3.2 不要把“能力保留率”伪装成一个百分比

旧稿写“32B 模型保留 671B 主模型 70% 以上推理能力”，这种说法没有稳定定义。

不同 benchmark 上的相对差距不同，Agent、数学、代码、语言任务也不能被压成一个统一的“能力百分比”。

史料应该记录各评测结果和部署价值，而不是制造一个不存在的总能力刻度。

---

## 四、许可证：蒸馏模型不是自动获得 teacher 的许可证

R1 系列是一个很好的法律/工程案例。

DeepSeek 官方说明：

- DeepSeek-R1 主模型与仓库：MIT；
- R1-Distill-Qwen 系列：上游基座来自 Qwen2.5，原始基座使用 Apache 2.0；
- R1-Distill-Llama-8B：上游基座仍受 Llama 3.1 License 约束；
- R1-Distill-Llama-70B：上游基座仍受 Llama 3.3 License 约束。[^3]

这说明一个很重要的原则：

> **蒸馏不会神奇地洗掉 student 基座原有的许可义务。**

一个模型即使使用 MIT teacher 的输出训练，只要 student 的基础权重来自有额外限制的模型，就仍需要考虑上游许可证。

因此“R1 六个蒸馏模型全部 MIT、随便商用”这种简化写法并不准确。

## 五、自有蒸馏与跨公司蒸馏不是同一个问题

技术上，它们可能都只是：

**调用 teacher → 收集输出 → 训练 student。**

但制度上至少要区分：

### 5.1 自有模型蒸馏

公司用自己的大模型训练自己的小模型。

这是最典型、争议最少的场景，也是大模型厂商降低 serving cost 的常规方法。

### 5.2 合法取得的开放模型输出

如果 teacher 权重开放、许可证允许衍生训练，开发者可以自行生成数据，再训练其他模型。

此时主要问题是许可证和数据来源，而不是 API 服务条款。

### 5.3 第三方 API 输出蒸馏

如果通过另一家公司 API 大规模生成训练样本，问题会转成：

- 服务条款是否禁止训练竞争模型；
- 是否规避 rate limits、地域限制或身份验证；
- 是否使用欺诈账号；
- 数据获取过程是否违反合同或其他法律。

这里的争议已经不只是“蒸馏技术能不能用”，而是**数据是怎样取得的**。

## 六、2026 Anthropic 指控：必须区分指控与已证事实

**2026-02-23**，Anthropic 发布《Detecting and preventing distillation attacks》，称其识别到 DeepSeek、Moonshot、MiniMax 使用约 24,000 个欺诈账号，与 Claude 产生超过 16 million exchanges，以提升自有模型能力。[^4]

Anthropic 将这些行为称为 industrial-scale distillation campaigns / attacks，并表示其违反 Anthropic 服务条款和地区访问限制。

史书这里必须保持证据层级：

- **可以确认**：Anthropic 公开提出了这一指控，并公布上述规模数字；
- **可以确认**：模型输出蒸馏本身是广泛使用的合法训练方法，Anthropic 在同一文章中也明确承认这一点；
- **不能自动确认**：Anthropic 对三家公司的归因、具体操作过程和主观目的已经经过独立司法或第三方全面验证。

因此本书不把“Anthropic 指控”直接改写成“三家公司已被证明实施攻击”。

这也是 2026 年写企业冲突时必须坚持的史料纪律。

## 七、为什么 API 模式天然害怕蒸馏

API 商业模式出售的是**访问能力**，而不是权重所有权。

用户每次需要能力，就再次调用 API。

蒸馏打破这一循环：

1. 先购买大量 teacher 输出；
2. 把输出转成训练数据；
3. student 获得部分能力；
4. 后续任务可以不再调用原 teacher。

于是 API 供应商面对一种特殊风险：

> **今天的收入，可能被客户转化为明天的替代品。**

这也是为什么许多模型 API 条款限制用输出训练竞争模型。

这种限制不等于“蒸馏技术非法”，而是商业合同试图阻止能力被一次性抽取后永久复制。

---

## 八、蒸馏与开放生态：能力传播速度被彻底改变

R1 最重要的生态影响之一，就是证明推理能力可以迅速进入不同尺寸。

以前前沿能力传播大致依赖：

**论文公开 → 社区复现 → 从头训练 → 等几个月。**

蒸馏把路径缩短成：

**强 teacher 出现 → 生成训练样本 → 微调已有基座 → 数天/数周出现 student。**

能力传播速度因此显著提高。

这也解释了为什么开放模型与闭源模型都会重视蒸馏：

- 开放生态把它视为能力民主化；
- 商业 API 把未经许可的大规模跨公司蒸馏视为护城河泄漏。

同一个数学方法，在不同产权结构下获得完全不同的政治意义。

---

## 九、2026 以后：蒸馏的对象开始从答案变成轨迹

Agent 时代让蒸馏继续变化。

一个高级 Agent 的价值不只在最终答案，还在整个 trajectory：

- 选择哪个工具；
- 查询什么信息；
- 何时运行代码；
- 出错后怎样恢复；
- 怎样分配 subagents；
- 什么时候停止继续搜索。

因此未来的 student 可能学习的不只是 teacher 的“推理文本”，而是**完成任务的策略**。

这使蒸馏更接近 imitation learning / behavior cloning，也进一步模糊“模型能力究竟是什么”。

模型公司真正想保护的，可能不是某个答案，而是一整套隐含的工作策略。

## 评曰

知识蒸馏最值得记住的，不是它忽然从“好技术”变成了“坏攻击”。这种说法本身就是误解。

蒸馏一直只是训练方法。

改变的是它所在的制度环境。

2015 年，teacher 和 student 都在研究者自己手里，问题是如何压缩神经网络。

2025 年，R1 用蒸馏把推理能力快速传播到多个尺寸，问题变成能力怎样扩散。

2026 年，商业 API 被用作潜在 teacher，问题又变成：

> **模型输出是一种普通服务结果，还是一种可以被抽取的资产？**

这个问题目前没有统一答案。

真正能够写清楚的只有边界：

**技术方法、权重许可证、student 上游许可、API 服务条款、数据取得方式、竞争法和证据归属，是六个不同问题。**

把它们全部压成“蒸馏是否合法”一句话，就会丢掉大模型时代最重要的产权结构。
