# 推理经济学：从“一个 Token 多贵”到“智能工作负载怎样调度”

> 训练决定模型能达到什么能力上限，推理决定这份能力能否被大规模使用。到 2026 年，推理经济学已经不再只是“GPU 每秒能吐多少 token”。长上下文把 prefill 变重，reasoning 把 decode 拉长，Agent 又把一次请求扩展成几十轮工具调用；cache、batch、并行 Agent、峰谷定价和本地推理同时出现。真正的经济问题变成：**怎样把有限算力分配到最值得的 token、最值得的模型和最值得的任务上。**

---

## 一、训练是生产模型，推理是在经营模型

训练支出通常集中在一个阶段；推理支出则伴随每一次真实使用持续发生。

这两个成本不能简单比较谁“更大”，因为它们性质不同：

- **训练**：决定能力、架构和模型资产；
- **推理**：随请求量、上下文、输出长度、并发和 SLA 持续变化；
- **后训练**：位于两者之间，越来越决定 reasoning / tool use / Agent 行为。

DeepSeek-V3 报告约 2.788M H800 GPU hours、折算约 557.6 万美元的**预训练计算成本**。[^1]

这里必须强调“预训练计算成本”：它不是整个项目全部研发、数据、人员、实验和基础设施的总成本。

这个例子真正说明的是：算法 / 架构效率可以显著改变能力达到同一水平所需要的 compute，而不是“前沿模型只值几百万美元”。

---

## 二、推理不是一个过程，而是至少两个过程：prefill 与 decode

大模型请求可以粗略拆成：

### Prefill

读取输入上下文并建立内部状态 / KV cache。

它受：

- 输入 token 数；
- attention 结构；
- 长上下文；
- cache reuse

影响很大。

### Decode

逐 token 生成输出。

它受：

- 输出长度；
- active parameters；
- memory bandwidth；
- batching；
- reasoning token 数

影响。

这也是为什么 API 定价会把 input 和 output 分开：两个阶段的硬件行为并不一样。

Agent 时代还加入第三类成本——**environment execution**：浏览器、shell、搜索、代码、storage 和其他 Agent。

---

## 三、MLA / MoE：DeepSeek 为什么改变成本讨论

DeepSeek-V2 / V3 的 MLA 与 MoE 路线把两个关键资源同时压缩：

- MLA 降低长上下文 KV cache 压力；
- 稀疏 MoE 让总参数容量远大于每 token 实际激活计算量。[^1][^2]

V3 的 671B 总参数只激活约 37B 参数。

这不是简单“参数更少”，而是把模型容量和每 token FLOPs 解耦。

Kimi K3、Qwen3.8、DeepSeek V4 等后续大型模型继续把“总参数极大、激活参数相对小”作为主流工程方向。[^3][^4]

因此 2026 年讨论模型大小时，**total parameters 已经不足以推断推理成本**；至少还要看 active parameters、attention、context 和 serving 实现。

---

## 四、长上下文的经济学：窗口不是免费的存储空间

1M context 看起来像模型“能读一本仓库 / 一堆文档”。

但长上下文会引入：

- 更重 prefill；
- 更大 KV / latent state；
- 更长首 token 延迟；
- 更多无关 token；
- 更高 cache / storage 压力。

所以“把所有历史都塞进去”并不是免费策略。

这推动了另一整套技术：

- prompt / context caching；
- retrieval；
- compaction；
- memory；
- attention 优化；
- prefix reuse。

Agent 的长记忆因此不是“上下文窗口越大越好”，而是**如何只为真正需要重新计算的信息付费**。

---

## 五、Cached input：上下文开始拥有“折旧价值”

GPT-5.6 的 2026 年价格非常能说明这个变化：

| 模型 | 普通 input | cached input | output |
|---|---:|---:|---:|
| Sol（8/21 promo） | $4.00 | $0.40 | $20.00 |
| Terra | $2.00 | $0.20 | $12.00 |
| Luna | $0.20 | $0.02 | $1.20 |

单位均为 $/1M tokens。[^5][^6]

cached input 只有普通 input 的十分之一。

这相当于模型经济学第一次明确承认：

> **重复读取同一份上下文，不应该每次都按“第一次理解”的价格收费。**

对于代码 Agent、企业知识库、长 system prompt，这会决定整个产品是否经济可行。

Anthropic 也把 prompt caching 作为 Sonnet 5 的重要成本工具。[^7]

---

## 六、Reasoning effort：智能计算预算成为可调资源

2024 的 o1 把 test-time compute 推向前台；2026 的模型进一步把它产品化为 effort。

同一个 Sonnet 5 / GPT-5.6，可以为不同任务投入不同的推理计算。[^5][^7]

这意味着推理不再是固定函数：

> `output = model(prompt)`

更像：

> `output = model(prompt, compute_budget, latency_target, tool_budget)`

简单分类任务没有必要用最高 effort；复杂工程任务可能值得多花几倍 compute，以减少重试和人工接管。

推理经济学因此开始接近资源调度问题。

---

## 七、并行 Agent：Test-Time Compute 从纵向变横向

传统 reasoning scaling 是让一个模型思考更多 token。

Kimi Agent Swarm、GPT-5.6 ultra 等路线让系统可以同时启动多个 Agent。[^8][^5]

这会产生新的成本函数：

- N 个 Agent × 模型 token；
- 多份搜索 / browser / sandbox；
- 重复上下文；
- orchestrator 汇总；
- 冲突和重复工作。

并行能缩短 wall-clock time，却可能显著增加总 compute。

所以 multi-agent 的优化目标不是“Agent 越多越好”，而是：

> **为这个任务，最便宜的并行度是多少？**

这和数据库 query planner、MapReduce worker 数量、云 autoscaling 是同一类问题。

---

## 八、Fast mode：时间本身可以被定价

一个后台研究 Agent 晚五分钟完成影响可能很小；IDE 补全慢一秒就会让人难受。

GPT-5.6 Fast mode 把更低 latency 做成独立服务层。[^6]

DeepSeek V4 的峰谷定价又从另一方向说明：服务商可以按照**什么时候使用算力**调整价格。[^9]

因此推理经济学至少同时有三个资源维度：

- compute 数量；
- compute 时间；
- compute 优先级。

这就是云计算已经走过的路。

---

## 九、Peak / off-peak：Agent 会改变算力需求曲线

传统聊天请求需要用户在线等待，很多流量发生在人类工作时间。

Agent 任务不一定需要实时：

- 夜间跑代码迁移；
- 凌晨生成日报；
- 空闲时重新索引文档；
- 低峰跑大规模测试。

DeepSeek 2026 年 8 月对 V4 系列引入峰谷定价，意味着模型服务开始主动引导需求错峰。[^9]

这可能是 Agent 经济学很重要的一步：

> **智能计算从“即时消费”变成“可调度工作负载”。**

只要任务允许延迟，用户和供应商都可以换取更低成本和更高设备利用率。

---

## 十、Batch：不是所有智能都要实时返回

批处理可以把大量独立请求组织到更高吞吐的执行方式。

文本分类、embedding、离线摘要、数据清洗、评测、合成数据都不需要逐条实时响应。

Anthropic 等厂商公开提供 batch 折扣，说明大模型 API 已经开始像数据仓库一样区分 interactive 和 batch workload。[^7]

未来企业“AI 成本优化”很可能和数据库成本优化类似：

- 哪些必须实时；
- 哪些可以 batch；
- 哪些可以 cache；
- 哪些可以用小模型；
- 哪些才值得上旗舰。

---

## 十一、模型路由：最便宜的 token 是根本不发给旗舰的 token

如果所有请求都发给最强模型，任何价格优化都有限。

GPT-5 的 router、GPT-5.6 Luna / Terra / Sol 分层、Google Flash / Pro、DeepSeek Flash / Pro 都在做一件事：

> **按任务难度选择不同成本的智能。**

这可能比单模型推理提速更重要。

一个系统可以：

- 80% 简单任务用 Luna / Flash；
- 15% 中等任务用 Terra / Sonnet；
- 5% 高风险 / 高价值任务用 Sol / Opus / Fable。

平均成本取决于路由质量，而不只是每个模型的价目表。

推理经济学因此从 model optimization 扩展到 **portfolio optimization**。

---

## 十二、本地推理：把 API 成本变成固定资产 + 电费

开放权重带来另一套经济模型。

云 API：

- 几乎零前期资本；
- 按量付费；
- 易扩缩；
- 供应商负责更新。

本地 / 私有部署：

- 先买 GPU / 服务器；
- 承担电力、运维、折旧；
- 高利用率时边际成本可能更低；
- 数据和运行权更可控。

Muse Glimmer 这种消费级本地 Agent 与 Kimi K3 / Qwen3.8 这种集群级开放旗舰说明，“self-host”内部也不是一个成本类别。[^10][^3][^4]

30B 单卡模型和 2.8T 多机模型的资本结构完全不同。

---

## 十三、推理芯片竞争的真正指标：不是 TOPS，而是工作负载利用率

专用推理硬件、GPU、TPU、NPU 都会宣传峰值算力。

但 LLM serving 更关心：

- HBM / memory bandwidth；
- KV cache capacity；
- interconnect；
- batch efficiency；
- decode latency；
- kernel / compiler；
- quantization support；
- MoE communication；
- utilization。

一张理论 FLOPS 很高的卡，如果模型无法被有效 batch 或 memory-bound，真实 token 成本仍可能很差。

所以硬件竞争最后必须落到：

> **$/token at target latency**

以及 Agent 时代更进一步的：

> **$/successful task at target SLA**

---

## 十四、“模型越来越便宜”与“AI 总支出越来越高”可以同时成立

这是推理经济学最容易反直觉的地方。

单位 token 价格持续下降，并不意味着行业总算力需求下降。

反而可能出现 Jevons paradox：

1. 每 token 更便宜；
2. 更多产品愿意嵌入 AI；
3. 每个 Agent 调用更多工具和模型；
4. 总 token / compute 消耗增长得更快；
5. 总数据中心需求继续上升。

所以“模型价格塌了”和“AI 基础设施继续狂建”完全可以同时为真。

便宜智能会创造新的需求。

---

## 十五、人类时间也是推理成本

企业常漏掉最贵的一项：人类等待和审核。

如果便宜模型：

- 多重试两次；
- 多问三轮澄清；
- 生成更长但更差的输出；
- 需要工程师花 20 分钟审查；

它可能比贵模型更贵。

同样，一个多 Agent 系统如果十分钟完成、但产出让人需要两小时检查，也没有真正提高经济效率。

因此 total cost 应包含：

> 模型 + 工具 + compute + latency + retries + human review + failure risk

这是“推理经济学”从算力经济学走向工作经济学的关键。

---

## 十六、推理成本真正决定的，是哪些智能会成为日常基础设施

GPT-5.6 Luna 进入免费用户；Gemini Flash 继续压价格；Sonnet 5 把更强 Agent 能力压到 $2/$10。[^11][^12][^7]

这些动作的社会意义不只是“消费者省钱”。

它们决定：

- 一个学生能否随时使用 reasoning；
- 一家小公司能否让每个内部流程都有 Agent；
- 一个软件能否在每次点击里调用模型；
- 本地设备能否拥有常驻智能。

前沿能力能否普及，不只取决于训练出它，还取决于**能否承担每一次使用它的边际成本**。

---

## 评曰：推理经济学最终是智能调度学

早期大模型成本讨论喜欢问两个数字：训练花了多少钱？API 一百万 token 多少钱？

到 2026 年，这两个数字都不够了。

同一个模型可以有普通 input、cached input、不同 effort、Fast、batch；同一个任务可以选择 Flash、Pro、local、cloud；还可以并行十个 Agent，或者让一个模型慢慢做。

于是推理经济学真正研究的东西变成：

> **什么时候，用哪个模型，在什么硬件上，以多大计算预算、多少并行度和什么延迟目标，完成这项工作最划算。**

这已经不是单纯“把矩阵乘法做便宜”。

它是一门完整的资源调度学。

模型能力继续提高当然重要；但当智能成为基础设施以后，社会真正消耗的是成百上千亿次小决策、工具调用和长程任务。

谁能把这些计算安排得最合理，谁才拥有 Agent 时代最深的成本优势。

因此推理经济学的终点不是“token 免费”。

它的终点是：**让每一单位算力尽可能多地产生可验证、可交付的工作。**
