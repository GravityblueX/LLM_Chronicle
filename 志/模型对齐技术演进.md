# 《模型对齐技术演进》：从“让模型听话”到运行时行为控制

> 对齐技术最初研究的是一个模型训练问题：怎样把 next-token predictor 变成 helpful / honest / harmless assistant。到 2026 年，这个定义已经太窄。Agent 会调用工具、操作电脑、持续数小时、协调子 Agent，甚至开始连接实验设备。于是“对齐”被拆成多个层：**训练时价值塑形、推理时奖励与预算、系统提示、工具权限、runtime classifier、fallback、trusted access、watermark、checkpoint 和 human approval。** 安全不再只存在于权重里，而是整个执行系统的属性。

---

## 一、RLHF：把“什么是好回答”变成可学习目标

**2022 年**，InstructGPT 把 SFT + preference ranking + reward model + PPO 组合成工业化 RLHF 流程。[^1]

它解决的是预训练模型的核心缺口：

> 预测互联网文本，不等于理解用户希望你怎样回答。

RLHF 让“用户更喜欢哪个输出”成为训练信号。

这一步对 ChatGPT 产品化至关重要：能力足够强但不遵循指令的模型，很难成为大众助手。

但 RLHF 也留下三个问题：

- 人类反馈昂贵；
- 标注标准不一致；
- 奖励模型可能被策略模型利用（reward hacking）。

于是 2023—2025 的对齐方法很大部分都在重新设计**反馈来自哪里、怎样训练得更便宜。**

---

## 二、Constitutional AI / RLAIF：把原则写成可执行训练材料

Anthropic 的 Constitutional AI（CAI）提出：不需要让人逐条标所有有害输出，可以给模型一套 constitution，让模型根据原则批评和修订自身输出，再通过 AI-generated preferences 训练。[^2]

CAI 的历史意义不只是节省标注。

它第一次非常明确地把“行为规范”从标注员脑中移到**可写、可审计、可修改的文本原则**中。

这使对齐获得治理属性：

> 谁写 Constitution？哪些原则优先？发生冲突时怎样权衡？

模型训练从此不只是数据与 loss，也包括制度文本。

---

## 三、DPO / KTO / SimPO：偏好优化从 RL 系统变成更轻的训练目标

**DPO** 证明偏好数据可以直接优化语言模型，不必显式训练 reward model 再跑 PPO。[^3]

随后 KTO、SimPO 等方法继续降低数据或 reference model 的工程要求。

这一时期的共同方向是：

> **让“偏好对齐”变得更容易被开放模型和中小团队使用。**

因此 2023—2024 的对齐民主化，很大部分不是新价值理论，而是工程简化。

---

## 四、GRPO / Verifiable Rewards：奖励开始来自环境，而不只是人类偏好

DeepSeek-R1 把 GRPO 和可验证任务奖励推到前沿模型训练中心。[^4]

数学、代码等任务可以直接判断：

- 答案对不对；
- 测试过不过；
- 格式是否满足约束。

这意味着“什么是好输出”不一定由人类偏好模型给出。

环境本身可以成为 reward source。

这条路线对 Agent 特别重要，因为 Agent 很多工作有可观察后果：

- 文件是否创建；
- 页面是否提交；
- 测试是否通过；
- shell command 是否成功。

对齐开始从“学会说正确的话”进入“学会产生正确结果”。

---

## 五、过程监督并没有消失，只是与结果监督重新分工

Outcome reward 很适合最终结果可验证的任务。

但复杂任务存在 credit assignment 问题：最终失败，究竟哪一步错？

Process Reward Model（PRM）、step-level verifier 等方法仍然重要，因为它们可以在推理中更早发现错误。

因此 2026 年更合理的理解不是：

**PRM vs ORM 谁赢。**

而是：

- 能自动验证最终结果时，用 outcome signal；
- 中间步骤很长且错误代价高时，引入 process feedback；
- 开放任务无法客观判定时，仍需要 preference / judge / human review。

奖励信号正在按任务分层。

---

## 六、Model Spec / Constitution 开始进入更早训练阶段

到 2026 年，对齐原则不再只在最后的 RLHF 阶段出现。

Anthropic Fellows / Anthropic 研究者提出 **Model Spec Midtraining（MSM）**：在 pretraining 之后、传统 alignment fine-tuning 之前，让模型学习描述 Model Spec / 行为原则的 synthetic documents，从而影响后续对齐如何泛化。[^5]

研究显示，即使后续 alignment fine-tuning 相同，midtraining 中不同 Model Spec 也会改变模型最终价值泛化，并可以降低部分 agentic misalignment 行为。

这件事很值得记：

> **对齐从“训练完再修行为”开始进入模型表征形成过程。**

Pretraining / midtraining / post-training 之间的界线因此越来越模糊。

---

## 七、System Prompt：最便宜也最脆弱的运行时对齐层

现代模型都有 system / developer instruction 层。

它的优势是：

- 不重新训练即可改变行为；
- 可以按产品、企业和用户场景定制；
- 更新速度快。

缺点也非常明显：

- prompt injection；
- instruction conflict；
- 长 context 中层级混淆；
- 用户输入可能诱导模型越权。

因此 system prompt 是**policy interface**，不是可靠的安全边界。

真正高风险工具需要更低层的权限控制。

---

## 八、Tool Permission：Agent 时代的对齐对象从“输出”变成“动作”

聊天模型错误回答通常只是文本风险。

Agent 错误动作可能：

- 删文件；
- 发邮件；
- 提交代码；
- 转账；
- 改生产配置；
- 操作实验设备。

因此 Agent 对齐必须回答：

> **它不仅应该想什么、说什么，还应该被允许做什么。**

这催生了权限分层：

- read-only；
- write；
- shell；
- network；
- external communication；
- financial / destructive action。

以及确认机制：

- always allow；
- ask once；
- ask every time；
- deny。

对齐因此变成 capability-based security 的一部分。

---

## 九、Checkpoint / Rollback：安全不一定阻止错误，也可以让错误可恢复

传统 safety 目标喜欢描述“模型不能犯这个错”。

实际工程更现实：模型一定会犯错。

所以 coding agents、computer-use agents 开始采用：

- git diff；
- filesystem checkpoint；
- sandbox；
- transaction boundary；
- rollback。

这是一种不同的安全哲学：

> **不要只降低错误概率，也降低错误造成的不可逆损失。**

Recoverability 正成为 Agent alignment 的核心指标。

---

## 十、Runtime Classifier：Fable 5 把安全层从权重中拆出来

2026 年 Claude Fable 5 / Mythos 5 提供了非常清楚的实例。[^6]

两款产品基于同一底层前沿模型，却通过不同 safeguards 和 access policy 形成不同能力边界。

Fable 5 对 cyber / bio 等高风险领域使用 runtime classifiers；触发时可能阻止请求或 fallback 到能力较低模型。

**2026-08-07**，Anthropic 更新 biology safeguards，并称内部测试中正常 biology 请求的 fallback 下降约 85%。[^7]

这个事件的意义在于：

- 底层模型没重新训练；
- 安全政策可以快速独立升级；
- false positive / false negative 变成单独可测系统指标。

对齐第一次明显变成**可热更新的 runtime service**。

---

## 十一、Trusted Access：对齐开始控制“谁能拿到什么能力”

Mythos 5 更进一步。

某些高风险能力不是简单从模型里删除，而只向经过验证的组织 / 用途开放。

这创造新的对齐层：

> **identity + organization + use case → capability access。**

模型风险控制由“所有用户同一拒答边界”变成分级权限。

这与云 IAM、零信任安全非常相似。

到高能力 Agent 时代，access control 很可能比单纯 refusal tuning 更重要。

---

## 十二、Watermark / Provenance：对齐开始覆盖模型输出离开系统之后

**2026-08-14**，Anthropic 宣布未来 Claude 文本使用统计式 watermark，以满足包括 EU AI Act 在内的透明度需求。[^8]

这类 provenance 机制不直接改变模型“愿不愿意回答”，却影响生成内容进入社会后能否被识别和治理。

因此 AI safety 的边界继续向外扩张：

**training behavior → runtime action → downstream provenance。**

---

## 十三、Hardware Action：物理 Agent 让对齐从数字权限进入物理权限

**2026-08-27**，Reuters 报道 Anthropic 发布 Model Hardware Standard（MHS）research preview，让 Agent 能通过标准接口连接机械臂、显微镜等可编程设备；该框架先由部分伙伴进行安全测试，并计划后续开放。[^9]

此条截至补订时官方页面尚待归档，因此按单一权威媒体来源记录。

MHS 之前，Anthropic 已通过 UST physical AI 和 Project Pilot 等工作探索 Claude 操作工程设备与无人机。[^10][^11]

一旦 Agent 进入物理世界，alignment 的损失函数发生质变：

- 误点网页可能重试；
- 误改代码可以 rollback；
- 机械臂撞坏设备可能不可逆。

所以未来对齐必须更加依赖：

- simulator；
- physical interlock；
- emergency stop；
- bounded workspace；
- human authorization；
- hardware-level safety constraints。

语言模型拒答只是最外层。

---

## 十四、对齐已经变成分层系统

到 2026 年，可以把对齐拆成至少七层：

| 层 | 主要技术 | 控制什么 |
|----|----------|----------|
| Pre / midtraining | data / Model Spec Midtraining | 基础表征和价值泛化 |
| Post-training | SFT / RLHF / DPO / GRPO | 默认行为偏好 |
| Inference policy | system prompt / reasoning policy | 当前会话规则 |
| Runtime classifier | safety model / fallback | 动态风险检测 |
| Capability access | IAM / trusted access | 谁能用什么 |
| Action sandbox | permission / checkpoint / rollback | 能做什么、失败后怎么办 |
| Provenance | watermark / audit logs | 输出离开系统后怎样追踪治理 |

“模型有没有对齐”因此已经不是 yes / no 问题。

需要问：**哪一层、对什么风险、在什么环境下。**

---

## 十五、为什么对齐不会有一个终极算法

不同任务的风险结构完全不同。

写诗的对齐、写代码的对齐、控制浏览器的对齐、操作实验室机器人的对齐，不可能只靠一套 RLHF data 解决。

随着 Agent 的行动空间扩大，系统越来越需要借用传统安全工程：

- least privilege；
- defense in depth；
- isolation；
- auditability；
- fail-safe defaults；
- reversible operations。

AI alignment 正从机器学习子领域变成**ML + security + systems + governance** 的交叉工程。

---

## 评曰

对齐技术史最初像是在训练一个“更懂事的模型”。

InstructGPT 教模型听人类偏好；Constitutional AI 把偏好写成原则；DPO 让偏好优化更简单；R1 又让任务结果本身成为老师。

但 Agent 时代迫使这条历史走出模型权重。

如果一个模型会操作电脑，真正的安全问题不是它是否在文本里说“我会谨慎”，而是：

- 它有没有写权限；
- 删除前会不会确认；
- 有没有 checkpoint；
- 网络访问范围多大；
- 高风险能力只给谁；
- classifier 误杀时能否单独更新；
- 物理设备有没有硬件 interlock。

所以 2026 年之后，对齐最成熟的形态可能不是“一个完美对齐的模型”。

而是一套承认模型会犯错、因此用多层制度包围它的系统：

> **训练塑造倾向，权限限制行动，环境验证结果，日志留下责任，rollback 降低损失。**

这比“让 AI 学会人类价值观”听起来不浪漫。

但它更像真实世界里安全系统一直工作的方式。
