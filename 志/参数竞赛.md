# 《参数竞赛》：从“多少 B”到“每个 token 激活多少”

> 参数竞赛并没有在 GPT-4 不公开参数以后结束。它只是换了计量单位。2020 年大家比较 dense model 的总参数；2024 年 MoE 迫使行业同时看 total parameters 与 active parameters；2026 年 Kimi K3 和 Qwen3.8 又把开放权重旗舰推到 2.8T / 2.4T，却分别只激活约 104B / 95B。于是“模型有多大”第一次明确分裂成两个问题：**它能存多少知识容量，以及每生成一个 token 实际调用多少计算。**

---

## 一、参数为什么曾经是最好的规模指标

在 dense Transformer 时代，参数量有一个非常方便的性质：

> **总参数 ≈ 每个 token 都要参与计算的参数。**

所以 GPT-2 1.5B、GPT-3 175B、PaLM 540B 的参数数字同时近似代表：

- 模型容量；
- 显存占用；
- 单 token 计算量；
- 训练与推理门槛。

这就是为什么 2020—2022 年“多少 B”几乎可以直接充当模型地位。

### 关键里程碑

| 时间 | 模型 | 公开参数 | 历史意义 |
|------|------|----------|----------|
| 2018 | GPT-1 | 117M | 生成式预训练起点 |
| 2019 | GPT-2 | 1.5B | 十亿参数进入公众视野 |
| 2020 | GPT-3 | 175B | 参数 scaling 成为产业战略 |
| 2021 | Switch Transformer | 1.6T MoE | “万亿参数”首次出现，但已经不是 dense |
| 2022 | PaLM | 540B dense | dense 参数扩张的代表性高点 |

GPT-3 尤其重要：175B 比 GPT-2 大两个数量级，few-shot / in-context learning 又明显增强，使行业很容易得出“继续变大就是路线图”的结论。[^1]

---

## 二、Chinchilla：参数不是越多越好，关键是训练预算怎样分配

**2022 年**，DeepMind Chinchilla 研究证明，在固定 compute budget 下，许多当时的大模型相对于参数量训练 token 太少。70B Chinchilla 用更多数据训练，可以超过 280B Gopher。[^2]

Chinchilla 并没有说“小模型永远更强”。

它修正的是：

> **如果训练计算总量固定，把太多预算花在增加参数、却不给模型足够数据，是浪费。**

因此参数数量从“越多越好”变成一个**需要与数据和训练计算共同优化的变量**。

LLaMA 后来进一步把这种思想产品化：13B 级模型通过更充分训练可以在许多任务上超过更早的 175B GPT-3。[^3]

从这一刻起，“多少 B”不再等于“有多聪明”。

---

## 三、GPT-4：参数从公开竞赛变成商业秘密

**2023-03**，OpenAI 发布 GPT-4，但技术报告不披露参数规模、训练数据量、详细架构和训练 compute。[^4]

后来关于 GPT-4 “1.7T / 1.8T MoE”等大量产业传闻从未得到 OpenAI 官方确认，本书不将其作为参数史事实。

这一步使闭源前沿模型进入“参数不可知”阶段。

Claude、Gemini、GPT-5.x 等后来也普遍不公开完整参数规模。

但这并不代表参数不重要，而是：

> **参数从营销数字变成了内部工程信息。**

此后公开世界的参数史主要由开放权重模型继续书写。

---

## 四、MoE：一个参数数字正式裂成两个数字

Mixture-of-Experts（MoE）让参数竞赛发生了概念断裂。

MoE 模型拥有很多专家，但每个 token 只路由到其中少数专家。

因此至少要同时记录：

- **Total parameters**：整个模型存储多少参数；
- **Active parameters**：一个 token 实际经过多少参数。

### Mixtral：第一次让大众熟悉“总参数 ≠ 推理参数”

**2023-12**，Mixtral 8x7B 总参数约 46.7B，但每 token 激活约 12.9B。[^5]

### DeepSeek-V2 / V3：稀疏前沿成为主线

**2024-05**，DeepSeek-V2：236B total / 21B active。[^6]

**2024-12**，DeepSeek-V3：671B total / 37B active。[^7]

V3 的比例尤其说明问题：模型可以拥有数千亿参数容量，但一个 token 并不需要支付 671B dense model 的全部计算费用。

从此“参数效率”开始比“总参数”更重要。

---

## 五、2025：Thinking 与 Agent 又让“模型大小”少了一个解释维度

即使知道 total / active parameters，也无法完整解释 2025 年后的模型能力。

原因是模型还可以在推理时花不同 compute。

同一个 checkpoint：

- 简单问题快速回答；
- 困难问题使用 extended thinking；
- Pro 设置并行探索；
- Agent 任务反复调用工具几十轮。

因此有效能力越来越接近：

**pretraining capacity × active compute × test-time compute × tool/environment feedback。**

这让“一个模型有多少参数”进一步退化为基础信息，而不是完整能力指标。

---

## 六、2026：参数竞赛重新回来，而且直接跨过 2T

参数数字在开放权重前沿重新变得醒目。

### 6.1 DeepSeek V4：1.6T / 49B

**2026-04**，DeepSeek V4-Pro 官方披露：

- **1.6T total**；
- **49B active**；
- 1M context。[^8]

V4-Flash 则为 284B / 13B active。

同一模型家族用总参数和激活参数共同定义 Pro / Flash 经济档位。

### 6.2 Kimi K3：2.8T / 104B

**2026-07**，Moonshot Kimi K3 达到：

- **2.8T total**；
- **104B active**；
- 1M context；
- 原生视觉。[^9]

Reuters 在发布时将其称为当时全球最大开放 AI 模型之一。

### 6.3 Qwen3.8：2.4T / 95B

**2026-08**，Qwen3.8 开放权重旗舰为：

- **2.4T total**；
- **95B active**；
- 1M context；
- 原生多模态。[^10]

### 6.4 为什么 2T / 3T 并不意味着“参数狂热回归 2021”

表面看，参数竞赛比 PaLM 时代更疯狂。

但其经济逻辑完全不同。

PaLM 540B 是 dense：参数容量和每 token 计算大体绑定。

K3 / Qwen3.8 是高度稀疏：总容量进入 2T 以上，而 active parameters 仍在百亿级。

这是一种新的 scaling：

> **扩大知识容量，但尽量不同比例扩大每 token 的计算成本。**

因此 2026 的“更大”是**稀疏地更大**。

---

## 七、active parameters 也不是推理成本的完整答案

看到 104B active 也不能直接说 K3 “等于一个 104B dense 模型的成本”。

真实成本还受：

- attention / KV Cache；
- context length；
- expert routing communication；
- quantization precision；
- batch size；
- prefill / decode 分离；
- speculative decoding；
- memory bandwidth；
- 芯片互联；
- runtime implementation

共同决定。

一个稀疏模型可能 FLOPs 低，却因跨设备 expert communication 很昂贵。

所以 active parameters 只是比 total parameters 更接近成本，但仍不是成本本身。

---

## 八、2026 的另一极：30B、本地模型和“参数密度”

同月 Meta 发布 **Muse Glimmer 30B**，目标是在个人电脑或单张消费级 GPU 上运行 always-on local agent。[^11]

这形成一个看似矛盾的市场：

- 一边：2.4T / 2.8T 开放旗舰；
- 一边：30B 本地 Agent；
- 中间：各种 Flash / 13B active / 18B active 稀疏工作马。

参数竞赛因此不是一条单向巨型化曲线，而是**模型生态位分化**。

最大的模型承担最难任务和蒸馏教师；中型稀疏模型承担生产 token；小型模型获得本地控制权。

---

## 九、GLM-5.3-Flash：总参数下降，能力反而上升

**2026-08-26**，GLM-5.3-Flash 为 **320B total / 18B active**。官方强调其能力超过参数更大的 GLM-5.2，同时 active parameters 与层数显著下降，并采用 sparse + linear attention hybrid。[^12]

这提供了参数史里另一个重要方向：

> **下一代模型并不一定总参数更大；架构、数据、后训练和激活效率可以让更小的总模型承担更强工作。**

所以 2026 参数史同时存在两种运动：

1. 旗舰容量继续向 T 级扩大；
2. 工作马不断降低 active compute。

这不是矛盾，而是分层供给。

---

## 十、参数的真正角色：容量、计算与部署必须拆开

到 2026 年，至少需要四个维度才能谈“模型大小”：

| 维度 | 回答什么问题 |
|------|--------------|
| Total parameters | 模型总容量多大 |
| Active parameters | 每 token 进入多少主要参数计算 |
| Context / KV state | 当前任务需要保存多少运行时状态 |
| Test-time / agent compute | 为完成一项任务还要追加多少推理与工具调用 |

因此“70B vs 405B vs 2.8T”这种单列参数比较已经不足以指导部署。

一个 2.8T 模型可以只有 104B active，却需要巨型多节点集群存放全部专家；一个 30B 模型可能能力弱一些，却能完全在本地运行。

**可部署性和参数容量已经不是同一个轴。**

---

## 评曰

参数竞赛没有结束。

结束的是**一个数字解释一切**的时代。

GPT-3 时代，175B 几乎同时意味着“更聪明、更贵、更难部署、更大的模型”。

MoE 之后，这些含义逐个拆开。

总参数代表容量，active parameters 更接近计算，context 决定状态成本，test-time compute 决定一次任务实际愿意烧多少资源，runtime 和硬件又决定这些理论计算能否高效实现。

所以 Kimi K3 的 2.8T 和 Qwen3.8 的 2.4T 并不是 2021 年参数军备竞赛的简单复活。

它们代表一种更成熟的野心：

> **把容量做得越来越大，同时让实际调用越来越稀疏。**

与此同时，Muse Glimmer 和 GLM-5.3-Flash 又提醒行业：最有影响力的模型未必是最大模型，而可能是**单位激活计算完成最多工作的模型**。

参数从“冠军奖杯”变成了资源配置表。

这可能才是参数竞赛真正成熟的标志。
